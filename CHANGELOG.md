## [1.9.0] — 2026-09-29

### Пункт 17 GAP v2: Пространственные системы (наклон/децентрировка поверхностей)
- **Единственный источник преобразований** — новый **`domain/spatial.py`**
  (OPAL-PC SPACE.DOC «SRT»: произвольно расположенные в пространстве
  поверхности; SBL — смещение базиса, SRS/SBO — последовательность и
  углы поворотов):
  - **`rotation_matrix(tilt_x, tilt_y, tilt_z)`** — правая матрица
    R = Rz·Ry·Rx (градусы, порядок X → Y → Z); тождественные углы
    (≤ COORD_BREAK_EPS) → `None` — быстрый путь без математики;
  - **`CoordBreak`** — координатный излом поверхности: вершина в
    локальном начале (пивот поворота), ось поверхности +Z;
    `point_to_local/point_to_global` (сдвиг вершины + поворот),
    `dir_to_local/dir_to_global` (только поворот), `from_surface()`,
    точные инверсии; `surface_has_coord_break()` — детектор полей.
- **Модель** (`domain/models.py`): у `Surface` добавлен `tilt_z`
  (ранее только tilt_x/tilt_y + decenter_x/decenter_y); все поля —
  нули по умолчанию (обратная совместимость: центрированные системы
  идут прежним путём бит-в-бит).
- **Точная трассировка** (`analysis/ray_tracing.py`): каждая
  поверхность с изломом встречает луч переходом в локальную СК,
  пересечением (аналитически сфера / Ньютон асферика) и возвратом в
  глобальную. Между поверхностями луч всегда в глобальной СК
  (decentered-конвенция, без накопления наклонов). Точки пути луча —
  теперь в глобальной СК (ранее приближение первого порядка).
  NaN-безопасность: луч мимо поверхности / расходящаяся итерация →
  маркер `MISS` с конечными координатами, без крэша и NaN.
- **UI** (main.py): колонки «Наклон X,Y,Z (°)» и «Децентр X,Y (мм)»
  таблицы конструктивных параметров (стоп остался последней).
  Формат ячеек — `format_coord_cell()/parse_coord_cell()`
  (utils/optics_utils.py: «5,-2.5,1»; мусор в ячейке не меняет
  значение). Чтение таблицы выведено в единственный парсер
  `read_surface_table()` (gui/controllers/system_controller.py) —
  им пользуются и «Собрать систему», и «Рассчитать» (прежде
  дублировалось — наклоны, введённые перед «Рассчитать», могли
  теряться).
- **JSON round-trip** (fileio/json_io.py): tilt_x/y/z,
  decenter_x/y пишутся и читаются; старые файлы без полей → нули.
  Форматы OPJ/LBO полей наклона/децентра не содержат — подключать
  нечего (проверено по парсерам).
- **Параксиальный расчёт**: поверхности с изломом считаются как
  обычные (первый порядок; ABCD-повороты не реализованы) — отмечено
  в docstring `paraxial_trace` со ссылкой на точную трассировку.
- Тесты (`tests/test_spatial_systems.py`, 66): матрицы поворотов
  (Rx/Ry/Rz, порядок композиции, ортонормальность det = 1), инверсии
  CoordBreak; **золотые тесты** — наклонённая параллельная пластина =
  призма: точка выхода совпадает с ручным Снеллиусом (1e-9, 15
  комбинаций θ/n/t), направление в стекле = R_x(θ)·(0, a, b),
  выходящий луч параллелен падающему, смещение — классика Слюсарева
  s = t·cosθ·sinθ·(1 − cosθ/√(n²−sin²θ)); наклонное зеркало —
  отклонение ровно 2θ, tilt_z поворачивает азимут (Rz(φ)·отражённое);
  децентрированная линза — трансляционная инвариантность (точная) и
  сдвиг изображения на dy; векторный Снеллиус n₁·d_t = n₂·d′_t на
  наклонённой/смещённой сфере с нормалью из глобального центра;
  NaN-безопасность (MISS/EDGE/TIR маркеры, конечные координаты,
  trace_fan не падает); обратная совместимость (нули = отсутствие
  полей, демо-системы); ячейки таблицы; JSON round-trip; колонки UI
  (offscreen): заголовки, загрузка/чтение, мусор не рушит значения.
- Прогон: 727 passed, 6 skipped.

## [1.8.0] — 2026-09-28

### Пункт 16 GAP v2: Единицы зрачка (дптр/мм)
- **Конверсия в одном месте** (`utils/optics_utils.py`, OPAL-PC Л1.4.4
  «единицы измерения положения зрачков … (дптр/мм)»; 1 дптр = 1/м):
  - **`mm_to_dioptre()` / `dioptre_to_mm()`** — D = 1000/мм для обратных
    длин (положения зрачков sP/sP′); 0 → ±∞ с сохранением знака
    (зрачок «на бесконечности»), NaN/±∞ на входе → ValueError;
  - **`field_deg_to_dioptre()` / `field_dioptre_to_deg()`** — поле
    дальнего типа tan-конверсией через ф′: D = 1000·tg ω / f′
    (f′ = 0 → ValueError);
  - **`field_native_unit()`** — родная единица поля системы («°» для
    INFINITE, «мм» предмета для FINITE); **`field_unit_display()`** —
    единица отображения (дптр только при переключателе = дптр, поле в
    градусах и f′ ≠ 0); **`format_pupil_position()`** (∞-значения —
    «∞»), **`format_field()`**, **`field_values_display()`**.
- **Состояние — единственное** (single source of truth):
  `get_pupil_unit()/set_pupil_unit()` + наблюдатели
  (`add/remove_pupil_unit_observer`) в utils; подписка слабая
  (WeakMethod): собранный GC виджет исчезает из реестра сам, реестр
  не удерживает панели и не падает на удалённых C++-объектах Qt.
  Комбобоксы панели анализа и панели результатов — только
  представления, синхронизируются наблюдателем (без циклов сигналов).
- **Область действия**: положения зрачков sP/sP′ (таблица «Параксиалы»
  на каждую λ — `PUPIL_POSITION_KEYS` в domain/calculations.py, панель
  результатов main.py) и оси поля — графики дисторсии/астигматизма/
  комы/габаритов пучков (`FieldDisplayMixin`: f′ + родная единица,
  `set_field_context`/`field_axis`/`field_scale_label`), СКВ по полю
  (вкладка «Цернике»), заголовки и ячейки таблиц поля
  (дисторсия/астигматизм/кома/габариты/гл. лучи/СКВ). Высоты лучей в
  веерах и зрачковые координаты волнового фронта — нормированные
  (как в OPAL-PC Л1.4.6), переключателем не трогаются.
- **Перестройка без повторного расчёта**: смена единиц обновляет
  таблицы из данных виджетов (`_refresh_field_tables`) и перерисовывает
  графики; f′ кэшируется по системе (`_efl_cache`), контекст поля
  раздаётся панелью (`_push_field_context`) в precomputed/phase2.
- Тесты (`tests/test_pupil_units.py`, 63): конверсия туда-обратно и
  табличные значения (500 мм → 2 дптр), граничные случаи (0 → ∞,
  отрицательные — знак, малые — линейность, NaN/∞ → ValueError,
  f′ = 0), подписи осей («±5.0°» / «±0.9 дптр»), заголовки и ячейки
  таблиц в обеих единицах, единое состояние двух комбобоксов,
  неизменность нормированных высот лучей, слабые подписки (панель
  после GC не оповещается; удалённый C++-объект не роняет смену).

### Пункт 12 GAP v2: Три способа задания апертуры
- **`domain/aperture.py`** — пересчёты способов задания апертуры
  осевого пучка. Каноническая величина — диаметр входного зрачка;
  `aperture_to_epd()` приводит любой способ к нему, `epd_to_apertures()`
  даёт все представления одного пучка, `convert_aperture()` — полный
  пересчёт. Способы:
  - **передняя апертура** — полуугол предметного луча (°): h =
    tan(u)·(путь предмет→входной зрачок); только для предмета на
    конечном расстоянии (в ∞ пучок параллелен);
  - **задняя апертура** — полуугол в пространстве изображений (°) или
    NA' = n'·sin u': h' = tan(u')·|sF' − sP'| у выходного зрачка;
  - **высота луча на апертурной диафрагме** (полувысота, мм) — через
    увеличение изображения диафрагмы;
  - прежние: D входного зрачка, F/#, NA (D = 2·f'·NA).
- **`ApertureType`** (domain/models.py): + FRONT_ANGLE, REAR_ANGLE,
  REAR_NA, STOP_HEIGHT (сериализация JSON по имени — совместимо).
- **`paraxial_trace`**: увеличения изображения диафрагмы —
  `entrance_pupil_magnification`, `exit_pupil_magnification`,
  `pupil_magnification` (луч через центр диафрагмы + инвариант
  Лагранжа). Пересчёт D зрачка/f# вынесен в `aperture_to_epd` (был
  inline в paraxial_trace и дублировался фолбэками в контроллере) и
  работает для всех способов; вычисляется после зрачков, на которые
  опирается.
- **`get_effective_aperture`** (utils/optics_utils.py): любой способ
  приводится к диаметру — F/# или угол больше не попадают в
  трассировку лучей как «мм».
- **UI**: вместо мёртвой пары «Передняя/Задняя апертура» — один
  переключатель способа + поле значения (`APERTURE_METHODS`,
  `SystemParamsWidget.aperture_from_ui/set_aperture`); оба контроллера
  собирают апертуру одним вызовом (было две одинаковые копии);
  легаси-виджеты aperture_type_combo/aperture_spin и _sync_aperture
  удалены.
- Тесты (`tests/test_aperture.py`, 23): увеличения зрачков
  (диафрагма на 1-й поверхности → m=1), высота на диафрагме ↔ D,
  задний угол (независимая проверка геометрией зрачок→фокус),
  NA' = sin(u'), передний угол на конечном предмете (atan(h/200)) и
  его неопределённость в ∞, прежние способы, замыкание пересчётов,
  get_effective_aperture, UI (переключатель, единая точка чтения,
  контроллеры без дублирования), круг JSON.
