# §17. FUN_1000_0746 — полная карта главного вычислителя (TASK_REV0746)

*Нумерация: в ТЗ этой теме отведён §17; в текущем REVERSE_TRACE.md §17 уже занят
«Инструментами волны 5» — при мердже настоящий раздел станет §18 (сдвиг +1, как у §14
относительно ТЗ волны 5). Ссылки вида «§7», «§9.2», «§11.2» — на разделы REVERSE_TRACE.md.*

Диапазон функции: **линейный 0x10746–0x1132A** (`retf 0x70` на 0x1132A — 0x70 байтов
стека-аргументов = ровно 28 far-указателей). «Общий хвост» 0x10C72–0x112D0 (§3, Ф1–Ф6)
целиком лежит внутри тела 0746 — Ghidra склеил собственную оркестрацию 0746 и
разделяемую математику трассировки, отсюда 34 KB декомпила. Дерево вызовов из §5/§11.2
(контур `4dfc → 0746 → REAL*4-таблицы`) подтверждено и детализировано до адресов.

## 17.0. Сигнатура и скелет (адресная карта вызовов)

```
FUN_1000_0746(a1..a28)                              # 0x10746; retf 0x70 @0x1132A
```

## 17.1. Каркас запроса: 28 far-аргументов (= «rec» из §7.0)

образе их содержимое — ASCII-мусор.

```python
        if *M32[a20] >= 2: R4[a4] = x87_top()        # 0x112FB+
    ВЫХОД: pop; retf 0x70                             # 0x11325-0x1132A
```

Досрочные выходы на 0x11325: ошибка пучка (0x10ADB, байт [0x39B1]→a1), сработавший

**Поправка к §7.0/§7.2 (фар-аргументы вычислителей):** в §7 аргументы 93f3 значились
как «rec+0x70, rec+0x68, rec+0x80, rec+0x78, rec+0x92» — байты call-site показывают,

печатальщики 8fa3-группы (§11.2) [НЕИЗВЕСТНО: потребители 0x3A68-0x3A80 вне 0746].

**Запись системы (overlay-сегменты):** поверхности — 0x45B7:0x5A8 (REAL*8 параметры,
шаг 8), 0x45B7:0xA8 (REAL*8 записи, шаг 8 — трейсерам), 0x45B7:0xAA8 (16-бит коды,
шаг 2 — селектор тела A/B), 0x45B7:0xBE8 (REAL*8-таблица, индекс |код|·40+8·[0x4506]);
wl_flags — 0x4E10:0x4 (шаг 2, чтение [surf*2−2]); λ-данные — 0x4EBB:0x88+8·i (e7db);
счётчики — 0x4BB3:0x59C/0x614+0x18·i; команда/стоп — 0x4DC0:0; N — 0x45B7:0.
Уточнение к §9.2: wl_flags здесь — самостоятельный массив (шаг 2), а не байт
0x18-шаговой записи поверхности (0x18-шаг — это записи cf98/ф6 §3; в 0746-контуре
организация иная).

**Полярность wl-диспетчера.** В cf98 (§9.2): `wl==0 → f344; wl≠0 → f359+e920`.
В 0746 (контур таблиц 4dfc) байты дают иную полярность:

```python
if код_поверхности[2*i-2] == 0:            # 0x10EB7 — обычная поверхность
    if wl_flags[2*i-2] != 0: FUN_1000_f344(...)   # 0x10C23
    else:                   TSR_0xFF95(...)       # 0x10C50
else:                                      # спец-поверхность (вторая λ)
    if wl_flags[2*i-2] != 0: FUN_1000_f359(...)   # 0x10F05
    else:                   TSR_0xFFA9(...)       # 0x10F32
    FUN_1000_e920(...)                            # 0x10F8E — безусловно (печать строки)
```

Т.е. в контуре таблиц **трейсер вызывается при wl_flags≠0**, а при wl_flags==0 работу
выполняет TSR-сервис 0xFF95/0xFFA9 (тела вне образа). Поскольку f344/f359 — один код
с флагом [0x50c2]=0/1 (§2), согласованное прочтение: wl_flags≠0 = «поверхность считается
на назначенной длине волны» → полный прогон трейсера; wl_flags==0 → облегчённый
TSR-прогон [НЕИЗВЕСТНО: содержимое 0xFF95/0xFFA9]. Выбор «основная/вторая λ» в этом
контуре определяется не wl_flags, а **кодом поверхности** ([BP+0x42], 0x10EB7).
