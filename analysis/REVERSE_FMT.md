# §18-A2. Форматник FORTRAN RTL 0x2E73:0x2042 — реверс и сверка с портом

**Дата:** 2026-10-15 · **Источник:** analysis/reverse_data/OPALA_unp.bin (линейный
адрес = смещение в файле; seg:off → lin = seg·16+off; сегмент RTL 0x2E73 →
база lin 0x2E730) · **Инструмент:** analysis/_tools/_dbg_fmt.py (дизассемблер с
синтезом x87-обёрток INT 34-3B) · **Эталоны:** extracted/opal_okb/RT__2250.PRN
(TABGL), RT__2236.PRN (TABOC) · **Порт:** analysis/tables.py, analysis/units.py.

---

## Вердикт (кратко)

1. **Форматник = стандартный MS FORTRAN 5.0 RTL**, целиком в сегменте
   0x2E73 распакованного образа. Печать таблиц OPAL входит через
   `PRINT`-точку **0x2E73:0x2042 (lin 0x30772)**; исполнение скомпилированного
   формата — **0x2E73:0x1D28 (lin 0x30458)**.
2. Форматы существуют в DGROUP **не как ASCII-строки**, а как
   **скомпилированные токен-потоки** (бинарные); ASCII-строки
   «(1x,i2,2(f7.3,f12.6),…)» компилирует лексер RTL (~0x31900–0x31A44) по
   256-байтной таблице классов символов **DGROUP:0x167A**. Этим же лексером
   RTL перекомпилирует форматы «на лету» при чтении FMT-переменных.
3. Округление чисел — **HALF_UP по точному десятичному разложению**
   REAL*8 (подпрограмма **0x34CB0**, «связь ≥5 → вверх по модулю»), а НЕ
   half-even: `0.0625` при d=3 → **«.063»**. Порт печатал f-строкой Python
   (banker's rounding → «.062») — **единственное доказанное расхождение,
   исправлено** в `tables._fwo`/`units._fwo` (Decimal ROUND_HALF_UP).
4. Отрицательный нуль: минус при нулевой мантиссе **схлопывается**
   (0x34D84: проверить знак 0x2D → обнулить; эталон RT__2250 строка N=0 —
   все «.0000» без минуса). Порт уже делал так ✔.
5. Ведущий нуль мантиссы **не печатается**: «.816», «-.535640» (эмиттер
   0x302F8–0x30396: символ '0' перед '.' ставится только при
   intdigits==0 **и** fracdigits==0). Порт уже делал так ✔.
6. **Звёздочек-переполнения «\*\*\*\*\*\*\*» в RTL НЕТ** — исчерпывающее
   сканирование байта 0x2A в сегменте не находит fill-цикла; укладчик поля
   **0x3202B** копирует `rep movsw` и добивает **пробелами** 0x20
   (`mov al,0x20; rep stosb`). Порт печатает `'*'*width` — расхождение
   **неопровержимо из эталонов** (ни одного переполнения в .PRN нет),
   поведение оставлено как защитное, задокументировано.
7. E-формат: буква экспоненты **'D'** для кода 0x09 (двойная точность),
   иначе **'E'**; экспонента со знаком, добивка нулями через 0x2F51E,
   ширина +1 при |exp|>99, кламп 0x7FFF. Таблицы OPAL E-формат не
   используют — материала для сверки порта нет (в порте его и нет).

Пункт правил ТЗ «те же коды в plain-зоне сегмента 0x2E73» не потребовался:
_unp-байты удобны, file-off == lin.

## 1. Протокол вызова (как печатальщики OPAL зовут RTL)

Точка `0x2E73:0x2042` — вход семейства `_WRITE`/PRINT-диспетчера. Соглашение
(из кода 0x30772–0x307F4):

```asm
030772  push bp; mov bp, sp
        mov ax, 2                     ; режим 2 = «печать по формату»
        push cs; call 0x3357e         ; захватить интерпретатор
        push si
        mov ax, [bp + 6]              ; ← смещение формата в DGROUP
        mov [0x1884], ax              ; [0x1884] = курсор формата
        lea ax, [bp + 8]              ; адрес списка аргументов (стек)
        mov [0x1886], ax              ; [0x1886] = база списка аргументов
        mov ax, 0x18ac; push ds; push ax
        call 0x3756a                  ; заполнить контекст-дескриптор (14 б)
```

Вызывающая сторона кладёт **аргументы-элементы первыми** (глубже), смещение
формата в DGROUP — **последним** → `[bp+6]`. Состояние интерпретатора —
глобали RTL в DGROUP:

| ячейка     | смысл                                                |
|------------|------------------------------------------------------|
| `[0x1884]` | курсор в токен-потоке формата                        |
| `[0x1886]` | база списка аргументов                               |
| `[0x188A]` | курсор по аргументам                                 |
| `[0x188C]` | сегмент аргументов                                   |
| `[0x188E]` | текущий код дескриптора / ячейка-аккумулятор         |
| `0x18AC`+  | контекст вывода (14-байтный дескриптор)              |
| `[0x18DC]` | диспетчер устройства (near-call цель, грузится рантаймом из таблиц у CS:0x4070/0x4080/0x4086/0x4098) |
| `0x176C`   | буфер записи (собирается строка до флеша)            |

Флеш записи — 0x32D54. Цикл «писать элементы, пока не кончится формат» —
0x30F70–0x31070; реверсия формата (формат кончился, аргументы нет — начать
скобку заново) — 0x30831.

## 2. Токен-поток и лексер форматов

Формат-строка ASCII не исполняется посимвольно: RTL хранит в DGROUP
**скомпилированные** форматы (для табличных печатальщиков OPAL их компилировал
компилятор FORTRAN в образ данных; тот же лексер работает и рантаймом для
FMT-переменных — 0x31900–0x31A44, таблица классов **DGROUP:0x167A**).

Лексер не сравнивает символы напрямую (`cmp al,'F'` в RTL нет) — он смотрет
класс из таблицы 0x167A и по классу строит байт-токен. Интерпретатор
(0x30480–0x306C8) декодирует токены так: `type = (b & 0x78) >> 3`,
бит 7 = «немедленный операнд», младшие 3 бита = значение → ячейка `[si+type]`.
Операнды достаёт селектор **0x33546**: бит 0 — источник (0 = поток формата,
1 = аргументы), биты 1–4 — размер (<4 байт / 4 байт = слово / >4 = dword).

Коды дескрипторов (значение `[0x188E]`, диспетчер 0x300DE):

| код  | дескриптор |   | код  | разделитель/символ     |
|------|-----------|---|------|------------------------|
| 0x01 | X (пробелы) | | 0x2A | пробел / таб           |
| 0x02 | H (литерал) | | 0x29 | цифра (повторитель/w/d)|
| 0x03 | P (масштаб) | | 0x0E | `(`                    |
| 0x06 | A (строка)  | | 0x1A | `)`                    |
| 0x07 | L (логич.)  | | 0x23 | `+`                    |
| 0x08 | I (целое)   | | 0x24 | `,`                    |
| 0x09 | D (dbl exp) | | 0x22 | `-`                    |
| 0x0A | E (эксп.)   | | 0x20 | `.`                    |
| 0x0B | F (фикс.)   | | 0x12 | `/`                    |
| 0x0C | G (общий)   | | 0x13 | `:`                    |
| 0x0D | Z (hex)     | | 0x11 | `'`                    |
| 0x14 | S (знак)    | | 0x19 | `"`                    |
| 0x1B | T (табуляц.)| | 0x2E | неверный символ        |
| 0x18 | B (позиц.)  | |      |                        |

Повторители `2(...)` и ширины `f7.3` — числа класса 0x29, собираются в
токен-операнды. Проверка на формате TABGL DS 0x9ea
`(1x,i2,2(f7.3,f12.6),f9.4,f11.6,2f9.4,2f8.4)` подтверждает: группы
повторителя раскрываются стеком скобок (реверсия 0x30831).

A-дескриптор (строки CP866 шапок) — копировщик 0x31340–0x31484, ошибки
0x0A–0x0C (длина/тип). Г-формат при «широком» числе подставляет
под-форматы-строки из DGROUP: `"(E7.0)(F7.5)…(F7.0)"` @ 0x3AA,
`"(a,f6.1,a)"` @ 0xD38.

## 3. REAL*8 → десятичная строка (ядро чисел)

Конвейер (для F/E/G/D):

```
REAL*8 → 0x354D9 → 0x3663B: 16 ASCII-цифр + decexp + знак
         блок результата: {+0 знак ('-' или иное), +2 decexp,
                           +4 ndigits, +6/+8 far → строка цифр}
       → 0x34CB0: округление до n цифр (HALF_UP, см. §4)
       → 0x302F8–0x30396: эмитция поля
       → 0x3202B: укладка в поле записи
```

Важно: десятичное разложение **точное** (16 цифр double), округление идёт
по цифрам этого разложения — эквивалент Python `Decimal(float)` (тоже точен)
с последующим quantize.

Предел значащих цифр — таблица слов DGROUP:0x1572 = `{7, 16}`:
G-дескриптор (код 0x0C) и 0xF берут 16, F/E — **7** (стандартная для MS
FORTRAN 5.0 «одинарная» печать F/E с семью значащими). Из эталонов OPAL
проверить потолок нельзя: все поля таблиц имеют intdigits+d ≤ 7 либо
гарантированные нули — расхождение с портом (который печатает сколько
влезет) **неопровержимо**, порт не менялся.

## 4. Округление 0x34CB0 — HALF_UP (доказательство)

Подпрограмме передаётся блок разложения (§3) и n — сколько цифр оставить.
Ядро:

```asm
034d00  cmp byte ptr es:[bx], 0x35   ; первая ОТБРАСЫВАЕМАЯ цифра ≥ '5'?
034d04  jl  0x34d84                  ;   нет  → усечение (см. ниже)
        ; ДА — округлить вверх по модулю:
034d45  cmp byte ptr [si], 0x39      ; идём справа налево по сохраняемым
034d48  jne 0x34d72                  ;   не '9' → inc digit (0x34d7e) и выход
034d4a  …   mov byte ptr [si], 0x30  ;   '9' → '0', перенос дальше влево
034d4c  mov byte ptr [si], 0x31      ; перенос ушёл за первую цифру:
034d52  inc word ptr es:[bx + 2]     ;   «1», decexp++ («999.95→1000.0»)
        ; усечение (первая отбрасываемая < '5'):
034d84  mov byte ptr es:[bx], 0      ; отрезать строку цифр
034d88  cmp word ptr es:[bx], 0x2d   ; знак был '-'?
034d8f  jne …                         ;   нет — готово
        ;   да — проверить, остались ли ненулевые цифры (схлопывание
        ;   отрицательного нуля; эталон RT__2250 N=0: все «.0000»)
```

Это **половина-вверх по модулю** (ties away from zero): связь «ровно 5 в
первой отбрасываемой» → вверх. Не half-even: у MS FORTRAN 5.0 RTL
округление вывода конвертер именно такое (известное поведение компилятора;
здесь видно из кода — сравнение `≥'5'` без оглядки на чётность соседа).

Эквивалент в Python (реализовано в порте):

```python
Decimal(value).quantize(Decimal(1).scaleb(-d), rounding=ROUND_HALF_UP)
```

Дискриминаторы (Python f-строка = half-even, OPAL = half-up):

| значение | d | f-строка (было в порте) | OPAL RTL (0x34CB0) |
|----------|---|------------------------|--------------------|
| 0.0625   | 3 | «.062»                 | **«.063»**         |
| −0.0625  | 3 | «-.062»                | **«-.063»**        |
| 2.5      | 0 | «2»                    | **«3»**            |
| 0.5      | 0 | «0»                    | **«1»**            |
| 0.1875   | 3 | «.188»                 | «.188» (не связь)  |
| −0.00015 | 4 | «-.0001»               | «-.0001» (double ниже связи: −0.00014999…98) |

## 5. Эмитция поля 0x302F8–0x30396

Порядок символов поля F w.d:

1. знак: `'-'`, если блок-знак '-' **и мантисса ненулевая** (минус нуля
   схлопнут ещё в 0x34CB0); `'+'` — только при флаге контекста +0x14
   (SP/SS-дескрипторы; OPAL не использует);
2. целая часть; **символ '0' перед точкой ставится только если
   intdigits == 0 И fracdigits == 0** — то есть для «0.xxx» ведущий нуль
   НЕ печатается: 0.816 → «.816», −0.535640 → «-.535640» (эталоны
   подтверждают обе формы);
3. `'.'` + дробная часть; недостающие цифры добиваются **'0'**
   (0x3481F — rep stos fill); w > 0x104 (260) → ошибка;
4. G-дескриптор: недостающие до ширины позиции — хвостовые пробелы через
   таблицу [0x1580];
5. укладка в поле — 0x3202B: `rep movsw` копия + **пробелы** 0x20
   (`mov al,0x20; rep stosb`) — см. §6.

Отрицательный нуль: в эталоне RT__2250 осевая строка
`0  .000  .000000  .000  .000000  .0000  …` — ни одного «-0.0000». Механизм:
0x34D84 (усечение) + 0x34D7E-цепочка обнуляют знак при нулевой мантиссе.

## 6. Переполнение поля: звёздочек НЕТ

FORTRAN-стандарт предписывает при переполнении поля заполнять его
звёздочками, и порт печатал `'*' * width`. В RTL OPAL:

- исчерпывающий скан байта `0x2A ('*')` по всему сегменту 0x2E73
  (0x2E730–0x30730+) не находит ни одного fill-цикла вида
  `mov al,0x2A; rep stosb`;
- единственный кандидат `0x37A0E (mov dl,0x2a)` — байты инструкции
  `add di,0x2ab2` таблицы Overlay Manager, ложный;
- укладчик 0x3202B при «текст длиннее поля» ведёт себя иначе: копирует
  сколько влезает и добивает пробелами — т.е. реальный RTL-результат
  переполнения F7.3 при 1234.5 скорее «1234.5 » с обрезкой, не «\*\*\*\*\*\*\*».

**Вердикт:** поведение порта `'*' * width` — небезобидная на вид, но
**ненаблюдаемая** девиация: в эталонах .PRN переполнений нет (все числа
влезают), RTL-звёздочек нет. Оставлено как защитный guard (лучше звёздочки,
чем тихая обрезка/расползание строки таблицы); задача ТЗ разрешала только
доказанные правки.

I-формат (колонка N в TABGL — `i2`): значения OPAL 0–3, переполнение
(напр. n=100+) эталонно не встречается;RTL-обработчик I печатает число,
при нехватке ширины — тоже укладка 0x3202B (без звёздочек). Порт печатает
`f'{n:2d}'` — для эталонных значений совпадает побайтово (golden-тесты).

## 7. E-формат (справочно, таблицами OPAL не используется)

Эмитция 0x2F51E–0x2F5CB:

- буква экспоненты: **'D'** если дескриптор D (код 0x09), иначе **'E'**
  (F-порт этот путь не задействует);
- порядок: явный знак, кламп ±0x7FFF, цифры экспоненты добиваются нулями
  (0x2F51E → 0x3481F rep stos '0'); ширина экспоненты +1, когда |exp|>99
  (E12.5 «0.123E-100» vs «.123-04»-подобных усечённых форм RTL не делает —
  всегда `E±dd`);
- мантисса — та же цепочка §3–§4 (ведущий нуль также подавлен).

Ошибки форматтера поднимаются через 0x346C8 кодами 0x01–0x1F / 0x28–0x36 /
0x3D–0x5F / 0x104 (диагностических строк F6xxx в образе нет — коды идут
в общий обработчик FORTRAN-ошибок времени выполнения).

### 8.1. Правка порта (единственная доказанная)

`analysis/tables.py::_fwo` и `analysis/units.py::_fwo`: до/после —

```python
# до: f-строка — half-even
text = f'{value:.{decimals}f}'
# после: HALF_UP по точному разложению, как RTL 0x34CB0
q = Decimal(value).quantize(Decimal(1).scaleb(-decimals),
                            rounding=ROUND_HALF_UP)
text = f'{q:f}'
```

с сохранением всей пост-обработки (минус-нуль → положительный, подавление
ведущего нуля, `None` → пробелы, переполнение → звёздочки, rjustify по
ширине). Неконечные значения и разрядности >60 цифр откатываются на
f-строку (в таблицы не попадают: поле всё равно переполнено).

Тесты `tests/test_tables.py::TestFormatFwo::test_rounding_half_up` —
новые golden-случаи: 0.0625→«.063», −0.0625→«-.063», 2.5 d=0→«3»,
0.5 d=0→«1», 0.1875→«.188», −0.00015→«-.0001» (double ниже связи).
Прежние golden-тесты RT__2236/RT__2250 побайтово проходят после правки
(24 + 24 тестов tables; полный прогон проекта 952 passed / 8 skipped) —
эталонные значения не лежат на ties, поведение на них не изменилось.

## 9. Открытые пункты

- Диспетчер устройств `[0x18DC]` грузится рантаймом из таблиц у
  CS:0x4070/0x4080/0x4086/0x4098 (LPT/CON/файл) — какие цели стоят в
  статическом образе, не разрешено (байты там — код, не чистые офсеты);
  на сверку печати не влияет.
- Точная нарезка «звёздочки vs обрезка» при переполнении (§6) — если
  понадобится, решается прогоном оригинала на числе вне поля; для порта
  неактуально.
