# GTIE00 (ЭКРАН - ГОЭ) — раскладка standalone-OPJ с ГОЭ-элементом

**Карточка:** TASK_GTIE. ИК-система с голограммным оптическим элементом,
последний отказ строгого парсера на стенде (REVERSE_GVERIFY.md §6).
Итог: раскладка заголовка/поверхностей **каноническая**, ГОЭ-специфика
сводится к (а) маркеру среды 0xFFFD в gidx и (б) блоку параметров
дифракционного элемента в общем хвосте после имён. Парсер расширен,
GTIE00 загружается (ГОЭ = заглушка), отказов на стенде 0/85.

Источники: `C:\GOLDEN_DOS\GTIE00.OPJ` (1152 б, 1994, read-only),
эталон `reverse_data/golden/bank/GTIE00.PRN` (G2BANK), семейный
файл `GTIN05.OPJ` (сферич. дифр. решётка), канон `US00KI02.OPJ`.
DOSBox не запускался — всё статическим разбором.

## 1. Метод

1. Полный hex-дамп GTIE00 + прогон полей строгой раскладки (докстринг
   `fileio/standalone_opj.py`, досье GFIX §P6.1) — смещения заголовка
   и блоков λ/кривизн/толщин/gidx/RI/имён совпали побайтово.
2. Скан всех 85 `*.OPJ` стенда на маркеры ≥0xFFFC в gidx: ГОЭ-семья =
   **GTIE00** (0xFFFD) + **GTIN05/YBBS77_** (0xFFFF — зеркало/решётка).
3. Сверка декодированных λ с шапкой эталона GTIE00.PRN (`Длина волны`
   4.2500/3.5000/5.0000) и Ax 26.17 ↔ апертура 26.0.
4. Формула хвостового маркера `u32 = 202+2·ns` сверена на трёх файлах
   (GTIE 222, GTIN05 204, US00KI02 242).
5. ARH-ветка: слот GTIE00 в OPAL.ARH не существует (§5) — спасать
   «битый» OPJ из архива нечем (и не нужно: OPJ цел).

## 2. Заголовок — весь канонический

| поле | смещ. | GTIE00 | US00KI02 (канон) |
|---|---|---|---|
| имя | 0x0C | «ЭКРАН - ГОЭ» | «IR -.2X D=10 2W=72 10L 2USP» |
| ns | 0x34 | 10 | 20 |
| flags | 0x36 | 3 (три λ-слота) | 1 |
| ? | 0x38 | 4 | 3 |
| ND | 0x3A | 3 | 0 |
| тип предмета | 0x3C | 0 (∞) | 0 |
| тип изображения | 0x3E | 1 (ближнее) | 0 |
| тип диафрагмы | 0x46 | 0 ('d') | 0xFFFF ('p') |
| положение предмета | 0x4C | 0.0 | 0.0 |
| **ГОЭ-скаляр** | **0x54** | **0.12** | 0 |
| апертура | 0x5C | 26.0 | 5.0 |
| апертура (дубль) | 0x64 | 26.0 | 5.0 |
| SD | 0x6C | 0.0 | −22.2 |
| поле Y/X, рад | 0x74/0x7C | −0.017453 (=−1°) | −0.62832 |
| λ f32 × слоты | 0x9C | **4.25, 3.5, 5.0** | 10.0 |

Отличия от канона: **0x54 = 0.12** (у канонических файлов 0; скаляр
«относительное отверстие»-типа — у US00KI02 per-λ-аналог в хвосте
−0.175 = Ax/f при Ax=5, f≈28.6; у GTIE дублируется per-λ эхом
0.12×3 @0x3E4) и 0x38 (семантика не локализована, на ГОЭ не влияет).

## 3. Поверхности (блоки канонические, смещения от ns/flags)

λ-слоты @0x9C (12 б) → кривизны f64×10 @0xA8 → толщины f64×10 @0xF8 →
gidx u16×11 @0x148 → RI f64 (4×3) @0x15E → имена («ВОЗДУХ» @0x1C0,
строки 2-4 безымянные — пробелы) → хвост.

gidx = `[1, 2, 1, FFFF, FFFD, FFFF, 1, 4, 1, 3, 1]` — слот i+1 = среда
после поверхности i:

| S | R, мм | d, мм | среда после | прочтение |
|---|---|---|---|---|
| 0 | +36.98 | 2.94 | строка 1 (n=1.407) | ИК-окно (CaF₂-класс) |
| 1 | +34.04 | 34.04 | воздух | вторая поверхность окна |
| 2 | −71.82 | −17.0 | **FFFF** | зеркало №1 |
| 3 | **−17.06** | −2.0 | **FFFD** | **ГОЭ** (голограммный элемент) |
| 4 | −15.70 | −8.0 | **FFFF** | зеркало №2 |
| 5 | ∞ | 5.0 | воздух | плоскость |
| 6 | ∞ | 0.8 | строка 3 (**Ge**, n=4.022) | защитное окно Ge |
| 7 | ∞ | 0.2 | воздух | — |
| 8 | ∞ | 0.3 | строка 2 (n=1.664) | окно №2 |
| 9 | ∞ | 0.0 | воздух | плоскость изображения (d=0, не 1e20) |

RI-матрица (4 строки × λ 4.25/3.5/5.0):

```
0: 1.0      1.0      1.0       воздух
1: 1.40723  1.41407  1.39898   ~CaF2 (n≈1.41 в 3-5 мкм)
2: 1.66392  1.69526  1.62397   ~сапфир/ИТР-класс
3: 4.02166  4.03243  4.01550   Ge (n≈4.02, слабая дисперсия — да, ИК)
```

Сверка с эталоном: λ-блоки PRN = 4.25/3.5/5.0 ✓; Sp = 36.980 = R(S0)
с точностью печати (совпадение до 1e-2, природа — оптическая, не
копия поля); Ax = 26.17 ↔ апертура 26.0 ✓. Схема: ИК-окно →
зеркальный сэндвич с ГОЭ → защитные окна экрана. Отрицательные
толщины (−17/−2/−8) — нормальная свёрнутая трасса зеркал, НЕ признак
повреждения (в §6 GVERIFY подозрение снято).

**Маркер 0xFFFD**: среда после ГОЭ, RI-строку не потребляет (как
0xFFFE/0xFFFF у зеркал). У решётки GTIN05 (ns=1, gidx=[1,FFFF])
маркера FFFD нет — сэмэнтик «зеркало» достаточен; FFFD отличает
дифракционную ГОЭ-поверхность от обычного зеркала. Правило зеркал
парсера (маркер в слоте i или i+1 → S(i−1)…S(i) отражающие) даёт
mirrors = {2,3,4,5}, ГОЭ = S3 (единственный FFFD-слот).

## 4. Хвост после имён: общий для всех OPJ + блок ГОЭ

Сразу после 10-байтовых слотов имён идёт область, общая для всех OPJ
(у канонических тоже): u32 = **202+2·ns** (маркер записи; GTIE 222,
GTIN05 204, US00KI02 242), затем:

- **блок параметров дифракционного элемента** (только при FFFD):
  эхо u16 0xFFFD, через ≤0x40 байт эхо u16 ns, затем f32×8.
  GTIE00 @0x1EC/0x206/0x210:

  ```
  rec = [0.9015, 1.0, 0.000485, 1.0, 0.6328, 0.0, 0.0, 100.0]
  ```

  Идентифицировано: **rec[4] = 0.6328 мкм = λ записи, HeNe-лазер**
  (классика для записи голограмм; совпадение с линией 632.8 нм до
  4-х знаков). Кандидаты прочих слотов (не подтверждены): 0.9015 и
  0.000485 — направляющие синусы двух записывающих пучков (θ≈64.3° и
  ≈0°), единицы — флаги/порядки, 100 — шкала/КПД. Для решётки GTIN05
  в этом же месте f64 0.19580 = λ0/период (период ≈ 3.013 мкм,
  ~332 штр/мм при λ0=0.59) — блок один и тот же, формат записи зависит
  от типа элемента.
- таблица полудиаметров f32×ns (US00KI02 @0x424: 18.8-34 мм ✓; у GTIE
  @0x34C — нулевая, полудиаметры ГОЭ-записью не сохранены);
- якорь (56, 3, 1.0, 0.707, 0.577…) — зоны/веса габарита, у GTIE
  @0x3A0 = (56, 3, 1.0, 0.707, 1e-4);
- per-λ скаляр @0x3E4 (GTIE 0.12×3; US00KI02 −0.175×3) — относительное
  отверстие-класс;
- концевые константы (u32 26/3 @0x414 = апертура/число λ, 8×f32 1.0).

DOS-филлер `ec 78 ad 60` @0x438 — мусор несохранённой памяти, не
данные (тот же паттерн в пустых слотах OPAL.ARH).

## 5. OPAL.ARH: слота GTIE00 нет

Голова ARH = 128×{u32 off, u16 size} + данные — хранилище ТЕКУЩЕЙ
системы редактора, не архив именованных OPJ (REVERSE_OPCOM §21.7).

- Оригинал `extracted/opal_okb/OPAL.ARH` (11990 б): 10 слотов,
  строка «ОП-04/40» (OKULAR-класс) и имя «ST11RP03» — состояние
  1994-97 гг. 0xFFFD в файле нет.
- Живой `C:\GOLDEN_DOS\OPAL.ARH` (деградация от Чтения — память
  «Деградация OPAL.ARH»): таблица ссылается за EOF (слот 19 до
  0x4154 при файле 0x2ED6), слот 3 начинается ns=6 — остаток НЕ
  GTIE00 (ns=10), 0xFFFD в доступных данных нет.

Вывод: канонической ARH-копии GTIE00 не существует, сверять не с чем.
OPJ при этом цел (все структуры замкнуты, эталонные λ/Ax сходятся) —
«битый файл» из гипотез §6 снят.

## 6. Загрузчик (порт)

`fileio/standalone_opj.py`:

- `GOE_MARKER = 0xFFFD` — принят в gidx, RI-строку не потребляет
  (раньше 0xFFFD проходил валидацию, но раздувал n_glass=65533 →
  RI-блок уходил за пределы файла — фактическая причина отказа §6,
  а не «мусорный gidx» как таковой);
- `opj['goe']` = {surfaces, rec (f32×8), wlh (λ записи, если
  правдоподобна)} — скан эха FFFD→ns→f32×8 в хвосте, best-effort,
  неудача скана разбор не валит;
- `standalone_to_system`: ГОЭ-поверхность = заглушка — glass='ГОЭ',
  is_reflective=True, кривизна/толщина честные, n_override пустой
  (среда не меняется); **дифракция записи не моделируется** —
  warning в opj['warnings'];
- прочие поверхности/среды — честно по RI-матрице (Ge-окно S6 и т.д.).

Судьба верификации (golden_verify): GTIE00 больше не падает —
Sp = 36.98 **GREEN** (параксиальный вход заглушкой не искажён),
Sp′ **RED** ~25 % (задний фокус держит дифракция ГОЭ — ожидаемо для
заглушки), осевые веера SKIP. Полная верификация ГОЭ-системы = будущая
задача (нужна модель дифракции по параметрам записи; rec-таблица уже
сохраняется в goe-ключе).

## 7. Открытые вопросы

1. Семантика rec-слотов ≠ wlh (0.9015/0.000485/1/1/100) — кандидаты
   в §4; нужна живая запись ГОЭ в OPAL (DOSBox) с варьированием
   параметров записи (CHL/CHR/WLH/CH из OPALOPT) для пинов.
2. Скаляр 0x54/per-λ 0.12 — «относительное отверстие»-гипотеза
   (§2) не сведена к формуле (нет второго ГОЭ-файла для сравнения).
3. 0x38 (1/3/4 по файлам) — семантика не локализована; на раскладку
   не влияет.
4. GTIN05 грузится в OPAL «ПУСТОЙ таблицей» (G2BANK) — раскладка его
   OPJ корректна (ns=1, решётка), пустота — elsewhere (вероятно
   Работа-RT не умеет решётки); кандидат на волновой модуль OPAVA.
