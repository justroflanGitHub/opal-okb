# GVERIFY — золотая верификация порта против банка .PRN (14 систем)

Дата: 2026-10-17. Харнесс: `analysis/golden_verify.py`; тесты:
`tests/test_golden_verify.py`. Эталоны: `analysis/reverse_data/golden/bank/*.PRN`
(DOSBox-прогон OPAL, CP866), рецепты: `C:\GOLDEN_DOS\*.OPJ` (стенд, read-only).

**Итог по 14 системам: GREEN 48 / YELLOW 22 / RED 30 / SKIP 60.**
Опорная система US00KI02 — полностью верифицирована (G:17 Y:2 R:2,
остаточные RED — волновые ~2–3 %, §2.4). OPAL3 — R:0.

Правила задачи: правки существующих модулей порта ЗАПРЕЩЕНЫ — все
расхождения фиксируются здесь (чинить отдельной волной); харнесс
дополняет недостающие примитивы самостоятельными функциями
(`_paraxial_ray`, строгий OPJ-лоадер), не трогая порт.

---

## 1. Метод

1. Строгий разбор standalone-.OPJ (`parse_golden_opj`): раскладка
   G2BANK (имя 0x0C cp866; ns 0x34; **flags 0x36 = число λ-слотов**
   (1→кривизны с 0xA0, 3→с 0xA8); тип предмета 0x3C / изображения
   0x3E (0=дальний, 1=ближний); диафрагма 0x46 (0='d', 1='z',
   0xFFFF='p'); апертура 0x5C f64; позиция зрачка 0x6C f64; кривизны,
   толщины с маркером 1e20, gidx, матрица ПП (1+nglass)×n_λ, имена
   сред с якорем ВОЗДУХ/AIR).
2. Перенос в `OpticalSystem` порта (`opj_to_system`): n_override из
   матрицы ПП (порт остаётся источником правды по показателям),
   терминальная толщина `_IMAGE_EPS=1e-3` (обход свойства трейсера,
   §4.1), полу TODO нет — апертуры поверхностей без виньетирования.
3. Расчёт порта: параксиальные габариты + осевой веер зональных лучей
   (`axial_fan`, запуск по высоте zone·Ax от дальнего предмета).
4. Разбор эталонного .PRN (`parse_golden_prn`): габариты пучков,
   продольные/поперечные аберрации, TABOC2 (волновые/неизопл/Н ЗР);
   формат — FORTRAN-поля с фиксированными правыми границами
   (прод/попер 17/28/39/52/65/77; волновые 16/26/36/47/57), CP866.
5. Сверка «величина | OPAL | порт | Δ | вердикт»: допуск параксиальных
   ≤1e-4 отн., аберраций ≤1e-3 отн.; YELLOW — до 10× допуска;
   SKIP — конвенция OPAL не реверсирована (RED было бы ложным
   обвинением порта).

## 2. Взломанные конвенции OPAL (валидированы на эталонах)

### 2.1. Метка Tg′*100 в TABOC2

- **Дальнее изображение (img=0): |H′ ЗР| в мм** — модуль высоты
  зонального луча в плоскости выходного зрачка. US00KI02:
  −20.6762→печать 20.684 (0.03 %, все 4 зоны); габаритный Ax′ той же
  величины знак сохраняет (−20.69). Совпадает с докстрингом
  `analysis/tables.py::_axial_zone_fan`.
- **Ближнее изображение (img=1): −100·tg u′** — знак OPAL обратен
  знаку наклона порта. HELIOS8: 4/4 зоны (25.922↔26.028, 22.328,
  18.102, 12.692, точность 0.4–0.6 %); 121: 3/4 зоны (0.866↔−1.354,
  0.707, 0.5 — точность <0.2 %); зона 1.0 у 121 даёт +20.845 против
  −20.309 — см. §3.1 (каустика сферической аберрации, парность
  зоны/строки по Н ЗР сомнительна на крайних лучах).

### 2.2. Продольные аберрации в дптр (дальнее изображение)

**дптр = 1000·(1/L′зоны − 1/L′паракс), длины от плоскости ВЫХОДНОГО
ЗРАЧКА** (не от последней поверхности). US00KI02: −0.0902/−0.0560/
−0.0300/−0.0116 против −0.09008/−0.05594/−0.03000/−0.01158
(совпадение 3e-4…2e-3). Выходной зрачок — изображение входного
(0x6C) параксиальным главным лучом: Sp′=−147.6695 против −147.670
(3.2e-6).

### 2.3. Строки TABOC2 отсортированы по метке, а не по зоне

У 121 метка Tg′*100 немонотонна по зонам (каустика). Идентичность
зоны восстанавливается по колонке **Н ЗР = отн.зр·Ax** (строка с
Н ЗР=7.0152 при Ax=8.1 — зона 0.866, а не вторая по порядку).
Харнесс сшивает по Н ЗР, порядок — фолбэк.

### 2.4. Волновые (мкм): опорная сфера — систематика ~3 %

Порт `_ray_wavefront` с гауссовой опорной сферой: US00KI02 зоны
1.0/0.866 — 3.3 %/1.9 % (0.753↔0.778, 0.362↔0.369), зоны 0.707/0.5 —
GREEN; KURSOVIK — до 12× (смещённый выходной зрачок, §4.2);
121 зона 1.0 — 6.6× (близкий фокус). Гипотеза: OPAL строит сферу с
иной центровкой (выходной зрачок/главный луч) — кандидат на
следующую волну реверса.

### 2.5. Прочее

- Поперечные (гр.мнсек/мм): конвенция не сведена (кандидаты — разность
  углов выхода с параксом в гр.мнсек — дают зонально 3–60 %) → SKIP,
  §5.
- Н ЗР (мм) = отн.зр·Ax (`units.pupil_h_mm`) — тождество совпадает
  на US00KI02/OPAL3/HELIOS8/121; заметь: Ax берётся из эталона
  (см. §5), т.е. строка проверяет формулу, а не независимые данные.

## 3. Ближний предмет (obj=1): конвенции не реверсированы — 7 систем SKIP

ST4, OKULAR, OBEKTIV, PLIOPT, LAB6_GAS, S_KOND1, OPTICS#1. Что
установлено:

1. **Ax (передняя апертура) = sin NA** (ST4 0.125, OKULAR 0.40113,
   OBEKTIV 0.40448, S_KOND1 0.33) — не мм; веер запускается **по
   углу** arcsin(zone·NA) от точки предмета, не по высоте.
2. **Н ЗР = 100·tg(arcsin(zone·NA))**: ST4 12.584↔12.5988,
   OKULAR 43.715↔43.7901 (расхождение ~0.1 % — rounding печатаемой
   NA либо поправка на реальный крайний луч).
3. **Sp в дптр** (ST4 9.717, OBEKTIV 42.858, S_KOND1 33.333): для
   OBEKTIV 1000/42.858 = 23.33 мм даёт правдоподобное положение
   предмета при NA 0.40448 и полувысоте ~10.3 (S_KOND1: ровно 30 мм),
   но для OKULAR (−6.564 → −152.3 мм) гипотеза расходится с f′=24.96 —
   не подтверждена.
4. **Положение предмета в standalone-OPJ не найдено** (0x6C для
   obj=1 систем: 2.0/−10.0/−6.667/0.0/... — под него не подходит);
   без него веер и габариты порта несопоставимы с эталоном.
5. Tg′*100 у OBEKTIV (obj=1, img=0): габарит Ax2=11.01 = метка зоны
   1.0 (11.019) — та же конвенция H′ЗР, но выходной зрачок без
   положения предмета не строится.

Пока предмет не локализован в файле — строки этих систем SKIP
(сверка невозможна без угадывания); кандидаты перечислены выше.

## 4. Зрачки/диафрагмы: пробелы порта (чинить отдельной волной)

1. **`trace_ray_through_system`**: при нулевой терминальной толщине
   последний сегмент пути — направление ДО преломления на последней
   поверхности (наклон веера −0.090923 вместо пост-рефракции).
   Обход харнесса: `_IMAGE_EPS=1e-3`.
2. **`paraxial_trace` поддерживает только stop_type 'd'**:
   - 'z' (диафрагма-поверхность; ST, KURSOVIK): sP/sP′ порта = 0/мимо
     (KURSOVIK Sp′ 26.23 против 23.835); индекс поверхности-диафрагмы
     в standalone-OPJ также не локализован (скан всех поверхностей не
     даёт пары (Sp, Sp′) одновременно) → все зрачковые ссылки веера
     смещены, продольные несут систематику 1–4 %, волновые — до 12×.
   - 'd' (HELIOS8, OPAL3, LAB6_GAS): sP порта = −0 против 24.19
     (HELIOS8).
   - 'p' у 121 (obj=0, img=1): 0x6C=8.162 как входной зрачок даёт
     Sp=8.162/Sp′=−46.98 против 14.444/−1.986; гипотеза «внутренняя
     плоскость диафрагмы» проверена сканом z∈(0..35) — не
     подтверждается (Sp не достигает 14.444 ни для одной плоскости).
     Для дальнего изображения (US00KI02) 0x6C = входной зрачок —
     работает идеально.
3. **`compute_isoplanatism` падает**: 121 — KeyError(-1.0),
   LAB6_GAS — KeyError(0.4737) (интерполяция неизопл за пределами
   сетки); харнесс ловит исключение и фиксирует в заметках системы.
4. **`decode_lbo_opj`** миспарсит standalone-OPJ (λ-слоты/сдвиги) —
   заменён строгим парсером харнесса.

## 5. Источник полувысоты веера Ax

Порт не вычисляет реальный габаритный луч для 'p'/нестандартных
диафрагм (заданная апертура 0x5C ≠ фактической: KURSOVIK 10↔18.49,
121 8.53↔8.1). Харнесс берёт Ax из габаритной строки N=0 эталона
(фолбэк: максимум Н ЗР, далее апертура OPJ). Это выравнивает вход
веера, но делает колонку Н ЗР = отн.зр·Ax полу-тавтологией (§2.5);
продольные/волновые при этом независимы.

## 6. GTIE00 (ГОЭ-голограмма): раскладка OPJ отличается

~~Отрицательные толщины (−17/−2/−8), мусорные gidx (65535/65533), нет
маркера 1e20 — строгий парсер отвергает файл.~~ **Закрыто TASK_GTIE**

осевые SKIP — полная верификация ждёт модели дифракции.

## 8. Главные источники расхождений (ранжировано)

1. **Диафрагмы 'z'/'d' в `paraxial_trace`** (§4.2) — зрачковые ссылки
   смещены → продольные/волновые系统性 KURSOVIK (12 RED), ST (веер
   не сходится), HELIOS8/OPAL3 Sp. Чинится в порте + локализацией
   индекса диафрагмы в OPJ.
2. **Ближний предмет obj=1** (§3) — 7 систем вне сверки: положение
   предмета не найдено в standalone-OPJ; NA-запуск/дптр-Sp/Н ЗР-tg
   известны частично. Нужен отдельный реверс заголовка OPJ.
3. **Опорная сфера волновых** (§2.4) — стабильные ~2–3 % на зелёных
   системах (US00KI02), кратно больше там, где зрачок смещён.
4. **`compute_isoplanatism`** — падает на 2 системах (§4.3).
5. **Поперечные гр.мнсек** — конвенция не сведена (§2.5), 30 строк
   SKIP у obj=0-систем.
6. **0x6C у 'p'+ближнее изображение** (121) — семантика не
   подтверждена (§4.2).
7. **Терминальная толщина трейсера** (§4.1) — обходится `_IMAGE_EPS`.
