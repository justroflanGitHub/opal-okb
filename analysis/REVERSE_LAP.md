## 1. Вердикт

OPALLAP.EXE — **инженерный решатель «ЛАП» (Линейный Анализ Параметров)**:
подгонка/оптимизация оптической системы по множеству целевых характеристик.
Это то, чего в порту требует `gui/dialogs/fit_dialog.py` + `optimizer.py`,
но на принципиально другом уровне постановки:

- **многоцелевая** задача: одновременно параксиальные габариты (f′, BFD,
  увеличение), аберрации отдельных лучей, волновые коэффициенты, MTF-марки;
- **якобиан d(мерит)/d(параметр) — центральные конечные разности P±DP0**
  (код: цикл 0x67BC драйвера GTISL, см. §5); дифференциальная трассировка
  RAYSNL даёт аналитические производные луча **по зрачковым координатам**
  (SR(i,j)), но не по конструктивным параметрам;
- три режима решателя: **GTISL** (линейный/основной), **GTISNL** (нелинейный),
  **GTISGR** (градиентный) — семейство по трассам протокола;
- итерации с **демпфированием**, лимитерами, границами и **штрафами**
  (PENIP0/PENSS), статусы останова ISTOP/JSTOP, счётчик NSTEP, протокол
  каждой итерации в файл PROTOCOL;
- мерит = Σоф(I)² + штрафы (та же формула, что в OPALOPT.DOC для
  OPT/OPTW — см. REVERSE_OPTDOC §1);
- **СЛАУ-решатель**: линейная система решается **явными развёрнутыми
  формулами на скалярах COMMON-блока** (размерность ≤5 параметров в
  линейном режиме). Признаков цикла исключения Гаусса или разложения
  Холецкого в образе **нет** (см. §6 — доказательство сканированием).

Почему порт «не работает» (воспроизведено ранее): его подгонка —
одиночная бисекция по одному параметру без проверки чувствительности
(вырожденный диапазон `[58.3422, 58.3422]` при `fit d f′`), а «DLS» —
градиентный спуск по скалярному RMS с clamp, ломающим конечные разности.
Полная сверка — §8, ТЗ на новый `optimization.py` — §9.

**Известные лимиты merged-образа**: (а) вызовы юнит→юнит, оставшиеся на

## 4. Строки → назначение и workflow

Заголовок экрана: «Система-Работа-OPAL-PC» (0x3C630). DGROUP содержит
таблицу имён данных: `SDIA`, `lAVTO`, `SRT`, `OPASDT`, `SDIA OPALLAP SRT RT
WA AI`, `gforus.dat`, `GIA` — протокол/словари решателя; теги видов функций
отклика: `WA RAY ABER APER DIST MAGN GLOB` (волновая/лучи/аберрации/
апертура/дисторсия/увеличение/габариты). Диалог зрачка: «1152 точки»,
«сетка регулярная», «азимуты», «узлы». Подпись RTL подтверждает MS FORTRAN:
«MS Run-Time Library - Copyright (c) 1990, Microsoft Corp».

Workflow (по меню ЛАП FUN_0000_6067 и диспетчеру работ FUN_0000_0d21):

1. **Задание**: списки целей (функции отклика с целевыми значениями,
   нормировками и весами), варьируемых параметров (PAR, коды в таблице
   [0xa16+2i]), границ/связей → штрафы.
2. **Диспетчер работ** FUN_0000_0d21 (work1..9): 1→FUN_6000_08fe,
   2→0bb5, 3→0d8c, 4→0f97/FUN_8400_543e, 5→13ca, 6→таблицы+FUN_8400_543e+
   FUN_6000_ae78+18b2, 7→FUN_0000_2a62→FUN_8400_0000/FUN_6000_ae78,
   8→FUN_0000_2c23, 9→FUN_0000_2c1c. Работы = подготовка данных/трассировка/
   аберрации (юниты 2/4/6 — вычислители, рут — драйверы).
3. **Решение** (меню ЛАП): команда решателя → FUN_0000_6067 (GTISL-драйвер,
   §5) → sub_074c05 (ядро итераций) → протокол в PROTOCOL (открытие
   FUN_1000_cdb7, имя @ ds:0x7a62; запись 1ECB:59D2 / 1ECB:5AF0).
4. **Протокол итераций**: пул строк 0x3CA60–0x3E960; печать = far-вызов
   писца с сегментом пула в DX (14 ссылок драйвера на сегмент 0x3CA6) и
   смещением сообщения; заглушки `mov dx,<seg>; jmp 0x2695E/0x2699C`
   (FUN_2000_2e04..2e68) — по одной на сообщение.

Таблицы зон 0x3CC30–0x3D2B0 (ABERRAY): «Главный луч», «Входные/Выходные
канонические зрачковые координаты», «Глобальные координаты изображения»,
«Расфокусир: сферическая аберрация», «синусный астигматизм», «синусная
кома», волновые коэффициенты `C x20/S x11/C x22…`; «ЭЛЕМЕНТАРНОЕ
ПРЕОБРАЗОВАНИЕ»: зеркальное / −1-й поворот / 1-е и 2-е увеличен. / анаморф /
2-й поворот / оборачив. — набор допустимых преобразований параметров
(связи-линки).

## 5. Карта вычислителей (главный драйвер GTISL = FUN_0000_6067)

`FUN_0000_6067` [0x6067..0x6E2D] — драйвер линейного решателя:

1. **0x67BC — якобиан конечными разностями** (центральные, P±d):
   ```
   0067bc  loop i=2..5 (слоты по 4 Б):
           FLD [0x67dc]        ; текущий параметр P
           FSUB [0x7f38+4i]    ; −d
           FSTP [0x7a1c+4i]    ; → P−d
           FLD [0x67dc] / FADD [0x7f38+4i] / FSTP [0x7a20+4i]  ; → P+d
           [0x7f38+4i] += [0x682c]   ; приращение шага d
   ```
2. **Цикл параметров** `[0x7a3c] = 1..5` (`cmp 5 / jle` — **линейный режим
   берёт ≤5 параметров**): код параметра `[0xa16+2i] → [0x7a34]`; для
   i==1 — FUN_7800_7a12(mode 5, −DP0: `[0x7b36] = −[0x67d4]`);
   FUN_7800_4fb4(...,300); затем **FUN_0000_4704**(P∓d, …) — полный прогон
   работ для возмущённой конфигурации; статус `es:[0x1950] = −1` — проверка
   прерывания/ошибки трассировки (цикл повторяется, пока статус ≠ −1).
3. **0x6a8e — sub_07d721** (юнит 4): составной вычислитель откликов;
   тянет семейство трассировки юнита 2: FUN_6000_4672, sub_099970,
   sub_06313a, sub_07208e (×3), FUN_7800_525c/51ec/511a и цепочку
   FUN_6000_9efa/9e52/a018/6a009/6a054/6a090/6a045/69e3a.
4. **0x6b73 — интерфейс/режимы**: FUN_1000_176b (селектор), ветвления по
   режимам 7 и 4 (`[0x681c]`, `[0x6822]`) — путь 0x6ffd.
5. **0x6c7c — path B (собственно решение)**: динамические массивы
   (RTL-alloc FUN_1000_fad8/fa06, дескрипторы с границами 1..49 и 1..5 —
   до 49 функций отклика на ≤5 параметров), протокол-заголовок GTISL,
   FUN_1000_d4a6 → счётчик целей, затем вызов **sub_074c05** (26 аргументов,
   `retf 0x34`) — ядро итераций; после него — протокол-футер и `FSTP
   [0x7a5a]` (фиксация результата). Path A ([0x6800]==0) — только прогон
   оценщика FUN_0000_4704 без решения.

Мастер-оценщик **FUN_0000_4704** [0x4704..0x5418] — единая точка вычисления
F/DF от возмущённой конфигурации (его трассы: WNBSFU `L=,IMM=,IRAY=`,
EAASAP, SLICKB `NT,delY,delX,ckbY,ckbX,CkbRH`, `CHRR=`).

**sub_074c05** [0x74C05..0x7561B] (юнит 4) — итерационное ядро:

- читает описатели через указатели `[0x4da4]/[0x4da6]`, нормировки
  `[0x6d0c..0x6d18]`; масштаб `[0x8f1e]=[0x53b0]·[0x4da8]`,
  `[0x8f1a]=[0x6d0c]·[0x6d18]·[0x6d14]·[0x6d10]`;
- **вырождение**: `FCOM [0x4dac]` → при нулевом делителе ISTOP=−1
  (`[es:arg]=0xFFFF`) и немедленный выход (0x74CC1);
- коррекции: `cur = −(x·k)/[0x8f1a]·[0x8f1e]` (четыре слота, 0x74CE0);
- **критерии останова по целям** (0x74E87):
  ```
  FLD [8ef4]; FSUB [8f0e]; FABS; FCOM [8f06]   ; |cur1−цель1| < допуск1 ?
  FLD [8ef8]; FSUB [8f12]; FABS; FCOM [8f0a]   ; |cur2−цель2| < допуск2 ?
  ```
- **демпфированный шаг** (0x74F0F): `[0x8ef4] = [0x8efe]/[0x4db2] +
  [0x4dba]` — т.е. `x_new = x/λ + c` (λ — коэффициент демпфирования);
- заполнение матрицы поправок: `bx = stride·i + 4·j + base` (0x74F6C,
  столбцовая раскладка FORTRAN);
- финализация юнитом 2: sub_0632b2 (x87-интринсик от одного аргумента —
  |x| либо √x), sub_0633b5 (×3), sub_062f1e (×2);
- арифметика — только на фиксированных адресах COMMON `[0x8Exx]/[0x8Fxx]`
  (именованные скаляры FORTRAN), см. §6.

## 6. СЛАУ: доказательство отсутствия Гаусса/Холецкого

Скан всего образа на индексные mem-формы x87-арифметики (`CD 3X` + modrm с
базовым/индексным EA, escape D8/DC/DE, операции ADD/MUL/SUB/DIV):

- **юниты 1–6: ноль** индексных форм (вся арифметика юнитов — на прямых
  абсолютных адресах COMMON и стековых [bp±d]);
- **рут: только [bp±d]-локалы** (кластеры 0x9C0A, 0xA788/0xA8B8 —
  геометрия поверхностей: FPTAN/F2XM1, направляющие косинусы), ни одного
  `[bx+si]`-умножения/деления;
- `FSQRT` в образе **один** (0x262A0) — внутри зоны FORTRAN-интринсиков
  0x260F6–0x26373 (там же пачки FABS/FTST), т.е. это библиотечный `SQRT`,
  а не разложение Холецкого.

Вывод: обобщённого цикла исключения (Гаусс) или квадратного корня
(Холецкий) в OPALLAP **нет**. Система при ≤5 параметрах решается явно
развёрнутыми формулами на именованных скалярах COMMON (`FMUL/FDIV/FCHS` по
фиксированным адресам [0x8Exx]/[0x8Fxx] внутри sub_074c05) — эквивалент
Крамера/явных нормальных уравнений малой размерности. Для порта это
означает: воспроизводить «аутентичный» решатель не нужно — достаточно
численно-стабильного решения (JᵀJ+λI)·ΔP=−Jᵀf любой библиотечной процедурой;
поведенчески это тот же GTISL.

## 7. Мерит-функция

По коду + REVERSE_OPTDOC §1 (формулы OPALOPT.DOC, те же в трассах):

- отклик цели: **оф(I) = (офт(I) − офз(I))/офн(I) × офв(I)** — текущее,
  целевое, нормировка, вес; мерит **F = Σ оф(I)²** (в протоколе — FMIN);
- штрафы: **шф = min(0; (нр−t)·g)** — активны при выходе за границу/связь
  (PENIP0 — границы, PENSS — связи PGL), добавляются к мериту;
- масштабирование GTIMAS (нормировка столбцов якобиана по max
  (RO(1)²+RO(2)²)) до решения;
- лимиты задачи: PAR ≤ 64 (OPALOPT), в линейном режиме фактически ≤5
  (§5.2); MTF-марок ≤20; до 49 функций отклика (дескриптор 1..49, §5.5);
- волновые коэффициенты и поперечные аберрации берутся из таблиц ABERRAY
  (§4) через работы диспетчера; MTF — через WNBSFU/EAASAP-семейство.

## 8. Сверка с портом

`gui/dialogs/fit_dialog.py` (диалог) + `optimizer.py` (движок), main.py:1552:

| аспект | OPALLAP ЛАП | порт | последствие в порте |
|---|---|---|---|
| постановка | N целей × M параметров одновременно | 1 цель × 1 параметр | нельзя задать «f′ + BFD + сферическая» вместе |
| якобиан | центральные разности P±DP0, масштаб GTIMAS | forward δ=1e-4·max(1,\|x\|) по скаляру | вдвое грубее, O(h) вместо O(h²) |
| решатель | (JᵀJ+λ)ΔP=−Jᵀf, ≤5 пар., явные формулы | dx=−g/(gᵀg+λ)·√(gᵀg) по градиенту скаляра | «DLS» вырожден в нормированный градиентный спуск |
| цели | оф(I) с нормировкой и весом + штрафы | только RMS пятна (в DLS) / f′,BFD,Γ (в fit_*) | аберрационные/волновые/MTF-цели недоступны |
| границы | штрафы PENIP0/PENSS, статус ISTOP/JSTOP | молчаливый clamp | clamp обнуляет шаг КР → grad=0 → ложная сходимость |
| останов | по допускам целей, NSTEP, ISTOP-коды | \|Δf\|<tol, \|dx\|<1e-15 | нет диагностики вырождения/недостижимости кроме ValueError |
| диагностика | протокол итераций (GTISL-трейсы) | callback | нет протокола решения |

Воспроизведённые отказы (предыдущий запуск): `fit d f′` → «Невозможно
достичь f′=61.2593… Достижимый диапазон: [58.3422, 58.3422]» — толщина
последней поверхности физически не влияет на f′, но `fit_focal_length`
(в отличие от `fit_bfd`) не делает пробу чувствительности и выдаёт
вырожденный диапазон вместо внятной ошибки; `fit d BFD` → «Изменение
thickness поверхности 2 не влияет на BFD…» — детект правильный, но диалог
позволяет выбрать такой параметр (для толщин исключается только последняя
поверхность, а не «не влияющие»); `fit R f′` — работает. Корневая причина
обоих: порта нет решателя многоцелевой задачи — он и не претендует, но
UX-ошибки и вырожденные диапазоны — прямое следствие одноцелевой бисекции
с эвристическими границами [0.01x..100x].

## 9. ТЗ на `optimization.py` (волна 9-код)

Переписать `optimizer.py` по модели ЛАП (API-совместимость по копированию
системы сохранить; старые `optimize/optimize_dls/optimize_simplex` —
делегируют в новый движок или остаются как legacy-пути).

### 9.1. Вход

```python
@dataclass
class Goal:            # функция отклика = «оф(I)»
    kind: str          # 'efl'|'bfd'|'magnification'|'transverse'|'wavefront_coef'
                       # |'mtf_mark'|'longitudinal'|'glass_boundary'
    target: float      # офз
    norm: float        # офн (нормировка; 0 = автo = max(|target|, typ))
    weight: float = 1.0    # офв
    tol: float = 1e-4      # допуск достижения цели (критерий ISTOP)
    refs: dict = field(...)  # поверхности/поля/λ/лучи/коэффициенты

@dataclass
class Variable:        # «PAR»
    surface_idx: int
    param: str         # 'radius'|'thickness'|'conic'|'semi_diameter'
    dp0: float         # шаг конечных разностей (в единицах параметра)
    bounds: tuple | None   # (min,max) → штраф PENIP0 вместо молчаливого clamp
    link: str | None   # имя «элементарного преобразования» (связь PGL/PENSS)

@dataclass
class Penalty:         # «шф»
    ref: ...; kind: 'bound'|'link'|'custom'; t: float; g: float

def solve(system, goals, variables, penalties=(), *,
          mode='linear',            # 'linear'(GTISL)|'gradient'(GTISGR)
          max_iter=50, damping=1.0, tol=1e-8, num_rays=30,
          protocol=None, callback=None) -> FitResult
```

### 9.2. Выход

```python
@dataclass
class FitResult:
    system: OpticalSystem        # оптимизированная копия
    converged: bool
    istop: int                   # 0=допуски целей; 1=NSTEP-максимум;
                                 # 2=нет улучшения; -1=вырождение (делитель≈0)
    nstep: int; fmin: float      # счётчик итераций, финальный мерит
    residuals: list[float]       # оф(I) по целям
    history: list[dict]          # per-iteration: nstep, fmin, x, λ
    protocol: list[str]          # строки протокола (аналог GTISL-трейсов)
```

### 9.3. Алгоритм (linear/GTISL-эквивалент)

1. P ← текущие значения переменных; λ ← damping.
2. Цикл `nstep = 1..max_iter`:
   а. F(P) — прогон всех целей через оценщик (параксиальный след +
      трассировка + таблицы аберраций); возмущённые прогоны кэшируются.
   б. **Якобиан J[m×n] центральными разностями** `P±dp0` (не forward!);
      столбец = (F(P+dp0·eᵢ)−F(P−dp0·eᵢ))/(2·dp0·eᵢ).
   в. оф = (F−target)/norm·weight; штрафы ψ = Σ min(0;(нр−t)·g)².
   г. Масштабирование GTIMAS: столбцы J нормируются на max|J[:,i]| (радиус
      и толщина несоизмеримы).
   д. Решение **(JᵀJ + λ·diag(JᵀJ))·ΔP = −Jᵀ·оф** (Марквардт); решатель —
      `numpy.linalg.solve` (Гаусс с частичным выбором ведущего элемента);
      при n≤5 допустимы явные формулы (аутентично ЛАП, §6); сингулярность
      → istop=−1 (аналог FCOM [0x4dac] → ISTOP=−1).
   е. Лимитер шага: |ΔPᵢ| ≤ k·dp0ᵢ (k≈10); выход за bounds — штраф +
      отражение в границу (не молчаливый clamp до вычисления разностей).
   ж. Критерии останова (порядок как в коде 0x74E87): все |оф(I)| < tolᵢ →
      istop=0; делитель/градиент ≈ 0 → istop=−1; nstep=max → istop=1;
      |ΔF|<tol·max(1,|F|) два шага подряд → istop=2.
   з. λ-адаптация: успех (F уменьшился) → λ/=2; неудача → λ*=3 и повтор
      шага (line search не нужен, но ≤15 бисекций α допустимы).
3. Протокол: строка на итерацию `nstep, FMIN, λ, ΔP` + финал
   `ISTOP,NSTEP` (формат ЛАП — для узнаваемости).

### 9.4. Solve-режим (замена fit_*)

Одна цель + один параметр: не бисекция, а Ньютон по чувствительности
dF/dP из центральной разности пары P±h; **обязательная проба
чувствительности** `|dF/dP| < eps` → явная ошибка «параметр не влияет на
целевую характеристику» (закрывает оба воспроизведённых отказа; для f′
автоматически отсекает толщину последней поверхности). Границы поиска —
из bounds переменной, не эвристика [0.01x..100x].

### 9.5. Тесты приёмки

1. демо-двояковыпуклая линза: `fit R f′` — сходится там же, где сейчас;
2. `fit d f′` (толщина до плоскости изображения) — понятная диагностика,
   не «достижимый диапазон [x,x]»;
3. многоцелевое решение: цели {f′=100, BFD=95} по {R1,R2,d1} — обе в
   допусках за ≤20 итераций;
4. оптимизация аберраций с фиксацией f′ (цель-ефl с большим весом +
   transverse-цели) — RMS падает, f′ уходит <0.5%;
5. граница: параметр упирается в bound → штраф растёт, istop=1, параметр
   в границе (не за ней);
6. вырождение: все цели нечувствительны к параметру → istop=−1, не цикл.
