## 1. Вердикт

**Гипотеза «OPALO/OPALOW = дифракционный анализ уровня 2» подтверждена
частично и уточнена.** Оба EXE — это ОПТИМИЗАТОРЫ ОПАЛ-ПК, вычисляющие
свои оценки («марки») вызовом математики уровня 2 (WA/GIA/DIA/MTF/SPOS
по ANALIZE.DOC §5–9):

| программа | роль (по встроенной справке) | страница |
|---|---|---|
| OPALO.EXE | «Описание марок для оптимизации **геометрических аберраций**» | `OPT.OH` |
| OPALOW.EXE | «Описание марок для оптимизации **коэффициентов Цернике**» | `OPW.OH` |

Доказательства:

1. **Таблица 63 марок в OPALOW** (ds:0x6080, лин. 0x69df0, записи по 4 байта,
   после неё int32-таблица номеров 1000..1043, 52, 70, 62):
   `C D ES CA CN N DNR AL SO SD SI CHL CHR WLH CH V0 VG0 SG' DSG' SP0' SG
   SP0 L LS' LS LSS' OP DE DEO DEI DED AS ID MTF DSA ZA RCA DPA AST DIS
   DIS% DVL DVL% ZM ZS RCM RCS DSP DSP' FCM DYM ZMM ZSM RCMM RCSM DXS DYS
   ZMS ZSS DXT DYT ZMT ZST CWZ NARC` — среди них **MTF** (дифр. ЧКХ, §8/§9),
   **AST** (астигматизм, §6), **DIS/DIS%** (дисторсия абс./отн., §6),
   **CHL/CHR/WLH** (шпальные миры, §9), **V0/VG0** (виньетка), **DSP**,
   **EQF** (в OPW.OH; равнофокусность = критерий опт. фокуса). В OPALO этой
   таблицы нет — наборы марок у программ разные.
2. **353 из ~700 тел функций побайтово идентичны** OPALO↔OPALOW (общий
   вычислительный кернел: трассировка, зрачок, интегралы) при ~350
   уникальных у каждой (свои наборы марок).
3. Оба вызывают **резидент OPAL.COM по фиксированным far-адресам**
   (сегмент 0x6771+: `lcall 0x6771:0x188/0x1fe/0x600` = UI-примитивы,
   0x6771:0x600 рисует прямоугольники координатами) — кода резидента нет
   в образе, память нулевая в статике: link-time привязка, отсюда
   «This program must be run under OPAL-PC» (ds:0x3634).
4. Пул вещественных констант уровня 2 (см. §5) содержит решёточные
   нормировки дифракционного счёта; комплексная арифметика COMPLEX*16
   каскадами — см. §6.

Спавн вспомогательных EXE (строки ds:0x463..0x687): `KATEX.EXE`,
`KATEXSAVE.TMP`, `OPALTRAN.EXE`, `OPALFIND.EXE`, `WRITEOC.EXE`, `OH.EXE`,
команды окружения `OSEDIT/BAD COMMAND/EXIT MENU/OPAL.EXE`,
`OPAL-PCJOB:SYSTEM:COMMAND`; файлы данных `OPTMTF.DAT` (ds:0x42 — первый
элемент DGROUP OPALOW!), `optrus.dat`, `OPALOW.DAT`, `SAVE.TMP`,
шаблон `COPY OPTMTF.DAT MTF`. Русских cp866-строк в образах НЕТ (весь
текст выведен в .OH/.REG-файлы и резидент).

## 2. EXEPACK и оверлеи

EXEPACK-трейлеры (методика REVERSE_UNP §1): OPALO CS0:IP0=1886:5A5B,
OPALOW 1DCD:5EF7; распаковка воспроизводима, ассерты трейлера проходят.

Хвост каждого EXE — цепочка мини-MZ (ovno 1..4), шаг = pages·512:

| | OPALO | OPALOW |
|---|---|---|
| юнит 1 (размер) | 0xB568 | 0xDEEB |
| юнит 2 | 0xD3F3 | 0xD3F3 (идентичен) |
| юнит 3 | 0x5199 | 0x5199 (идентичен) |
| юнит 4 | 0xA2BD | 0xA2BD (идентичен) |
| таблица входов рута | 111 записей (39/46/11/14 по юнитам) | 111 (39/46/11/14) |
| DGROUP | 0x5957 | 0x63D7 |

**Уточнение модели оверлеев против B1a-плана: юниты грузятся в ОДНУ
область** — ридер 0x1DF84 (OPALO) всегда пишет на 0x442D:0 порциями по
0x400 параграфов; OPALOW — 0x48B7 (ридер 0x2389F). Загрузчик 0x1E029:
таблица юнитов ds:0x2F74 (файловые позиции), проход по цепочке мини-MZ
(`[si+0x1a]`=ovno), накопление смещения, затем чтение и применение
релокаций (0x1DFC2, адденд из ds:0x2E24). Т.е. в памяти живёт ОДИН юнит
одновременно, «юнит = набор подпрограмм одной группы работ», подменяемый
при вызове. Для Ghidra юниты 2–4 перелинкованы на фиктивные базы
(OPALO 0x6800/0x9000/0x9800, OPALOW 0x7200/0x8000/0x8600) с контролем
затирания рута (`opalo_ovl.py`, печать «юнит N затирает…» — 0 случаев).

Сборка Ghidra: `C:\tools\ghidra_scripts\BuildOpalo.java` / `BuildOpalow.java`
(блоки R0..R6 + OV2..OV4, сиды = входы таблицы + диспетчер, вход = CS0:IP0);
дальше `-process -noanalysis` + ListFuncs/DecompileAll. Функции: OPALO 795,
OPALOW 820 (после автоанализа).

## 3. Схема x87-эмуляции Microsoft (важно для чтения кода)

MS FORTRAN 5.0 без сопроцессора: каждая ESC-инструкция закодирована
как `INT 34h..3Dh`:

- `CD 34..3B` — INT заменяет ESC-байт D8..DF, далее modrm(+disp) как обычно
  (пример: `CD 35 5E AA` = FSTP dword [bp−0x56], `CD 39 06` = FLD qword [si]);
- `CD 3C` — ESC-байт **сохранён** после INT (проверено статистически:
  97% следующих байт D8–DF), т.е. `CD 3C DD 47 F8` = FLD qword [bx−8];
- `CD 3D` — макрос «FISTP → DX:AX» (два байта, далее обычный код);
- `CD 3B DF E0` = FNSTSW AX (×92 в OPALO).

Статистика по кодовым зонам OPALO (число ловушек): D8 325, D9 950,
DA 4, DB 145, DC 1433, DD 2386, DE 371, DF 119, 3C 819, 3D 934.
Чтение такого кода вслепую невозможно — написан `_tools/x87dis.py`
(capstone-16 + декодер ловушек); выборки — `reverse_data/disasm/*.txt`.

В самой RTL (загрузка рута с 0x18860 OPALO / 0x1DCD0 OPALOW; обработчики —
линейные 0x1F4A6…0x1F829 в OPALO, в OPALOW сдвиг +~0x5470) сидят
обработчики-реализации: f2xm1×8 (0x1F4A6…0x1F7EB — EXP/LOG/POW),
fptan 0x1F506, fprem 0x1F66C, **fsqrt 0x1F72A**, **fsincos 0x1F7C1**,
fpatan 0x1F7D4/0x1F829 — т.е. трансцендентные функции физически
присутствуют только как обработчики эмулятора; **в прикладном коде
ни одного FSIN/FCOS/FSQRT/FPTFAN-ловушки нет** (гистограмма мнемоник:
fld 2112, fstp 1856, fistp 1230, fmul 702, fcom 385, fdiv 282, fadd 278…).
Тригонометрия для ДПФ берётся вызовом RTL-функций (far-call) либо
вычисляется в юнитах — см. §6, пробел.

OPALO (`OPALO_full.bin`, 0xA22BD):

| зона | диапазон | содержание |
|---|---|---|
| R0 BSS/DGROUP | 0x00000–0x106A0 | PSP-пул, стеки RTL |
| R1 RTL | 0x106A0–0x206A0 | стартап 0x1886:5A5B→(RTL-группа, DS=0x5957), эмулятор x87, I/O |
| R2 код | 0x206A0–0x306A0 | диспетчер оверлеев 0x1E197, ридер 0x1DF84, загрузчик 0x1E029, прикладные функции |
| R3 код | 0x306A0–0x406A0 | прикладные функции (самые плотные по x87) |
| R4 пул юнитов | 0x406A0–0x506A0 | runtime-место юнита (база 0x442D0) |
| R5 код/константы | 0x506A0–0x606A0 | таблица входов 0x5C396, **пул double 0x5C510–0x5CF50** (ds:0x2FA0–0x39E0) |
| R6 данные | 0x606A0–0x667B0 | DGROUP-данные, строки |
| OV2/OV3/OV4 | 0x68000/0x90000/0x98000 | юниты на фиктивных базах (runtime 0x442D) |

DGROUP=0x63D7, пул double 0x66F44–0x679F6 (ds:0x317C–0x3C86),
таблица входов @0x66D66, диспетчер 0x23AA:0x00A3, таблица марок ds:0x6080.

Разница адресов OPALO↔OPALOW для одного кода: +0x547..+0x646 параграфов
(ранние сегменты) — OPALOW-рут шире из-за большего юнита-1.

## 5. Пул вещественных констант (FORTRAN-литералы уровня 2)

Пулы идентичны по составу (OPALO ds:0x2FA0.., OPALOW ds:0x317C..), значения:
`1/128`×8 (и −1/128), `0.5`×2, `524288`=2¹⁹ ×4, `1e-5/1e-6/1e-7/1e-9`,
`0.9999/0.99999/1.00001`, `0.9, 0.07, 0.05, 0.1, 0.001, 20, 25, 5, 99,
100, 777(OPALOW), 1000, 100000`…

Интерпретация: **шаг решётки 1/128** → сетка зрачка/ФРТ 128 (нормированная
координата ρ∈[−1,1] с шагом 1/64 на полу-зрачке — согласуется с §7 GIA
1152/512/288 точек на полузрачке как СУПЕРсет для геометрии и 128 — для
дифракции); **2¹⁹=524288** → нормировка БПФ/свертки (128²·32 или 512·1024);
**20** → ≤20 частот ОПФ (ANALIZE.DOC §8); `0.9/0.07/0.05` — параметры
аппроксимаций ОПФ; `1e-6..1e-9` — допуски сходимости; `0.9999/1.00001` —
границы нормировки.

Статических таблиц sin/cos (twiddle) НЕТ ни в одном формате (float64/80 —
проверено полным сканом) — тригонометрия вычисляется RTL-вызовами в момент
счёта. «Размер решётки 64/128/256» из плана B1a: подтверждён только 128.

Константы передаются в подпрограммы юнитов **по ссылке** (FORTRAN CALL):
`lea ax,[0x320a]` (1/128) + массивы ds:0x9352/0x937A/0x9382 → `lcall 0x70d4:7`
(юнит-2, функция работы с массивами); 2¹⁹ → вызовы из OPALOW-рута
(FUN_1000_7dff @0x1845F и 0x18739). Т.е. нормировка — параметр кернела.

## 9. ТЗ на psf_mtf.py (волна 10 — уточнение после сверки)
