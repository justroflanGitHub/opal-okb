# REVERSE_OPAVA — карта OPAVA.EXE (модуль волнового анализа ОПАЛ-ПК)

Волна 8 / задача B1b. Методика — `REVERSE_UNP.md` (EXEPACK-распаковка исполнением
стаба при load-сегменте 0, посегментная пересборка Ghidra, far-скан). Смежное:
`REVERSE_TSR.md` §5 (int 3Fh у OPALA), §6 (шина x87 int 34h–3Dh), §7 (int 90h OPAL.COM).

Объект: `extracted/opal_okb/OPAVA.EXE` (341 525 байт). Распакованный образ:
`analysis/reverse_data/OPAVA_unp.bin` (0x64000). Декомпил: `C:\tools\rea-out\decomp_opava\`
(775 функций + `_index.txt`), проект Ghidra `C:\tools\rea-out\OPAVA`.

## Вердикт

**Гипотеза подтверждена полностью**: OPAVA = работа «WA» ОПАЛ-ПК — *полный анализ
аберраций: полихроматическое волновой фронт*. Меню (DATA_MENU 437B:0010):

> 1. Коэффициенты зонального разложения — **WZON**
> 2. Коэффициенты глобального разложения — **WGLB**
> 3. СКВ волновой аберрации по полю — **RMS**
> 4. Плоскость наилучшей установки — **BFP**
> 5. Отображение волнового фронта — **WDSP**

(команды — DATA_MENU 437B:00CE). Разложение по 28 полиномам Цернике
(таблица пар в DGROUP — ASCII «00 20 40 … 66», см. §6). Документация работы —
`DOC/ANALIZE.DOC` §5 (нумерация пунктов 5.2/5.3/5.4/5.5 совпадает с пунктами меню),
научная часть — `DOC/MAN_VP.DOC` («Влияние параметров на глобальные коэффициенты
разложения волновой аберрации»).

## §1. Заголовок MZ и EXEPACK-трейлер

Упакованный EXE: pages/bytes_last → образ 0x3B86E байт, дальше **пул оверлеев**
0x3B86E..0x53615 (0x17DA7 ≈ 98 КБ, §5). Трейлер EXEPACK (file 0x3A540, magic `RB`):

| поле | значение | комментарий |
|---|---|---|
| IP0 | 0x5EE9 | вход после распаковки |
| CS0 | 0x1C7C | CODE_RTL2 (овелей-менеджер, §5) |
| SP0 | 0x1000 | |
| SS0 | 0x622B | STACK |
| stub_para | 0x132E | |
| mem_end_para | 0x6202 | |

Образ получен исполнением стаба при load-сегменте 0 (та же схема, что OPALA;
`_tools/exepack.py`), релокации не нужны — сегментные иммедиаты линк-тайтовые
абсолюты при базе 0. Как и у OPALA — псевдо-плоская far-адресация линкера
(`lcall (0x27,0)` = линейный 0x270).

## §5. Оверлейный менеджер и пул (главное отличие от OPALA)

**Конвенция int 3Fh** (3 байта payload — у OPALA было 5):

```
CD 3F <sel:byte> <entry:word>   ; вход = (таблица_сегментов[sel]):entry
```

Обработчик 1C7C:5DC5 (лин. 0x22585): сохраняет регистры в журнал-кольцо DGROUP:0x1F62
(записи по 5 байт, ≤0x80), извлекает sel/entry, читает таблицы:

| таблица | адрес | тип | содержимое |
|---|---|---|---|
| селектор → сегмент | DGROUP:0x3204 | word | 49 статических значений (лин. 0x5BFF4) |
| селектор → файл | DGROUP:0x3266 | byte | 1..4 — номер MZ-модуля пула |

Загрузчик (0x22648, коды 6/7 через [0x248B]) читает модуль из `opava.exe`
(имя в DGROUP:0x32AB), трэмплин: `push cs:5D83; push dx(сегмент); push cx(entry); retf`.

**Пул = 4 MZ-модуля в хвосте файла** (первый — 0x3BA00, дальше по страницам):

| файл | MZ @file | код @file | загрузка | reloc | селекторы | сегменты загрузки |
|---|---|---|---|---|---|---|
| 1 | 0x3BA00 | 0x3C200 | 0x5DF3 | 478 | 1–9 | 35FC, 370D, 371B, 375D, 37D5, 3804, 3AD2, 3B58, 3B68 |
| 2 | 0x42000 | 0x42400 | 0x431F | 190 | 0A–0C | 35FC, 36A3, 39DD |
| 3 | 0x46800 | 0x47C00 | 0x6D7E | 1175 | 0D–22 | 35FC…3CA3 (16 шт.) |
| 4 | 0x4EA00 | 0x4F200 | 0x4415 | 423 | 23–30 | 35FC…3A33 (14 шт.) |

Все модули грузятся **контигерно от 0x35FC0** (зона 0x35FC0..0x3BDB3 ≈ 24 КБ —
совпадает с нулевым зазором образа 0x35FB0..0x3CEE0; модули-«сиблинги» перекрываются
в памяти — классическое overlay-дерево, загрузка по требованию). Значения релокаций
модулей финальные (сегменты 0x35FC–0x3CA3, внешних ссылок на корень/DGROUP нет:
COMMON доступен через DS, RTL — прямыми far `lcall 1C7C:…`/`28E9:…`).
Прологов `55 8B EC` в пуле — 49 = числу селекторов. Строк в пуле нет — чистая математика
(FPU-байты D8–DD дают псевдо-кириллицу при наивном скане).

**11 сайтов int 3Fh** (полный дизасм входов — `reverse_data/_opava_ovl_dis.txt`,
скрипт `_tools/opava_ovl_dis.py`; аргументы — far-указатели на COMMON
сегментов 0x4470/0x41B9/0x418B/0x446E/0x43CF/0x3CD4 и DS-буферы):

| сайт | sel/file | entry | роль (по коду входа) |
|---|---|---|---|
| 0x013D (f77_main) | 1/1 | 0 | init: обнуление COMMON через указатели [0x32DA/0x32DC/0x32DE], default 1000; **открывает scmva.dat** (`lcall 370D:0xE` = сел 2), строит структуры чтения |
| 0x0678 | 0x26/4 | 0xA | геттер 4 слов из [0xC16..0xC1C] (retf 8); соседний entry-0 — целочисленная адресная арифметика массивов |
| 0x07F0 | 9/1 | 5 | печать строк протокола (RTL write 1C7C:0EC2, юнит 0x382), инкремент счётчика записей |
| 0x086D | 6/1 | 3 | обнуление буфера 0x438 слов + динамические массивы (1C7C:3DA4/3DB0 = alloc/realloc, `lea bx,[0x3338]`, `[0x5C5C]`) |
| 0x0B31 | 7/1 | 3 | заполнение матрицы с шагом 4 байта через seg [0x33A4] — накопление нормальных уравнений МНК (перед входом — плотный FPU-код) |
| 0x0B83 | 5/1 | 5 | копирует `'vnb.gl'` (DS:0x368) → буфер 0x5B9C; печать **глобального** разложения |
| 0x0BDC | 8/1 | 4 | копирует `'vnb.sk'` (DS:0x37C) → буфер 0x5D28; печать **СКВ по спектральному интервалу, полю и зрачку** |
| 0x0C3F | 3/1 | 0xA | адресная арифметика массивов (элементы 4 байта), [0x5A50]=N+1 |
| 0x0CA8 | 4/1 | 4 | подготовка аргументов ([0x5B12], [0x5AA6]=N+1, [0x5AC4]) + печать (юнит 0x2E0) |
| 0x2580 | 0x1A/3 | 6 | работа с `F(x,y)yxZERN.DAT`: [0x65C4]=1, вызовы 1C7C:3E14/3DD4/3FD2, COMMON [0x3484] — **сохранение/чтение карты волнового фронта** |
| 0x2768 | 0x0A/2 | 0 | большой ввод: 28E9:0x18C с [0x5FB2]/[0x5FBC], 28E9:0xB67 — **чтение файлов данных волнового анализа** |

Внутри file1 оверлеи зовут друг друга прямыми far-call по сегментам загрузки
(напр. `lcall 370D:0xE`) — корректно, т.к. модуль грузится целиком.

## §6. x87, датчики, DAT-файлы

**x87**: та же шина int 34h–3Dh (INT# = 34h + (ESC − D8h), далее байты эмулируемой
инструкции) — внешний резидентный эмулятор OPAL.COM обязателен (REVERSE_TSR §6).
Гвард — int 90h + строка «This program must be run under OPAL-PC» (§4).

**DAT-файлы** (hex — `_tools/opava_dat.py`):

- **VAFORUS.DAT** (3784, текст CP866) — «болванки» печатных форм протоколов VA.
  Секции `*<имя>` + текст формы + FORTRAN-формат: `*vnb.sf` (коэффициенты зонального
  разложения по пучкам: расфокусировка/сферическая/дисторсия/кома/астигматизм/прочие,
  марки `С x20…С x66`), `*pnuo.d` (пучки по MIN СК W dS′ / MIN СК R dS′), `*pnuo.c`
  (границы глубины резкости), `*pnui.d` (пучок/плоскость установки/СК W/dY′/dX′),
  `*vnb.gl` (глобальное разложение C x020…C x1111), `*vnb.sk` (СКВ по спектральному
  интервалу, полю и зрачку; −A без расфокусировки, −B без кривизны, −C без дисторсии).
  Имена секций = строки DGROUP; оверлеи sel5/sel8 подставляют их при печати (§5).
- **SCMVA.DAT** (28434, двоичный) — входной банк полихроматического анализа:
  word-маркер `0x814B` + поток 4-байтовых слов от смещения 2 (7108 f32; значения
  ~1e-4…1e-2 — весовые/спектральные коэффициенты). Структура периодична: записи
  по 65 f32 (260 байт) с внутренним маркером `0x8181` в слове 32; ненулевые прогоны
  48+15 значений; хвост — таблица 8-байтовых записей с монотонным полем 0x403E…0x4048
  (индекс/длина волны). Читается оверлеем file1 при инициализации (§5, сайт 0x013D).
  Парный файл SCMVP.DAT (24884) — для работы VP (OPALVP.EXE).
- **OPALOW.DAT** (2100, двоичный) — тот же маркер `0x814B` + 524 f32 малых значений
  (±0.001…0.25, чтение с off 2). В OPAVA строки «opalow» нет — файл принадлежит модулю
  OPALOW.EXE (REVERSE_TSR §1), включён в поставку общим банком; по формату — весовые
  коэффициенты той же серии, что SCMVA.
- Прочие из DGROUP: `ZERN.DAT` (карты волнового фронта F(x,y), сел 0x1A),
  `buffer.dat` (спул), `PROTOCOL.PRN` (печать через `file2prn.ini`).

## §8. Сверка с нативным портом (`analysis/*.py`)

Есть в порту:

- `zernike.py` — полиномы Цернике + Noll-нормировка, МНК-подгонка
  (`fit_zernike_coefficients`), карта волнового фронта (`compute_wavefront_map_2d`),
  хроматика по дискретным λ (`compute_zernike_chromatic`), глобальное разложение
  (`compute_global_zernike`, поле×λ×зрачок);
- `strehl.py` — Стрел (Марешаль + точный), σ волнового фронта;
- `aberrations.py` — кривые фокусировки/дефокусировки, пятна рассеяния.

Пробелы относительно OPAVA (кандидаты в волны 9+):

1. **Базис 28 членов с m≥0 до n=12** (пары §4) — в порте 15 терминов Noll (±m) до
   порядка 4; марки `C x IJ` в терминах хроматизм×радиус×азимут не введены.
2. **Ортогональные полиномы спектральной координаты** (полихроматическое разложение,
   ANALIZE.DOC §5.2; данные SCMVA.DAT) — в порте лишь перебор длин волн.
3. **ПНУ**: оптимизация дефокусировки раздельно по минимуму СК W и СК R
   (√(dX′²+dY′²)), индивидуальная/общая (среднее индивидуальных), границы глубины
   резкости по допускам СК W/СК R — в порте только MTF-кривая по дефокусировке.
4. **СКВ по полю** (пункт меню 3 / `*vnb.sk`) — нет аналога-функции.
5. Гистограммы коэффициентов с обнулением по DEL, 3D-отображение WDSP
   (модуль OPAL-PC), печать по формам VAFORUS — UI-уровень, в порте не требуется.

## §9. Остаточная неопределённость

- Точная семантика селекторов file3/file4 (16+14 шт.) — в корень OPAVA обращаются
  только 0x1A (сохранение карт) и 0x26 (геттер); остальные вызываются из самих
  оверлеев прямыми far-call (нужен скан пула по `9A`/`EA`).
- SCMVA.DAT:producer неизвестен из OPAVA (кандидаты — OPALOW.EXE/OPALO); точная
  схема записи 65×f32 (48+15+маркер 0x8181) требует чтения кода-писателя.
- Смещения сайтов >0x2580 (их 2 из 11) аннотированы по аргументам, но не по коду
  входа целиком.
