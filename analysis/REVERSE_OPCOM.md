# §21. REVERSE_OPCOM — OPAL.COM: резидент-командир пакета ОПАЛ-ПК

**Дата:** 2026-10-16 (волна 8/G1++, статанализ — DOSBox не запускался) · **Файл:** `extracted/opal_okb/OPAL.COM` (6775 б = 0x1A77) · **Источники:** `decomp_opalcom/` (Ghidra), `analysis/reverse_data/opalcom_{full,handler,rec}_disasm.txt`, `analysis/_tools/rec_dis16.py`, `scripts/_scratch_opcom.py`, §18 (REVERSE_TSR), §20 (REVERSE_G1), сырые байты файла.

## 21.0 Резюме

**OPAL.COM — не «TSR-сервис» в классическом смысле, а резидентный шелл-командир:** COM-процесс, который

1. ставит единственный перехват — **int 90h** (диспетчер 0x156E, 16 сервисов по таблице 0x115);
2. читает конфигурацию из env (`OPAL_WORK/OPAL_TEMP/OPAL_SAVE` — ставит OPAL.BAT);
3. открывает/создаёт **файл-архив OPAL.ARH** (таблица 128 слотов × {u32 offset, u16 size} + данные);
4. расшифровывает **каталог модулей OPAL.PSP** (собственный побайтовый шифр, 25 записей × 0x60);
5. грузит **OPAL5X5.EXE** (это ДАННЫЕ, 0x400 б конфигурации меню 5×5, не программа!) в CS:0x116B;
6. shrink'ается до **0x196 параграфов** и становится **родительским шеллом**: сам запускает модули пакета (OPALA, MENUOPAL, …) через DOS EXEC, поддерживая их файл-шиной int 90h.

Все программы пакета (OPALA, MENUOPAL, OPALSHOW, METAPRN, OPALCALC…) при старте проверяют `getvec(90h) ≠ 0000:0000`; без резидента — «This program must be run under OPAL-PC» (§18.7). Авторская подпись в файле: **`(C) Paul McHacker`** (0x103). Гипотеза int 2Fh опровергнута ранее (§18); int 90h — единственный перехват OPAL.COM.

**Верхняя строка досье-загадки:** статический поток init'а содержит «холостой» первый EXEC и блок выхода с восстановлением вектора (§21.5) — но стенд §20 наблюдал резидент живым. Это главный открытый вопрос (§21.12).

## 21.1 Адресные конвенции артефактов (обязательно к прочтению)

Три набора артефактов используют ТРИ разных базы. Каноническая конвенция этого досье — **«disasm» = CS-относительное смещение = file_offset + 0x100** (COM грузится по PSP:0100; все три `opalcom_*_disasm.txt` и ячейки вида `[0x143]` — в ней).

| Артефакт | Формула → disasm | Пример: диспетчер |
|---|---|---|
| `opalcom_{full,handler,rec}_disasm.txt` | тождественно | 0x156E |
| decomp `decomp_opalcom/0100_XXXX_*.c` | disasm = XXXX + 0x100 | 0100:146B → 0x156B |
| decomp `decomp_opalcom/0000_XXXX_*.c` | disasm = XXXX − 0x1000 | 0000:2967 → 0x1967 |

Проверено сходимостью байтов: 0x163A («push dx; push es; push bx; call 0x186F…») лежит в файле на 0x153A ✓; thunk 0100:146B (jmp 0x1967) ↔ 0000:2967 ✓; строка «`        .EXE`» (13 б) на disasm 0x1B6A ✓. Ghidra-проект прошлого агента содержал два перекрывающихся блока — отсюда двойные имена функций (например, FUN_0000_1100 и FUN_0000_2967/29B7 — три декомпиляции одного init-хвоста; FUN_0000_1100 дополнительно засорена мусорной «декомпиляцией» D/P/F-филллера как кода — ей доверять нельзя).

## 21.3 Инсталляция: init на 0x1A67 (реконструкция по rec_disasm)

```
0x1A67: cld; mov sp,0x100                 ; мини-стек поверх PSP (init неглубокий)
0x1A6B: ax=3590h; int21                   ; getvec(90h)
0x1A70: [0x13D]=ES; [0x13B]=BX            ; сохранить старый вектор
0x1A7A: ax=2590h; dx=0x156E; int21        ; ПЕРЕХВАТ: int 90h := CS:0x156E
0x1A82: [0x143]=0; 0x1A88: [0x16F]=CS
0x1A8D: si=0x295("OPAL_SAVE"), cl=4 → env_search(0x1A1B)   ; запись конфига №4
0x1A95: es=[2Ch]; bl=4 → 0x1822          ; копия значения в запись №4
0x1A9E: дописать "OPAL.ARH"/"\OPAL.ARH" в конец значения (проверка :/\/\0 по [di-1])
         → запись №4 = полный путь к OPAL.ARH
0x1AB9: dx=0x295 → 0x195B: AH=5Bh CREATE NEW (CX=0x2000) OPAL.ARH
         если создан:  zero 0x300 б таблицы имён (0x329) + записать её в файл;
         если существует: AH=3D02 open R/W → read 0x300 б → 0x329   (хэндл → [0x13F])
0x1AC3: si=0x2DE, cl=5 → env_search (имя-заполнитель DDDD → фейл → [0x2DE]=0)
0x1ACB: es=env; add di,4                 ; di → хвост env = ПОЛНЫЙ ПУТЬ OPAL.COM (DOS 3+)
0x1AD4: bl=5 → 0x1822                    ; запись №5 = путь OPAL.COM
0x1AD7: std; скан назад 0x49 б до '\'    ; → позиция "OPAL.COM"
0x1AE1: push di; дописать "OPAL.PSP\0" (9 б, si=0x156) в запись №5
0x1AEB: dx=0x2DE → 0x19AD: AH=3D00 open OPAL.PSP; [0x141]=hdl
         read 2 б → [0x629] (=25); read 25×0x60 → 0x62B; ДЕШИФРОВКА на месте (§21.6)
0x1AFB: pop di; дописать "OPAL5X5.EXE" (11 б, si=0x14A) вместо "OPAL.PSP"
0x1B05: AH=3D00 open OPAL5X5.EXE; read 0x400 б → CS:0x116B (конфиг меню 5×5!)
0x1B24–0x1B41: env_search ×4: 0x171→cl=0 (OPAL_WORK), 0x1BA→cl=1 (OPAL_TEMP),
         0x203→cl=2 (OPAL_SAVE), 0x24C→cl=3 (D-DDD-заглушка → запись обнуляется)
0x1B44: es=env; add di,4 (→ путь OPAL.COM в хвосте env); bl=3 → 0x1822  ; запись №3 = путь
0x1B50: std; скан '\' назад; [0x327]=di; дописать "        .EXE" (13 б, si=0x1B6A)
         → запись №3 = ШАБЛОН ЗАПУСКА "C:\DIR\        .EXE" (имя модуля пишется в [0x327])
0x1B67: jmp 0x191B — ШЕЛЛ (§21.5)
```

Формат env-хвоста (DOS 3.x): `[строки][00][00][01 00]["C:\...\OPAL.COM"][00]` — `add di,4` перепрыгивает `00 00 01 00` точно на путь. `env_search` (0x1A1B) сканирует блок окружения по байту, сравнивая шаблон DS:SI; байт **0x0A в шаблоне = wildcard/конец-префикса** (0x1A34: `cmp [bx+si],0x0A; je found`); после совпадения ищет `=`, пропускает пробелы, значение копирует в запись BL. Имена переменных обязаны быть ВЕРХНИМ регистром — DOS `SET` сам переводит имена в верхний регистр (`set opal_work=…` в OPAL.BAT даёт `OPAL_WORK=…`) ✓.

**Замечание:** расшифрованный каталог остаётся в памяти; OPAL.ARH открывается R/W и его 0x300-байтная голова (таблица имён) при завершении шелла записывается назад (0x1881).

## 21.4 Шина int 90h: диспетчер и 16 сервисов

**Диспетчер 0x156E** (единственный код на вершине прерывания):

```asm
0x156E: push si/di/ds; push cs; pop ds; sti
        mov [0x143],0            ; код возврата
        xor ah,ah; mov si,ax     ; SI := AL
        call word ptr [si+0x115] ; ТАБЛИЦА, индекс = ЗНАЧЕНИЮ AL (байт!)
0x1583: mov ax,cs:[0x143]        ; AX → вызывающему (через iret)
        pop ds/di/si; iret
```

**Индексация байтовая** (AL=1 попадает на «середину» слова) → валидны только **чётные AL = 0,2,…,0x1E**. Таблица 0x115 (16 слов):

| AL | Адрес | Функция (по дизасму) |
|---|---|---|
| 0x00 | 0x163A | **Чтение блока из ARH**: BX = индекс таблицы имён; валидация 0x186F (offset≠0); lseek(0x4200) на {u32 off}; read(0x1851) u16 len байт → DS:DX клиента |
| 0x02 | 0x166F | **Запись/расширение в ARH**: поиск по 5-байт ключу ES:DI (0x18A7); если CX:DX=−1:−1 → lseek END (запрос размера); иначе seek+**write** (0x1867); обновляет {off,len} в таблице имён ([bx],[bx+2],[bx+4]) |
| 0x04 | 0x15F4 | **Обновить запись каталога**: по ключу ES:DI; копирует 0x60 б **от клиента в каталог** (запись модульного статуса) |
| 0x06 | 0x15D9 | **Прочитать запись каталога**: по ключу ES:DI; 0x60 б каталога → ES:DI клиента |
| 0x08 | 0x172B | **Запустить модуль по 5-байт ключу** ES:DI (найти 0x18A7 → EXEC-цикл §21.5) |
| 0x0A | 0x17A3 | **Запустить модуль по индексу** BL (валидация BL<25) + ключ ES:DI; также — продолжение цикла после выхода потомка |
| 0x0C | 0x17FF | **Взять exit-код потомка**: BX ← [0x147] |
| 0x0E | 0x1804 | **Взять конфиг-запись BL** → ES:DI клиента (strlen ≤ 0x64, 0x18F6: адрес = 0x171+0x49*BL) |
| 0x10 | 0x16BD | **Запустить по 8-симв имени** DS:DX: имя → [0x327] (шаблон), затем EXEC как 0x08 |
| 0x12 | 0x17E8 | **Выбрать следующий модуль по ключу** ES:DI (только если [0x149]=1): [0x145] ← найденный индекс |
| 0x14 | 0x15CF | **Проверить ключ** ES:DI (есть ли в каталоге; CF=нет) |
| 0x16 | 0x1822 | **Записать конфиг-запись BL** ← строка ES:DI (то же, чем пользуется init) |
| 0x18 | 0x17D6 | **Выбрать следующий модуль по индексу** BL (если [0x149]=1; BL<25) |
| 0x1A | 0x162A | **Обнулить слот BX** таблицы имён (6 б по 0x329+6*BX) |
| 0x1C | 0x17BB | **Прочитать запись каталога №BL** (без ключа): 0x60 б → ES:DI |
| 0x1E | 0x15D3 | **Адрес данных резидента**: DX:BX ← CS:0x116B (конфиг меню 5×5 из OPAL5X5.EXE) |

Семафоры: [0x149]=1 нужен сервисам выбора (0x12/0x18) — пока шелл не вошёл в цикл, выбор запрещён. 0x1900 (после каждого int21 в хелперах) пишет AX в [0x143] при CF — «последняя ошибка DOS».

**Клиенты шины** (по §18 + свежие находки): OPALA — обёртки `lin 0x2E611/0x2E634` с AL=2 и AL=0x1C; OPALSHOW — обёртка `FUN_15f4_0069` (проверка вектора + `swi(0x90)`), `FUN_1089_0106` использует конфиг; OPALCALC (0x13422), METAPRN/METAPRNO (по 4 сайта). Гвард-паттерн у всех один:

```asm
mov ah,35h; mov al,90h; int 21h   ; getvec
cmp es,bx (или mov ax,es; cmp ax,bx); je FAIL   ; 0000:0000 → резидента нет
…int 90h…
FAIL: "\r\nThis program must be run under OPAL-PC\r\n\a"; exit(255)
```

## 21.5 Шелл-цикл EXEC и загадка первого запуска

**Блок входа в шелл (0x191B):**

```asm
0x191B: ah=4Ah; bx=0x196B>>4=0x196; int21   ; shrink памяти до 0x196 параграфов
        jb 0x192D                            ; (провал — сразу к выходу)
0x1928: bl=0; call 0x17A3                    ; «запустить каталог[0]»
0x192D: [0x149]=1                            ; резидент готов
0x1932: call 0x1881                          ; flush: seek(ARH,0) + WRITE 0x300 б таблицы имён + close
0x1935: call 0x1946                          ; drain: сброс [0x143] (петля при [0x149]≠1)
0x1938: lds dx,[0x13B]; ax=2590h; int21      ; ВОССТАНОВИТЬ старый int 90h
0x1941: ax=4C00h; int21                      ; ЗАВЕРШИТЬ процесс
```

**EXEC-цикл (0x172B→0x17A3):** найти по ключу → имя из записи+4 (8 б) → [0x327] (шаблон «…\        .EXE») → **0x190E: сброс Ins-бита** `and byte es:[0x417],0x7F` → `ax=4B00h; ds:dx=0x24C (шаблон пути); es:bx=0x16B (EPB)`; стек сохранить ([0x137]/[0x139]); int21; стек восстановить; `[0x143]=0`; **ah=4Dh** → [0x147]; `bl=[0x145]`; если bl≠0xFE и bl<25 → **следующий EXEC** (jmp 0x172B); иначе ret → 0x192D (выход шелла). Потомок «выбирает» следующий модуль сервисами 0x12/0x18; ничего не выбрал (bl=0x1E file-default ≥25) → шелл завершает работу, восстанавливает int 90h и умирает — **корректный анинсталл**.

**⚠ Проблема первого запуска (главный открытый вопрос).** Вызов 0x1928 идёт с BL=0, но ES:DI в этот момент указывает в хвост шаблона пути (DI=[0x327]+13 — байты после «`        .EXE`», т.е. мусор/D-филлер), а 0x172B всегда делает `call 0x18A7` — **поиск по 5-байт ключу ES:DI** → ни один ключ каталога («SHOWO»…) с мусором не совпадает → CF → мгновенный ret → по статике шелл сразу выходит через 0x192D–0x1944, снимая int 90h. **Но стенд §20 наблюдал резидент живым** (OPALA стартовала, «Program: OPAL», заставка; батч «застревал» — т.е. блокирующий EXEC потомка был!). Либо в трассировке ES/DI через init+int21(4Ah) есть неучтённый нюанс, либо на стенде цепочка дошла до EXEC иначе. Требуется runtime-зонд (§21.12, п.1). Отметим: catálogo[0] = **OPALSHOW** («SHOWO», BGI-графика, экран «Enter password:» с контактами ИТМО — см. §21.6 и `analysis/reverse_data/opalshow_cyr.txt`) — именно он и есть «заставка, ждущая ввода» из §20 (ENTER/SPACE/ESC не подошли, потому что это **ввод пароля**).

## 21.6 OPAL.PSP — зашифрованный каталог модулей (= меню)

Файл 2402 б = word N (=25 = 0x19) + 25×0x60. Дешифровка на месте (0x19E8–0x1A18), по записи:

```
key = entry[0]                       ; 1-й байт записи — ключ шифра (в файле = ASCII-код!)
lodsb/stosb: ключ переписывается как есть
for i in 1..0x5F:
    c = entry[i] ^ key
    c = ror8(c, key & 0x0F)          ; x86 ROR byte: счётчик mod 8
    c ^= 0x5A
    c -= (key ^ 0x53)
    c ^= 0xC5
    entry[i] = c; key -= 7           ; ключ деградирует на 7 каждый байт
```

Формат записи (0x60): `+0` 5-байт **командный ключ** (4 знака + 5-й байт, совпадающий с 1-м символом имени — упаковка с перекрытием на +4!); `+4` 8-симв **имя EXE**; `+0xC` описание (CP866); `+0x2E` word флаги; `+0x34` 4×FE — разделитель; `+0x38/+0x40/+0x48` три 4-симв **расширения файлов** модуля (обычно заглушки EXT0/EXT1/EXT2; METAPRN→`LIB`, OPALA→`GRIN`); `+0x50` 1-байт класс (S/R/L/I/A/P/C/E/O).

## 21.7 OPAL.ARH — архив данных пакета

Формат: **0x300 б голова = 128 слотов × {u32 offset, u16 size}** (= таблица имён резидента 0x329), дальше данные. Файл 11990 б (0x2ED6), занято 10 слотов (дамп `_scratch_opcom.py`):

| слот | off | size | начало данных (интерпретация) |
|---|---|---|---|
| 0 | 0x0FD0 | 604 | 01 00 00 00 + пробелы — заголовок системы |
| 1 | 0x122C | 1036 | 02 00 01 00 17 00 50 00… — структурированные записи |
| 2 | 0x1638 | 48 | «`8е 8ф-04/40 v=-1`» — строка стекла/версии (CP866) |
| 3 | 0x1668 | 4200 | 16 00 00 00 01 00… — большой блок (поверхности?) |
| 4 | 0x26D0 | 1044 | нули |
| 5 | 0x2AE4 | 184 | 04 00… + REAL*8 (00 00 00 80 3F…) |
| 6 | 0x2BCC | 640 | паттерн EC 78 61 AD… (шифрованное/упакованное) |
| 8 | 0x2B9C | 48 | четыре REAL*8 = 1.0 (00 00 80 3F ×4) |
| 10 | 0x2E4C | 120 | REAL*8-пары (44 1D 77 1A 0C 0B 53 40…) |
| 41 | 0x2EC4 | 18 | **«ST11RP03\0»** — имя сохранённой оптической системы |

Исполнимых файлов в ARH нет (§18.7) — это хранилище данных, к которому OPALA обращается сервисами AL=0/AL=2 по индексу слота (BX).

## 21.8 OPAL5X5.EXE — не программа

0x400 б без MZ (§18.1), открывается init'ом как **данные** (0x1B05–0x1B21) и читается в CS:0x116B — конфигурация раскладки меню 5×5; клиентам отдаётся сервисом **AL=0x1E** (DX:BX=CS:0x116B). Название файла прописано в OPAL.COM на 0x14A.

## 21.9 Как клиенты детектят резидента

Только **getvec(int 90h) ≠ 0000:0000** — ни сигнатур в RAM, ни env-переменных, ни int 2Fh. Обёртка OPALA (lin 0x2E611/0x2E634, §18.7) и обёртка OPALSHOW (`decomp_opalshow/15f4_0069`) идентичны: `mov ax,es; cmp ax,bx; je FAIL` — вектор пуст ⟺ ES==BX==0. Отдельная «сигнатура» не нужна: 0x156E валиден, пока жив процесс-шелл. Сервис 0x1E (CS:0x116B) даёт данные меню; [0x16F]=CS — самоссылка в EPB.

## 21.10 KEYRUS.COM и взаимодействие с OPAL.COM

KEYRUS.COM (22351 б, «KEYRUS beta16 (c) 1991–1994 Gurtjak») — независимый резидент-русификатор: клавиатурные вектора int 09/10/16/1F/08/44 (§18.6), шрифт CP866 через int 1F. Загружается в OPAL.BAT/START.BAT **до** OPAL.COM — порядок неважен для механики (перехватов не пересекаются: KEYRUS — BIOS/DOS-клавиатура, OPAL.COM — int 90h). Единственная точка касания: **0x190E перед каждым EXEC сбрасывает бит Insert в BDA 0x417** (`and es:[0x417],0x7F`) — чтобы «залипший» Ins (например, после переключения раскладки KEYRUS) не утащился в потомка. Кириллица строк OPALSHOW/OPALA (CP866) рендерится шрифтом KEYRUS.

## 21.12 Открытые вопросы → план DOSBox-стенда (следующая волна)

1. **Первый запуск модуля (§21.5).** Поставить брейкпоинт (DOSBox EML: `CS:0x172B` после старта opal.com) и сдампить ES:DI перед `call 0x18A7`; трассировать `int 21h AX=4B00h` (кто и с каким path). Варианты: (а) DI в реальном рантайме указывает на валидный ключ; (б) resize 4Ah на стенде ведёт себя иначе; (в) часть потока, которую статика теряет (SMC?). От ответа зависит рецепт «золотого запуска».
2. **«Enter password:»** OPALSHOW (`opalshow_cyr.txt` 0x960E) — найти ожидаемую строку (декомп OPALSHOW: функции 15F4/1089-серии; вероятно, пароль = «OPAL» или из OPAL5X5-данных) — иначе заставку не пройти (§20: ENTER/SPACE/ESC не годятся).
3. **Композитный хендлер 0x158B–0x15CE** (AH=68h = commit DOS 3.3+, буфер 0x2F4 б) — до конца не разобран: точная семантика кэширования ARH.
4. **Расширения EXT0/EXT1/EXT2 и байт-класс** в записях каталога (+0x38..+0x50) — как их читают модули (сервисы 0x04/0x06 пишут/читают целые записи — кто их меняет?).
5. **Слоты ARH** 0x2E4C+ (REAL*8) и слот 6 (0x2BCC, паттерн) — сопоставить с форматами OPALA (GLM/GLS-структуры, см. REVERSE_MAP).
6. **[0x16B] EPB**: env=0 (наследование), cmdtail=CS:0x169 («\r») — проверить, не подменяет ли какой-то сервис cmdtail (аргументы модулям?).
7. **Что реально рисует OPALSHOW** (BGI EGAVGA из OPALPCX?) и как выглядит меню MENUOPAL (скрины menu*.png/w*.png есть, но не OCR-нуты — нужен win_ocr.ps1 прогон).

## Резюме (для быстрого прочтения)

- OPAL.COM = резидентный шелл-«командир»: **int 90h — единственный перехват**, диспетчер 0x156E, 16 чётных сервисов из таблицы 0x115 (файл-шина ARH, каталог, EXEC, конфиг, выбор модуля).
- Инсталляция (init 0x1A67): getvec/setvec 90h → env OPAL_WORK/TEMP/SAVE (таблица 0x171, 6×0x49) → OPAL.ARH (голова 0x300 = 128×{u32 off,u16 len}) → **OPAL.PSP дешифрован** (каталог 25 модулей × 0x60, ключ=1-й байт, ror/xor/sub-цепочка) → OPAL5X5.EXE (данные!) → CS:0x116B → шаблон пути «…\        .EXE» в записи №3.
- Шелл: shrink 0x196 пара → EXEC-цикл 0x172B/0x17A3 (модули = потомки; следующий выбирается сервисами 0x12/0x18); выход — восстановление int 90h + 4C00 (чистый анинсталл).
- Каталог = **меню 5×5 из 25 модулей** полностью расшифровано (OPALA «Габариты и аберрации», OPAVA, OPAAIG/AI/DT, OPALLAP, OPALTRAN, OPALO/OW/OV, OPALTOL, KATALOG, OPALCALC, OPALEDIT, DOS=выход, OPALSHOW=заставка с паролем). Контакты разработчиков: ИТМО/ЛИФМО, Rodionov.
- Детект клиентами: getvec(90)≠0:0 → иначе «must be run under OPAL-PC». KEYRUS — независимый русификатор; пересечение с OPAL.COM только в сбросе Ins-бита (0x190E) перед каждым EXEC.
- Открытые вопросы: холостой первый EXEC (п.1), пароль OPALSHOW, хендлер 0x158B. Готово §21.0–21.12 (все заявленные разделы ТЗ закрыты, кроме runtime-проверки первого запуска — статикой она не закрывается).
