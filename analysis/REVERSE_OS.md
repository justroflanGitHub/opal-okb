# REVERSE_OS — OPALOS.EXE / GENIZE.EXE (волна 9/C3)

Разведка двух оставшихся крупных EXE пакета ОПАЛ-ПК. Методика —
[REVERSE_UNP.md](REVERSE_UNP.md) (EXEPACK + Ghidra real-mode), протокол
int 3Fh — [REVERSE_TSR.md](REVERSE_TSR.md) §5, братские оптимизаторы —
[REVERSE_OPALO.md](REVERSE_OPALO.md) (OPALO/OPALOW), словарь задачи —
[REVERSE_OPTDOC.md](REVERSE_OPTDOC.md).

- Объекты: `extracted/opal_okb/OPALOS.EXE` (389556 Б), `GENIZE.EXE` (196390 Б)
- Инструменты: `_tools/os_map.py` (карта), `_tools/os_int3f.py` (таблицы
  селекторов), `_tools/os_ovl.py` (chain в EXE-хвосте), `_tools/os_build.py`
  (merged-образ + seeds), `_tools/exepack.py` (run_stub)
- Данные: `reverse_data/OPALOS_{unp,ovl1..4,full}.bin`,
  `GENIZE_{full,unp}.bin`, `_oplos_seeds.txt` (126),
  `_OPALOS_strings.txt` (4761), `_GENIZE_strings.txt` (2160)
- Декомпилы: `C:\tools\rea-out\decomp_opalos\` (1185 файлов, 8 отказов),
  `decomp_genize\` (668), списки `_oplos_funcs.txt` / `_genize_funcs.txt`

## 1. Вердикт

**OPALOS.EXE = работа «OPS» — интерактивный оптимизатор аберраций
ПРОСТРАНСТВЕННЫХ систем** (децентрировки/наклоны поверхностей и блоков,
сдвиги диафрагмы/объекта/изображения). Гипотеза ТЗ «оптимизационный
синтез» подтверждена наполовину: это ДА оптимизатор, но «синтез»
ограничен подбором схемы через меню `Scheme` и случайный старт `Random`
(никакого автогенератора структур в образе нет). Доказательства:

1. Титул встроенной справки `OPS.OH` (0x9C6E Б):
   **«Описание марок дла оптимизации аберраций пространственных систем»**
   (sic, опечатка «дла») — OPALO/OPALOW аналогично описывают свои наборы
   марок (см. REVERSE_OPALO §1).
2. Словарь **71 марки OPS.TRA** в данных @0x688a0 (§5) — уникальные
   пространственные марки SXB/SYB/SZB (сдвиг блока), TXB/TYB/TZB
   (наклон блока), ARB, SOX..TDZ (сдвиги/наклоны объекта/изображения/
   диафрагмы), NYHR..NXHL (градиентные среды), DFOC/AST/ZM/ZS/W.
3. Строка выбора метода @0x65392:
   `norm=/  LM  DLSM-3 DLSM-2 DLSM-1 OBM SDM+LSM LSM SDM` — семь методов
   + нормировка; строка режима @0x66004: `-Penalty Merit Step Cycle`
   (управляющие величины итерационного процесса).
4. Стартовая форма задачи `extracted/opal_okb/FORM.OPS` (112 Б):
   `! -------------- SPACE -------------- !` / `PAR(*) = C;` /
   `EQF(*) = V1,V2;` / `MF(*) = DX,DY;` — тот же язык PAR/EQF/MF, что у
   OPT/OPW (FORM.OPT/FORM.OPW), но с пространственными марками.
5. Работает только под резидентом: `This program must be run under
   OPAL-PC` @0x6878a (у GENIZE/OPALLAP строка продублирована дважды).

**GENIZE.EXE = генератор тест-объектов (изображений) для
дифракционного анализа** — интерактивный редактор мишеней и движок
расчёта их изображения в квадрате N×N. Гипотеза ТЗ «генератор исходных
структур (дублет/триплет/руссар)» СНЯТА: линзовых структур программа не
знает (это к LIB/*.LBO); GENIZE = GENerate IMAGE. Доказательства:

1. Типы объектов (cp866-строки 0x2fdc2..0x30e68): прямоугольники
   (X0 Y0 PX PY, интенсивность, угол fi), треугольники (X0 Y0 S0 H0),
   правильные многоугольники (X Y, число сторон), круги (X0 Y0 R0),
   шпалы-миры (пары X Y, угол, масштаб «мкм»), буквы А/E/W, знаки
   `:+%#`, общий фон; счётчики «Общее количество тест-объектов»,
   «Максимальный размер тест-объекта».
2. Правило масштабирования задано явно: «МК ИЗОБРАЖЕНИЕ ОБЪЕКТОВ В
   КВАДРАТЕ РАЗМЕРОМ─» @0x30fa4 — все объекты нормируются в общий
   квадрат (сетка N×N); вид отображения: Черно-белое / Изофоты /
   Изофоты log (@0x30f1d `log`).
3. Файлы: читает формы `.FRM` («Не найден файл .FRM»; в пакете есть
   TANK.FRM/TREE.FRM — см. REVERSE_OPALO §7) и «НЕТ ФАЙЛА С ОПФ»;
   пишет `bpf100` (бинарный формат 100, изображение) и `bpf300`
   (@0x30797), временные `HAR.TMP`, `MTF.TMP`, протокол `PROTOCOL.PRN`.
4. Строка @0x2feef `PSF EF LSF EDGE BAR MTF SF` — режимы свёртки/
   анализа: ФРТ, EDGE, BAR (шпала), ЧКХ; справка `GINIZ.OH` (sic),
   `MONITOR.OH`; меню `Command→ Menu View Edit Calc Help Comm` @0x308ba.

Связка OPALOS↔GENIZE: OPALOS читает `GFILE.TMP` (три упоминания
@0x65028/0x65033/0x6504c, диагностика `ERROR IN G-FILE !!`, `SQRT in
IAVPLD2`) и имеет trace-точки GTIDIA — при оптимизации пространственных
систем используется изображение тест-объекта (G-файл) как источник
критериев (DIA-подобная оценка от протяжённого объекта). GENIZE —
редактор/генератор этих G-файлов (формат bpf100).

## 2. OPALOS: EXEPACK и оверлеи

EXEPACK (методика REVERSE_UNP §1): OPALOS CS0:IP0 = **0x2E62:0x6271**,
после run_stub (PSP=0xFFF0, load-seg 0) корневой образ — 0x6FA60 Б.
Дальше в EXE-хвосте цепочка из 4 mini-MZ оверлей-юнитов (os_ovl.py,
модель opalo_ovl.parse_chain; релоки хранят конечные сегменты).

Вход 0x2E62:0x6271 ставит **int 3Fh := 0x2E62:0x612D** (Overlay Manager
FORTRAN 5.0), DS := 0x63D0 (DGROUP, имя `opalos.exe` @ds:0x3F35) и
ljmp 0x2E62:0x43D0 (RTL-startup). Отличие от OPALA (REVERSE_TSR §5):
payload трамплина **3 байта** `CD 3F <sel> <off16>` (у OPALA — 5).
Обработчик (как у OPALLAP): word[sel] @ds:0x3DA4 = сегмент входа,
byte[sel] @ds:0x3EA2 = № юнита; селекторов 127 (0-й пустышка, живых
126); юниты 1..4 имеют 45/48/11/22 входов; пул один на всех:
**0x4AB4:0000..0x599BF** (в статике нули). Юниты грузятся с диска
целиком в пул при смене юнита (single load pool).

Схема вызова из корня (дизассм 0x3DED8, хвост RTL2):

```
8d46b0  lea ax,[bp-0x50]      ; буфер формы
16 50   push ss; push ax
b80423  mov ax,0x2304         ; ds:0x2304 = ' -Penalty Merit Step Cycle '
1e 50   push ds; push ax
8d46fc  lea ax,[bp-4] ...
cd3f 23 0200                  ; INT 3Fh sel=0x23 off=0x0200 -> unit-1
```

— корневой драйвер передаёт форму «Penalty/Merit/Step/Cycle» юниту-1
(селектор 0x23 → сегмент входа 0x5568): управляющая панель итераций
живёт в оверлее, корень только координирует.

| диапазон | размер | содержимое |
|---|---|---|
| 0x00000..0x013C0 | 0x13C0 | код main-модуля (main @0000:0000 → int 3Fh sel 0x16) |
| 0x013C0..0x20612 | — | нули/BSS корня |
| 0x20612..0x2E620 | — | RTL1 (сегмент 0x2A31) |
| 0x2E620..0x3E620 | — | RTL2 (0x2E62, ~840 far-ссылок); хвост 0x3D000+ — драйверные функции корня (см. §2) |
| 0x3E620..0x4AB33 | — | нули + рудименты |
| 0x4AB33..0x599CE | 0xEE9B | пул юнитов (нули в статике); юнит-1 собирается сюда |
| 0x599CE..0x63D00 | — | данные приложения: trace-строки 0x61482..0x61E88 (§6), список MARK 0x646A6, имена спавнов 0x64D2C.., GFILE.TMP 0x65028, меню 0x65316, методы 0x65392, Merit 0x66004 |
| 0x63D00..0x6FA60 | 0xBD60 | DGROUP (0x63D0): таблицы селекторов @0x67AA4 (word) / 0x67BA2 (byte), словарь 71 марки @0x688A0, проверка резидента @0x6878A |
| 0x70000..0x7EE7F | 0xEE7F | юнит-2 (fake-база 0x7000) |
| 0x80000..0x85199 | 0x5199 | юнит-3 (0x8000) |
| 0x86000..0x8FFB4 | 0x9FB4 | юнит-4 (0x8600) |

Юнит-1 в merged-образе лежит на РЕАЛЬНОМ месте (0x4AB4:0, размер
0xCA04); юниты 2..4 перелинкованы на фиктивные базы 0x7000/0x8000/
0x8600 (os_build.py, как opallap_build.py). Ghidra-блоки: R0..R6 по
0x10000 + OV2/OV3/OV4; seeds = входы из таблиц селекторов (126) —
`BuildOpalos.java`. Итого 1183 функции, x87-эмуляция INT 34h..3Dh (та
же, что в OPALO — REVERSE_OPALO §3).

## 4. GENIZE: EXEPACK без оверлеев

CS0:IP0 = **0x2032:0x3860**; после распаковки одиночный образ
0x36690 Б (222864), оверлеев и int 3Fh НЕТ (проверено os_int3f.py —
таблиц нет, `CD 3F` в коде отсутствует). Карта:

| диапазон | содержимое |
|---|---|
| 0x00000..~0x1B790 | код приложения, сегменты 0000 (main @0000:0000: `55 8B EC … lcall 0x203E:0x4CC0`; драйвер FUN_0000_087c, 8871 Б; растеризаторы; x87-кернелы FUN_0000_6C33/F869) и 1000 (в т.ч. FUN_1000_B290 — 18-аргументный вычислитель) |
| ~0x1B790..0x2B554 | RTL FORTRAN (модули 0x1B79, 0x203E; Ghidra находит внутри 428 функций — служебные RTL-точки) |
| 0x2B554..0x30000 | данные/BSS: матрица изображения и буферы (MS Run-Time Library ©1990 @0x30748 — уже в блоке строк) |
| 0x30000..0x36690 | строки cp866 (меню объектов, диагностика), bpf100/bpf300, GINIZ.OH, .FRM |

Ghidra-блоки G0..G3 (`BuildGenize.java`), 668 функций. GENIZE —
единственная работа пакета с РУССКИМ UI в самом EXE (у OPALO/OPALOW
весь текст вынесен в .OH; OPALLAP — смесь).

## 5. Словарь OPS.TRA — 71 марка

Строка @0x688a0 — токены фиксированной ширины 4 байта (имя+паддинг),
после неё пробелы (int32-номеров, как в OPALOW, здесь НЕТ). Непосредственно
перед строкой — пул вещественных литералов FORTRAN (float64, смещения
0x6882C..0x68884): 2^-15=3.05e-5 (порог сходимости?), -1, 1, 2, 8, 3,
6, 4, 0.5 — малые целые/степени двойки, вероятные веса и коэффициенты
демпфирования методов. Полный список марок:

```
C   ES  CA  CHL CHR WLH CH  SZ  D   N   DNR CN  SO  SI  CT
NYHR NYHL NXHR NXHL CHA SX  SY  SXB SYB SZB TX  TY  TZ
TXB TYB TZB ARB SOX SOY SOZ TOX TOY TOZ SIX SIY SIZ
TIX TIY TIZ SDX SDY SDZ TDX TDY TDZ AS  V1  V2  ANM
VT  VT' DISX DISY AST DFOC TS  DY  DX  ZM  ZS  W
DVLX DVLY XCEN YCEN ZCEN
```

Расшифровка (по OPT.TRA/OPW.OH и составу): C — кривизна; ES/CA —
асферика; CHL/CHR/WLH/CH — шпальные/полевые аберрации; SZ — толщина;
D — диаметр; N/DNR/CN — стекло (показатель/дисперсия/концентрация);
SO/SI — положение объекта/изображения; CT — центрировка;
NYHR/NYHL/NXHR/NXHL — градиенты N (неродн. среды, 4 квадранта);
CHA — цилиндричность; SX/SY — сдвиг поверхности (X,Y), SXB/SYB/SZB —
сдвиг БЛОКА (X,Y,Z); TX/TY/TZ и TXB/TYB/TZB — наклоны поверхности и
БЛОКА; ARB — поворот блока; SOX..TOZ — сдвиг/наклон объекта;
SIX..TIZ — изображения; SDX..TDZ — диафрагмы; AS — позиция апертурной
диафрагмы; V1/V2/VT/VT' — виньетирование; DISX/DISY — дисторсия;
AST — астигматизм; DFOC — дефокус; TS/DY/DX — поперечные аберрации;
ZM/ZS — зейделевы масштаб/сдвиг; W — волновая; DVLX/DVLY — отн.
дисторсия; XCEN/YCEN/ZCEN — центры (используются EQF-связями).

Язык задачи (FORM.OPS + OPS.OH): `PAR(*) = <марки>;` — оптимизируемые;
`EQF(*) = <марки>;` — уравнения связи; `MF(*) = <марки>;` — функция
качества; `pmin(j1..jk)`/`pmax(j1..jk)` — групповые границы; `RAYR=k`,
`RAYAZ=k` — лучевые условия (количество/азимуты лучей);
`PCRV(1)=1; PCVA(1-4)=0,90,180,270` — поворот координат пучка;
пример связи из OPS.OH: `EQF(1-3)=XCEN,YCEN,ZCEN; EQF#(1-3)=0,0,0`.
Синтаксис весов в MF — `<марка>/<вес-маска>` (FORM.VP: `dw1/0****`).

## 6. Методы оптимизации и трассировка

Методы (@0x65392): `LM` (Levenberg–Marquardt), `DLSM-1/2/3` (Damped
Least Squares — три варианта демпфирования), `OBM`, `SDM+LSM`, `LSM`
(линейный МНК), `SDM` (наискорейший спуск) + `norm=`. Панель
управления @0x66004: `-Penalty Merit Step Cycle` (штрафы, функция
качества, шаг, число циклов) — форма уходит в юнит-1 (§2). Меню работ
@0x65316: `Scheme Angle Glass Text All INF MF Loop Step Graf Full
Random Glass Com...` — Scheme (редактор схемы), Angle/Glass (углы/
стёкла), Text, INF, MF (функция качества), Loop/Step (итерации),
Graf/Full/Random (график/полный/случайный старт). Горячие клавиши
@0x658d8: F4-GLASS, F5-MAP, SPACE-ZOOM, L(0..2)/WAVE.

Trace-точки итераций (форматные строки в данных 0x61482..0x61E88,
пишутся в `iavdp1.for`-трейс по OPAL-PC TRACE — REVERSE_TRACE):

| строка | вывод | смысл |
|---|---|---|
| `GTISpd - ISTOP,NSTEP,IPOD=` | останов/шаг/режим | управление шагом |
| `RAYAD-R WA,W1,W11,HX,HY` / `RAYAD,IT,IP,idef` | волновая аберрация + зрачок | набор данных МНК |
| `RGRSKP F=` | значение функционала | оценка merit |
| `PENIP0 ROP=` | штрафы | penalty-член |
| `GTIDIA` | изображение (DIA) | критерий по G-файлу |

Спавн (аналогично OPALO): `KATEX.EXE` (dd.tmp, SS.TMP, PR.TMP),
`OPALTRAN.EXE`, `OPALFIND.EXE`, `WRITEOC.EXE`, `OH.EXE` + `OPTDOC.OH`
(документация оптимизатора — досье REVERSE_OPTDOC), `OPAL.EXE`
(возврат в меню), `ZERN.DAT`. Файлы данных: `GFILE.TMP` (изображение),
`PR.TMP` (протокол). ФМ-формат вывода итераций @0x65A4C:
`(1x,2(I3,3x),G9.4,1x,G9.4,1x,G9.4,1x,2(I2,2x),2(I3,2x),2x,I4,5x)`.

Глубокий разбор DLSM-кернела (матрицы нормальных уравнений, демпфирование)
в декомпиле затруднён: DS юнитов трекается плохо, ссылки на строки идут
через релоцируемые far-указатели (см. REVERSE_UNP §4 об ограничении);
фиксируется адресат — юнит-1 (45 входов, 0xCA04 Б) и юнит-4 (22 входа,
0x9FB4) как носители вычислений (функции с x87-интенсивностью:
FUN_8600_887D и др.). Для порта достаточно контракта (методы + merit +
penalty + словарь марок), численное ядро берётся из порта МНК.

## 7. GENIZE: объекты, файлы, масштабирование

Редактор: `Command→ Menu View Edit Calc Help Comm`; Save/Load objects
(.FRM-файлы форм). Типы (параметры в скобках):

| тип | параметры |
|---|---|
| Прямоугольники | X0 Y0 PX PY (полуразмеры), интенсивность, угол fi |
| Треугольники | X0 Y0 S0 H0 (основание/высота), инт., fi |
| Правильные многоугольники | X Y центра, размер, число сторон, инт. |
| Круги | X0 Y0 R0, инт. |
| Шпалы (миры) | пары X Y, размер шпалы, инт., угол, масштаб мкм |
| Буквы | А, E, W |
| Знаки | `: + % #` |
| Фон | общий уровень |

Расчёт: «Производится генерация изображения» — объекты растеризуются в
квадрат N×N («МК ИЗОБРАЖЕНИЕ ОБЪЕКТОВ В КВАДРАТЕ РАЗМЕРОМ─»), вывод
Ч/Б или изофоты (lin/log). Режимы анализа @0x2feef: `PSF EF LSF EDGE
BAR MTF SF`. Выход: `bpf100` (изображение), `bpf300`, `HAR.TMP`,
`MTF.TMP`, `PROTOCOL.PRN`; вход: `.FRM`, файл ОПФ («НЕТ ФАЙЛА С ОПФ» —
для свёртки с ЧКХ системы). x87-кернелы в сегменте 0000/1000
(FUN_1000_B290 — 18-аргументный вычислитель, 77 x87-строк в декомпиле).
Точные константы сетки (N, размер пикселя) в декомпиле не видны без
трекинга DS — при портировании берутся из формата bpf100 (заголовок
содержит размер; см. задачу ниже).

## 8. OPALOS ↔ OPALLAP (волна 9/C2) — отличия

| признак | OPALOS (интерактив) | OPALLAP (пакетный драйвер уровня 2) |
|---|---|---|
| работы в строках | OPS (Scheme/Angle/Glass/MF/Loop/Step/Random) | `SDIA OPALLAP SRT RT WA`, `AI gforus.dat GIA SDIA` |
| меню 1..9 | нет (свой UI оптимизации) | Глобальные координаты/Увеличения/Дисторсия/Габариты/Аберрации/Координаты лучей/Рисунок системы/Аппроксимация волнового фронта/Геом. анализ |
| методы | LM/DLSM-1..3/OBM/SDM+LSM/LSM/SDM, norm, Penalty/Merit/Step/Cycle | нет (не оптимизатор) |
| справка | OPTDOC.OH (спавн OH.EXE) | мониторовые .OH (WA/GIA/DIA/RT/SRT) |
| спавн | KATEX/OPALTRAN/OPALFIND/WRITEOC/OH | не найден |
| DGROUP | 0x63D0 (0xBD60 Б) | 0x5273 (0xD2E0 Б) |
| пул юнитов | 0x4AB4..0x599BF, 4 юнита, 126 сел. | 0x30BA..0x3C630, 6 юнитов, 133 сел. |
| payload int 3Fh | 3 байта `CD 3F sel off16` | 3 байта (как OPALOS) |
| RTL-сегмент | 0x2E62 | 0x1ECB |

Вывод: это РАЗНЫЕ классы программ над общей математикой уровня 2
(OPALOS — третий фронтенд семейства OPT/OPW/OPS; OPALLAP — драйвер
анализа). Общего кода между ними мало (разные RTL-сборки), модель
оверлеев — общая (single pool + int 3Fh).
