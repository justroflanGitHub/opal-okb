# §18. «TSR-рантайм» OPAL — реверс и разбор гипотезы §14.0

**Дата:** 2026-10-14 · **Файлы:** extracted/opal_okb/* · **Инструменты:** analysis/_tools/{tsr_lib,dis16,scan_vecs,exepack}.py · **Дампы:** analysis/reverse_data/{OPALA_unp.bin, tsr_disasm*.txt, tsr_opalcom.txt, tsr_final.txt}

---

## Вердикт (кратко)

**Гипотеза §14.0 «вывод таблиц идёт через TSR-движок вне EXE» — ОПРОВЕРГНУТА.**

1. `lcall 0xFF95/0xFFA9` — это не «рантайм-помощь TSR», а `CALL FAR 0x0FF9:0x0005/0x0019` — **собственные** REAL*8-функции OPALA (пара близнецов «λ→n»).
2. «TSR-сегменты» 0x2E73 / 0x506E / 0x52A6 / 0x52D4 — **пре-релокационные сегменты самого OPALA.EXE**, невидимые в §14.0 потому, что OPALA упакован **MS LINK /EXEPACK** и Ghidra-дамп покрывал только plain-зону. Образ распакован полностью (см. §1).
3. Печать строк идёт через **форматник FORTRAN RTL** `0x2E73:0x2042` внутри EXE — внешнего печатающего сервиса не существует.
4. Единственные векторы, которые ставит OPALA: **int 00h** (деление), **int 23h** (Ctrl-C) и **int 3Fh** — **Overlay Manager FORTRAN 5.0**. int 0x90 — файл-шина резидентного OPAL.COM. **Никто в пакете не ставит int 34h–3Eh и int 0xE0** (cd e0 — 0 вхождений).
5. int 34h–3Dh — это x87-обёртки эмуляции Microsoft (линкер переписывает `NOP/WAIT+ESC` → `CD 34…CD 3D`); их ~6,7 тыс. в OPALA. Инсталлятор обёрток в поставке отсутствует → на машине-оригинале вектора обслуживались **внешним резидентным эмулятором, загружаемым вне пакета** (CONFIG.SYS/AUTOEXEC), либо резидентом того же семейства. Никакого отношения к «шине сервисов печати» они не имеют.

## 1. EXEPACK: почему §14.0 видел «[НЕИЗВЕСТНО]»

OPALA.EXE (339800 б) упакован Microsoft LINK `/EXEPACK`: MZ `nreloc=0`, вход MZ `cs=0x4464:ip=0x0010` указывает на стаб-распаковщик (orig-lin 0x44650), трейлер `…[0]=0x9397 [2]=0x2E73 [8]=0x1000(SP0) [10]=0x5B82(SS0) [14]='RB'` хранит **оригинальный** вход. Стаб сам применяет релокации (`add es:[di],bx`, bx=сегмент загрузки) — поэтому в заголовке nreloc=0.

Распаковщик исполнен на мини-интерпретаторе 8086 (`analysis/_tools/exepack.py`, трюк: PSP=0xFFF0 → load-сегмент 0 → релокации добавляют 0 → образ остаётся **пре-релокационным**). Результат:

- стаб завершается `LJMP → 0x2E73:0x9397` — ровно оригинальный вход из трейлера ✔;
- образ 0x5C000 байт сохранен: `analysis/reverse_data/OPALA_unp.bin`;
- верификация: bytes[0..0x3F600) совпадают с файлом (plain-зона), хвост 0x3F600..0x5C000 распакован и содержит CP866-строки ровно на «TSR-сегментах» 0x506E/0x52A6/0x52D4 и DGROUP 0x552F.

EXEPACK-нуты также: METAPRN.EXE, METAPRNO.EXE, OPALOW.EXE, OPALVP.EXE, OPALO.EXE, OPALOS.EXE, OPALLAP.EXE (у всех nreloc=0, стаб на входе). OPALCALC.EXE — обычный EXE. OPAL5X5.EXE (0x400 б) — не MZ вовсе (файл-конфигуратор меню 5×5).

## 2. «lcall 0xFF95 / 0xFFA9» — расшифровка

Байты в местах 0746/e920/e7db: `9A 05 00 F9 0F` и `9A 19 00 F9 0F` = `CALL FAR 0x0FF9:0x0005` / `0x0FF9:0x0019`. Никаких векторов прерываний: обычные far-вызовы внутри OPALA (сегмент 0x0FF9 — математическая библиотека у вершины первого 64K-блока, 130 far-вызовов на него из кода).

Обе функции — близнецы, различаются только начальным флагом (0 в `0FF9:5`, 1 в `0FF9:0x19`, далее общий код с lin 0xFFBB):

```asm
0FF9:0005  push bp; mov bp,sp; sub sp,0x4C; push di; push si
           mov [bp-2],0;   mov [bp-0x20],0     ; вариант A
0FF9:0019  …                mov [bp-2],1; … 1   ; вариант B
общее:     les bx,[bp+0xA]
           int 3Ch                  ; ← x87-обёртка «далее полный ESC»
           fld qword ptr [bx]       ; загрузка REAL*8 аргумента
           int 38h                  ; ← x87-обёртка (ESC DC-семейство)
           push ss …
```

Это и есть «λ→n» из §14.0: пара REAL*8-функций дисперсии (два варианта показателя преломления — два стекла/две ветки), целиком внутри EXE.

## 3. «TSR-сегменты» = сегменты одного EXE

| Сегмент (пре-релок) | Содержимое (из OPALA_unp.bin) |
|---|---|
| **0x2E73** | RTL FORTRAN 5.0 (старт 0x2E73:0x9397 — оригинальный вход; тысячи far-вызовов `9A xx xx 73 2E`; топ целей: 0x3AF5×140, 0x3B01×98, 0x38F8×85, 0x0E9E×85…) |
| **0x0FF9** | математические функции (0x0FF9:5/0x19 — дисперсии; 0x0FF9:0x86A6 — вызывается из стартовой функции сегмента 0) |
| **0x506E** | **пустой буфер** (нули, BSS — рабочая зона форм; заполняется в рантайме) |
| **0x52A6** | **словарь режимов вывода таблиц** (CP866): «НЕТ/ДА», «Аберрация», «Разностный», «Спектр», «ВСЕ», «Поперечные/Продольные/Волновые», «Неизоплан.», «C'm», «Z'm», «Меридиональное/Сагиттальное/Косое», «Азимут=», «Дисторсия абсолют./в %», «Положение фокусов», «Астигмат., кривизна», «Радиусы каустики», «Светораспределение», «Световые/Экрана», «Габаритные», «Веер», «Хромат.увелич. абс/в %», «Хромат.полож. мер./саг.», «tg'*100», «mm», «вх. зрачок/диафрагма/вых. зрачок», «Суммы на поверхностях», «Накапливающиеся суммы», «Координаты нул. лучей», «Естественная/Каноническая/Заданная», «по Апертуре» |
| **0x52D4** | **шаблоны экранных форм + именованные форматы**: бланки «Габариты пучков-└реальные», «Учет экранирования пучков-└Отсутствует», «Аберрации -└Поперечные», «Количество лучей -…», «Пучок -└ALL», «Сечение пучка -└Меридиональное», «Вид графика -└Дисторсия абсолют.», «Нормировка -└Каноническая»… и **именованные форматы FORTRAN** `*sumsed(' ',I3,5(F11.5),2F10.5)`, `*sumab3(' ',7(F11.5))` + заголовки колонок `S1 S2 S3 S4 S5 S1хр S2хр` (суммы Зейделя). 9 прямых ссылок `mov ax,0x52D4` из кода форм (lin 0x68B4…0x7662) |
| 0x552F | DGROUP (данные RTL: таблицы оверлей-менеджера 0x2A38–0x2B60, строки ошибок, FP-константы с 0x2AF0: `00 00 F0 3F`=1.0, `00 00 80 3F`=1.0f…) |
| 0x3F60 | **оверлейная зона** (см. §5) |

Полные дампы: `analysis/reverse_data/tsr_final.txt`.

## 4. Печать: 0x2E73:0x2042 — форматник RTL, не TSR

```asm
2E73:2042  push bp; mov bp,sp; push si; push cs; call 0x3357E  ; вход far (retf)
           mov ax,[bp+6]; mov [0x1884],ax        ; unit
           lea ax,[bp+8];  mov [0x1886],ax       ; список аргументов
           mov ax,0x18AC; push ds; push ax; push cs; call 0x3756A  ; компилятор формата (дескриптор CS:0x18AC)
           …проверка [0x1870..0x1876] (таблица открытых устройств), сброс флагов буферов…
           mov ax,1; push ax; call word ptr [0x18DC]             ; косвенный вызов диспетчера устройств DGROUP
           … retf
```

19 call-сайтов `9A 42 20 73 2E` в OPALA. Это внутренний движок форматного вывода FORTRAN RTL (дескрипторный, с косвенной диспетчеризацией через DGROUP:0x18DC) — **весь вывод таблиц живёт внутри EXE**.

## 5. int 3Fh — Overlay Manager FORTRAN 5.0 (настоящая «рантайм-помощь»)

Установка — на оригинальном входе `0x2E73:0x9397` (lin 0x37AC7):

```asm
push ds; mov ax,0x552F; mov ds,ax        ; DGROUP
mov ah,30h; int 21h; cmp al,2; jae ok    ; требование DOS 2+ («Incorrect DOS version»)
ok: mov byte [0x2112],1                  ; флаг «восстановить вектор при выходе»
    mov di,0x2AEC; mov al,[di]           ; № вектора ИЗ ДАННЫХ = 3Fh (опция линкера /OVERLAYINTERRUPT)
    mov [0x2113],al
    mov ah,35h; int 21h                  ; getvec: сохранить старый → [0x2114]/[0x2116]
    mov dx,cs; mov ds,dx; mov dx,0x9272; mov ah,25h; int 21h   ; setvec 3Fh := 0x2E73:0x9272
    … call 0x37B1A  ; открыть "opala.exe" (имя DGROUP:0x2ADD), построить полный путь (drive+cwd)
    jmp 0x3261E     ; RTL-startup
```

**Протокол вызова — инлайн, как у x87-обёрток:** в коде корня стоит `CD 3F <байт-селектор> <word> <word>` (6 сайтов: lin 0x37DE, 0x423B, 0x4329, 0x29C67, 0x2AA4B, 0x2C084; селекторы 0x02, 0x12, 0x16, 0x1C). Обработчик `0x2E73:0x9272`:

1. снимает с стека адрес возврата (`pop bx; pop es; popf`) и читает **5 байт payload сразу после `CD 3F`**, пропуская их;
2. пишет вход (ES:BX после payload + флаг) в кольцевой журнал DGROUP:0x24A8 (макс. 0x80 записей — иначе «`\r\nOverlay Manager stack overflow\r\n`»);
3. селектор → word-таблица **DGROUP:0x2A74** (селекторы 1–30 → все **0x3F60**, сегмент загрузки) и byte-таблица **0x2AB2** (селекторы 1–21 → **файл 1** = opala.exe; 22–30 → **файл 2**);
4. валидатор/загрузчик `0x37833`: если нужный файл/оверлей не текущий — открыть/перечитать (retry-цикл «`\r\nPlease insert diskette containing `…`\r\nin drive `…», «`\r\nCannot load overlay: too many open files\r\n`», при отказе «`\r\nOverlay not found\r\n`»);
5. `retf` в точку после payload, **подложив на стек** [dx=сегмент 0x3F60][cx] и far-стаб **0x2E73:0x9230** — стаб снимает журнал-запись при возврате из оверлея;
6. CodeView-поддержка: детект отладчика через `getvec(int 3)` + сигнатура **«CVDEBUG»** на `es:[0x80]` (DGROUP:0x29C8); уведомления отладчика «события 6/7» через `lcall [DGROUP:0x29D0]`.

**Структура файла:** load image 0x46172 б; хвост 0xCBE6 б = таблица far-входов оверлейных функций (`0x3F60:0x0552, 0x3F60:0x0547, 0x3F60:0x053E, …`) + код/данные оверлеев. Все 30 селекторов грузятся в **один** сегмент 0x3F60 (0x3F60..0x4617 ≈ 27 КБ) — в памяти одновременно один оверлей. OPALTRAC.EXE несёт наложенный MZ-заголовок (cs=0xFFF0:0x0100, nreloc=1, hdr=0x80) — типичный формат оверлейного файла LINK; кандидат на файл-оверлей №2 (имя файла 2 в таблице DGROUP нулевое — подставляется в рантайме).

## 6. int 34h–3Eh: x87-обёртки без инсталлятора

Подтверждение модели §0/§0.1 прямо в коде (см. §2): `int 3Ch` стоит **перед** настоящей ESC-инструкцией (`fld qword [bx]`) — «CD 3C + полный ESC»; `int 38h` — обёртка ESC-DC. Счётчики в OPALA: 34h×233, 35h×802, 36h×12, 37h×102, 38h×1181, 39h×2062, 3Ah×316, 3Bh×16, 3Ch×747, 3Dh×892, 3Eh×0.

Механизм (литература: os2museum.com «8087 Emulation on 8086 Systems»; Ralf Brown INT 34–3D «Floating Point emulation»): при линковке с библиотекой эмуляции **линкер** переписывает `NOP/WAIT+ESC` в `INT 34h–3Dh`; эмулятор при старте ставит хендлеры, а при наличии 8087 **самопатчит INT обратно в ESC** при первом исполнении.

**Но в пакете нет ни одного инсталлятора 34–3D.** Полное перечисление setvec в распакованном OPALA (все `mov ah,25h; int 21h`, включая динамический AL):

| Вектор | Где ставится | Назначение |
|---|---|---|
| **int 00h** | lin 0x35C32 (`mov ax,0x2500; mov dx,0x3F99`) | FORTRAN-обработчик деления на ноль; старый → DGROUP:0x20D1, восстановление при выходе (0x35D5E) |
| **int 23h** | lin 0x3763D | хук Ctrl-C на время работы |
| **int 3Fh** | lin 0x37B03 | Overlay Manager (§5) |

Прямых записей в IVT (0xD0–0xF8) нет; `int 11h` (детект FPU) — 0 вхождений. OPAL.COM ставит только int 90h (и чистит бит Shift в BDA 0x417); KEYRUS.COM — клавиатурные вектора (int 09/10/16/1F/08/44, волна 4); OPALCALC.EXE — plain-EXE, векторов 34–3E не ставит; остальные EXE — EXEPACK-нутые дочерние программы (их хендлеры жили бы в их собственном адресном пространстве и не могли бы обслуживать OPALA).

**Вывод:** на машине-оригинале векторы 34h–3Dh обслуживались **резидентным x87-эмулятором Microsoft-совместимой схемы, загруженным вне этой поставки** (из CONFIG.SYS/AUTOEXEC.BAT до OPAL.BAT). «Шина TSR-сервисов int 0x35/0x39/0x3A/0x3D» из §14.0 — артефакт интерпретации: это обычные FP-обёртки (ESC DC/D9/DA…-семейства + FNSTSW/FWAIT), исполняемые тысячами в математике OPAL.

## 7. int 90h — файл-шина OPAL.COM (единственный настоящий TSR)

Обёртки OPALA (lin 0x2E611 и 0x2E634 — вторая используется обёртками-функциями с AL=2 и AL=0x1C):

```asm
push ax/bx/dx/es
mov ah,35h; mov al,90h; int 21h    ; getvec(90h)
mov ax,es; cmp ax,bx; je FAIL      ; вектор пуст → OPAL.COM не резидентен
pop …; int 90h; cwde; cdq; retf    ; вызов шины, расширение до INTEGER*4
FAIL: mov dx,0x3390; mov ah,9; int 21h   ; «\r\nThis program must be run under OPAL-PC\r\n\a»
      mov ax,0x4CFFh; int 21h            ; exit(255)
```

**Гвард пакета:** без резидентного OPAL.COM программы отказываются стартовать. Обработчик OPAL.COM (0x156E) диспетчеризует по AL через таблицу CS:0x115 (заполняется при инсталляции), ищет имя в каталоге **OPAL.ARH** (записи offset/size, `cmp [bx+4],ax`), читает блоки — DOS-подобная семантика AH=5Bh/3Dh/3Fh (детали — волна 4). Клиенты int 90h: **OPALA** (2 обёртки), **OPALCALC.EXE** (0x13422), **METAPRN.EXE / METAPRNO.EXE** (по 4 сайта). OPAL.ARH (11990 б) — безымянная таблица каталога данных, исполняемых файлов внутри нет.

## 8. Карта памяти после загрузки (OPAL.BAT: keyrus.com → opal.com)

```
0x00000  IVT + BDA (int 34–3D → ВНЕШНИЙ резидентный x87-эмулятор, в поставке отсутствует)
…        DOS, драйверы, KEYRUS.COM (резидент: int 09/10/16/1F/08/44)
…        OPAL.COM (shrink до 0x196 параграфов, int 90h, EXEC-лончер + файл-шина OPAL.ARH)
…        дочерний процесс (OPAL5X5.EXE — конфиг-меню 5×5, 0x400 б) → OPALA.EXE:
         PSP  = L−0x10
         L:0  … EXEPACK-стаб → распаковка вниз до ~0x5C000 б, саморелокация +L
                пре-релок сегменты: код 0x0000…, RTL 0x2E73+L, матем. 0x0FF9+L,
                оверлейная зона 0x3F60+L (≈27 КБ, один оверлей), данные 0x506E/0x52A6/0x52D4+L,
                DGROUP 0x552F+L, стек 0x5D0D+L:0x1000 (RTL переносит SP на 0x652E)
                (векторы: int 0, int 23h, int 3Fh — ставит и снимает сам)
         итого OPALA ≈ 360 КБ RAM + оверлеи читаются с opala.exe по требованию
```

## 9. Значение для нативного порта

- «TSR-движок» не существует: всё, что §14.0 относил к внешнему сервису, находится внутри OPALA.EXE (в упакованном хвосте).
- Для воспроизведения вывода таблиц достаточно: (а) семантики FORTRAN-форматника (0x2E73:0x2042, включая именованные форматы `*sumsed`/`*sumab3` из 0x52D4); (б) словарей и шаблонов форм 0x52A6/0x52D4 (CP866, сдамплены); (в) REAL*8-дисперсий 0x0FF9:5/0x19; (г) вместо int 90h — прямое чтение файлов из OPAL.ARH.
- Оверлейный механизм (int 3Fh) для порта не нужен — это только схема ленивой загрузки кода.
