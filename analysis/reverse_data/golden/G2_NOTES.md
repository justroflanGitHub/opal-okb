# G2 — промежуточные находки (рабочий дневник, войдут в REVERSE_G2_GOLDEN.md)

## Текстовый .PRN = ПРОТОКОЛ OPALTRAN (механизм доказан, сеанс 78f41760 от 16.10)

RT__1956.PRN (481 б, 19:41) и RT__20_0.PRN (4149 б, 20:00) созданы так:

1. Загрузка системы → PROTOCOL.PRN пересоздаётся пустым (0 б).
2. Таблица, рассчитанная в ТЕКСТОВОМ виде (F2 = Menu → пункт → ENTER),
   добавляется в протокол в памяти (формат: заголовок «Cистема-<имя> <пар.>
   Работа-RT ... OPAL-PC» + секция таблицы, строки \r\r\n).
   - В протокол попал п.2 «Параксиальные характеристики» (меню F2, DOWN×5 с
     6-го пункта закольцевало на 2) → PROTOCOL.PRN 0→427 б.
3. F4 = Prtkol — открывает ОКНО ПРОТОКОЛА (диалог с разделами).
4. F9 = Save — диалог Записи («Каталог»/«Имя», имя по умолчанию RT__HHMM.PRN,
   HHMM = время) → ENTER принимает → файл RT__HHMM.PRN = дамп протокола.
   Рядом с RT__2250.PRN лежит RT__2250.PCX → F9 пишет .PCX для графики,
   .PRN для текста.
5. RT__20_0.PRN = та же сессия, протокол вырос (Параксиальные + Аберрации
   осевого пучка ×2) → повторный F9→ENTER в 20:00.

Формат RT__2236.PRN (эталон): заголовок + «Аберрации осевого пучка»
(продольные/поперечные) + волновая таблица — т.е. протокол сессии, где
рассчитывали только осевой пучок. Для золотого файла: с US00KI02 рассчитать
осевой пучок в тексте → F9 → ENTER.

## Особенность навигации (проверено в живой сессии 23:0x)
- Вьюхи через F10→RIGHT RIGHT→ENTER(Анализ)→ENTER→'4'→'6' НЕ пишут протокол
  (PROTOCOL.PRN остался 0 б от 22:06). Пишет только пересчёт через F2-меню.
- Гейт «Не готов принтер. Записать в файл ?» (появляется при F7→цифра без
  принтера): DOWN+ENTER = ДА (создаёт RT__HHMM.PRN с ДВОИЧНЫМ потоком для
  пункта '1' Расчет, 24969 б, побайтно = RTTEST32.PRN). LEFT+ENTER = НЕТ.
- ESC гейт НЕ закрывает. PostMessage-клавиши (dosbox_send.py) в OPALTRAN
  работают только после focus() окна (ALT-трюк) — сырые сканкоды
  keybd_event (_scratch_sdl.py) надёжнее.
- OPALTRAN = 640×400 ГРАФИКА (VGA mode 12h?), текстового слоя VRAM нет;
  шрифт в OPALTRAN.EXE НЕ найден обычным сканом (возможно сжат). KEYRUS
  шрифт (таблица @0x45d0) экрану НЕ соответствует.
- Заголовок окна DOSBox: «Program: OPALTRAN» — цепочка OPAL.COM запускает
  OPALTRAN.EXE (не OPALA.EXE напрямую).

## Система в памяти = IR = US00KI02 (подтверждено)
- US00KI02.OPJ (1312 б, offset 12) = «IR    -.2X D=10  2W=72 10L  2USP» —
  РОВНО система эталона RT__2236.PRN (и RT__2250.PRN). Задача «загрузить
  US00KI02» уже выполнена авто-восстановлением сессии из OPAL.PSP.
- F8 в RT открывает диалог загрузки, но ТАМ ЖЕ открывается ENTER на п.1 —
  ввод текста «US00KI02.OPJ»+ENTER в этом диалоге ЗАВЕРШИЛ программу
  (title → DOSBOX, 640×400). Не повторять! Лечится перезапуском OPAL.COM.
