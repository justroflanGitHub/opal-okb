## 1. Цель и результат

У реестра команд (`commands/registry.py` — источник истины: 506 команд,
схемы с описанием/параметрами/returns) не было человеческого справочника —
README упоминал только счётчик. Сделано:

| Артефакт | Что это |
| --- | --- |
| `scripts/gen_command_reference.py` | headless-генератор (без Qt): `--check`, `--out DIR`, `--json` |
| `docs/reference/COMMANDS_INDEX.md` | оглавление: счётчики + таблица 40 категорий со ссылками-якорями |
| `docs/reference/commands-<category>.md` × 40 | страница категории: сводная таблица команд + секции параметров |
| `docs/reference/registry_snapshot.json` | машиночитаемый дубль реестра (для агентов) |
| `tests/test_cmd_reference.py` | 4 инварианта (полнота, `--check`, страницы категорий, якоря) |
| `.gitattributes` | `docs/reference/** text eol=lf` — против autocrlf |
| README.md | ссылка на справочник рядом с упоминанием реестра (506 commands) |

## 2. Использование

```bash
py scripts/gen_command_reference.py            # регенерация docs/reference
py scripts/gen_command_reference.py --check    # бит-в-бит сверка, без записи
py scripts/gen_command_reference.py --out DIR  # альтернативный каталог вывода
py scripts/gen_command_reference.py --json     # краткий итог в stdout (JSON)
py -m pytest tests/test_cmd_reference.py -v    # 4 инварианта
```

- Пути резолвятся **от корня репозитория, не от cwd** — запуск из любого
  каталога (проверено из `%TEMP%`).
- Коды возврата: `0` — генерация выполнена / `--check` чист; `1` — `--check`
  нашёл расхождения; `2` — ошибка аргументов CLI. Годится как CI-guard.
- `--json`: `{"commands": 506, "categories": 40, "files_expected": 42,
  "check": "ok", "missing": 0, "extra": 0, "changed": 0}`.
- Тесты-инварианты (все 4 зелёные, headless, чтение `docs/reference` +
  единственный subprocess `--check`):
  1. `test_reference_is_complete` — h3-секции страниц, snapshot и счётчики
     индекса покрывают реестр (506/40) без расхождений множеств;
  2. `test_check_mode_is_clean` — `--check` exit 0 (регенерация бит-в-бит);
  3. `test_every_category_has_file` — каждой категории соответствует
     `commands-<cat>.md` с h1 `# Категория <cat>` и строка в индексе;
  4. `test_markdown_headers_and_anchors_are_valid` — ровно один h1 и один
     h2 на странице, уникальные слаги, все внутренние/индексные ссылки
     ведут на существующие якоря (слаги в стиле GitHub).

## 3. Формат справочника

- **`COMMANDS_INDEX.md`** — заголовок с пометкой «автогенерируется, не
  редактировать вручную» + команды регенерации/проверки; счётчики
  `Команд: 506`, `Категорий: 40`; таблица `Категория | Команд | Файл`
  со ссылками-якорями вида
  `[commands-aber.md](commands-aber.md#категория-aber)`.
- **`commands-<category>.md`** — h1 `# Категория <cat>`, строка «N команд.»
  (русская форма множественного числа), сводная таблица
  `Команда | Описание | Параметры | Returns` (имена параметров — inline-code),
  затем h2 `## Параметры и результаты` с **h3-секцией на команду**:
  полное описание без обрезки, строка `**Returns:**` и таблица
  `Имя | Тип | Обяз. | Умолчание | Choices | Описание`. h3 используется
  только для команд — на этом строится инвариант подсчёта секций.
- **`registry_snapshot.json`** — `meta {generator, command_count:
  506, category_count: 40, categories: {<cat>: N, …}}` + `commands[506]`
  (name, category, description, returns, params[{name, type, required,
  default, choices, help}]); `json.dumps(ensure_ascii=False, indent=2,
  sort_keys=True)`.

## 4. Ключевые решения

- **Детерминизм.** Явные stable-сортировки (категории и команды —
  `sorted()`, параметры — в порядке объявления схемы), в выводе нет
  временных меток и версий; файлы пишутся в UTF-8 с принудительным `\n`.
  Регенерация бит-в-бит проверяется `--check` (CI-guard). В `.gitattributes`
  добавлено `docs/reference/** text eol=lf`: без него clone с
  `core.autocrlf=true` на Windows превратил бы LF → CRLF в рабочем дереве
  и сломал бы бит-в-бит сверку.
- **Экранирование `|` в таблицах.** `_cell()`: переводы строк → пробел,
  `|` → `\|`. В реестре **17 команд** с `|` в описании/returns/help
  параметров (в описании `calc.aperture.na` — сырой текст `NA = NA′·|V|`,
  на странице он превращается в `NA = NA′·\|V\|`) — всего 59
  экранированных вхождений на 8 страницах; без экранирования таблицы
  разъезжались бы.
- **Якоря-слаги по алгоритму GitHub:** lower(); удалить символы кроме
  unicode-букв/цифр/пробела/дефиса/подчёркивания; пробелы → дефисы.
  `calc.paraxial` → `calcparaxial`, «Категория aber» → `категория-aber`.
  В тесте `_slug()` реализована **независимо от генератора** — тест ловит
  рассинхрон алгоритмов (проверено негативным тестом, см. §6).
- **h3 зарезервирован за командами:** инвариант полноты считает h3-секции
  страниц и сверяет множество с именами реестра (506 == 506).
- **Headless-импорт реестра без Qt:** `import commands` регистрирует все
  builtin-команды; bootstrap `sys.path.insert(0, <корень репозитория>)`
  по образцу `scripts/corpus_scan.py` (та же строка, см. `corpus_scan.py:46`);
  stdout/stderr переустанавливаются в UTF-8 (консоль Windows cp1251).

## 7. Ограничения / следующие шаги

- **Якоря-слаги — алгоритм GitHub.** GitLab, VS Code и другие рендеры
  считают якоря иначе (кириллица, точки, нижние подчёркивания) — там
  оглавление индекса может не сработать. Для GitHub Pages / README-рендера
  GitHub всё корректно.
- **Индекс и страницы на русском** (язык реестра). Английская версия —
  потенциальный CLI-флаг генератора (`--lang en`), пока не делалось.
- **`--out DIR` не подключён к CI/релизам:** можно собирать снапшот
  справочника в артефакты релиза — следующий шаг, если понадобится.
- **Справочник — производная реестра:** любое изменение `commands/`
  требует регенерации; забытую регенерацию ловит инвариант `--check`.
- Пакет E (финал ТЗ): полный `py -m pytest -q` зелёный, CHANGELOG `[1.34.0]`,
  воспроизводимость генерации одной командой.
