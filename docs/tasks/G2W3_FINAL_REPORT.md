## Зеркальные — отдельный разбор (приоритет ТЗ)

**Критерий ТЗ «зеркальные в банке есть» формально НЕ достигнут.** Честная
причина: в standalone-OPJ стенда зеркальной кодировки нет, а зеркальные,
существующие в LBO-библиотеках, требуют рецепта загрузки из библиотеки,
которого в волне 3 не было (расследование — G2W3_PLAN.md §4):

1. **Формат**: поверхность OPJ = 16 байт (R: double, d: double) — поля
   «тип поверхности/зеркало» в структуре нет.
2. **Конвенция OPAL** (стенд, `C:\GOLDEN_DOS\DOC\MANUAL.DOC` §2.1.2):
   отражающая поверхность особо не выделяется — после неё знак показателя
   преломления среды меняется на противоположный (минус у кода/имени).
3. **Скан всех 85 OPJ стенда** (glass-блоки — имена cp866): ни одного имени
   с минусом, ни одного «ЗЕРКАЛО»/«MIRR» → ни один standalone-кандидат
   не кодирует зеркало. (Попутно: в glass-блоке имена, а не индексы —
   поиск LBO-индексов 65534/65535 в нём в принципе не мог ничего найти.)
4. **Disasm**: слово «Зеркальное» встречается ровно один раз
   (`_OPALLAP_strings.txt:03cd2d`) — пункт меню «ЭЛЕМЕНТАРНЫЕ
   ПРЕОБРАЗОВАНИЯ» (зеркальное оборачивание изображения), к типу поверхности
   отношения не имеет.
5. Ближайшее к зеркальным в банке: **121** (TIR-кромка OD2 — строки «иного
   прохода», теперь + EGOR_2 з1.0, LEXA23 з0.866, DEM з1.0),
   **US00KI02** «IR -.2X» (отрицательное увеличение, не зеркало);
   единственный зеркальный standalone **YBBS77_ «Тор»** — отклонён ранее
   (дрейф pulldown-меню, фикс требует правки драйвера — запрещено).
6. **Future work (волна 4)**: зеркальные есть только в LBO-библиотеках
   (`C:\GOLDEN_DOS\Lib\*.LBO`, 14 файлов), все parse-ok в corpus_v2 — **6
   систем**: LENS_SPC ×4 (ST01FH01 зеркально-линзовый f'=55, ST01FH02 f'=450,
   ST01FH03 Ричи-Кретьен f'=1500, ST01FI02 ИК з-л), USLENS ×2 (US01FH01
   MIRR 2M+4L, US01FH02 MAKS-CASS). Рецепт g2bank грузит только .OPJ файловым
   диалогом Чтения; нужен новый рецепт (диалог библиотеки) + расширение
   драйвера. Именно они закроют приоритет «зеркальные».
7. Приоритет ТЗ по конвенциям знаков/мнимых изображений отработан
   переносом на **ИК/KBR-семейство** (8 систем) и сиблингов xfail-гипотез —
   см. ниже: знаковый вопрос получил 3 новые точки (DEM1, LEXA23, SERGEY0).

## Находки-топ (полный реестр — G2W3_FINDINGS.md)

1. **Знак при мнимом изображении — L_p НЕ дискриминатор.** Три новые точки:
   DEM1 — флип при L_p=+14.29 (z_obj=0), LEXA23 — нет флипа при L_p=−10.25,
   SERGEY0 — флип при L_p=−923 (arcsec). DEM1 и LEXA23 взаимно исключают оба
   простых правила по знаку L_p; данные согласны с «OPAL флипует при
   действительном изображении с перевёрнутым веером» — нужно отдельное
   расследование. Попутно: **несимметрия кода сверок** — правило флипа есть
   в mm-ветке (near) и отсутствует в arcsec-ветке.
2. **SERGEY0: прод-дптр — константа OPAL/порт 0.819–0.822** по всем зонам —
   множитель печати (E2-множитель марша λ; семья KOLLEKT) — кандидат на
   калибровку по KOLLEKT-методу.
3. **Паттерны G44 пер-системны**: сиблинги WA3/PETRO3/ANDREW_2 зелёные →
   паттерны WA2/PETRO1/222 не семейные, а специфичны конкретным системам;
   GTIN0 (двойник ST) и S_KOND3/SERGEY3/LEXA11 — семьи зелёные.
4. **TIR-кромка в прямом прогоне** (121-паттерн): EGOR_2 з1.0 (волновые
   201.52λ при SKIP порта), LEXA23 з0.866 (за критическим углом при na≈1),
   DEM з1.0 — строки «иного прохода» OPAL; точная инверсия «Н ЗР → зона»
   sin(arctan(hzr/100))/NA (правка N4) на малых NA тождественна старой.
5. **Формат-находки** (4 правки парсера, обратно совместимо): слитые Sp/Sp′
   (DEM1, N1), звёздные поля (LEXA23, N2), компактный хвост TABOC2 (DEM/
   LEXA23, N3), точная инверсия Н ЗР (N4); дубль секции осевого (GUTAN4/
   LEXA21/G1) парсер взял без правок; YBBG00 без glass-блока — полный RT.
6. **Кандидат-fix сверок** (не применён, за Пакетом D/волной 4): abs() в
   near-ветке для Tg'*100 (H`ЗР) при img=0 — закрывает SERGEY0 Tg ×4 (→Y)
   и по числам G44 — VV ×3 (→GREEN), но меняет старую систему → только
   осознанно, вместе с xfail-пересмотром.
