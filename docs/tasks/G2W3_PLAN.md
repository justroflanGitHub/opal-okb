## 4. Зеркальные: расследование (приоритет ТЗ)

**Вывод: печатать зеркальные в волне 3 неоткуда — среди 85 standalone-OPJ
стенда зеркальной кодировки нет. Зеркальные системы есть только в LBO-библиотеках
(6 шт, все parse-ok в corpus_v2) и требуют отдельного рецепта загрузки →
future work (волна 4).**

Факты:

1. Формат OPJ (`fileio/opj_io.py`): поверхность = 16 байт (R: double,
   d: double) — поля «тип поверхности/зеркало» в структуре нет.
2. Конвенция зеркал OPAL (стенд, `C:\GOLDEN_DOS\DOC\MANUAL.DOC` §2.1.2):
   отражающая поверхность особо не выделяется — после неё показатель
   преломления среды меняет знак на противоположный («меняется на
   противоположный знак, стоящий у кода или имени»). В LBO-библиотеках
   (`fileio/decode_lbo.py`) зеркало = индекс стекла 65534/65535
   (`MIRROR_INDEXES`).
3. Скан glass-блоков всех 85 OPJ стенда: минус-имён и «ЗЕРКАЛО» нет → ни один
   standalone-кандидат не кодирует зеркало через среду. Замечание к зонду
   оркестратора: glass-блок OPJ хранит ИМЕНА (8 байт cp866), а не индексы —
   поиск 65534/65535 в нём в принципе не мог ничего найти; корректный признак —
   минус у имени (нет ни у одного) или отсутствие glass-блока (3 файла, §3).
4. Слово «Зеркальное» в disasm-строках — ровно одно:
   `analysis/reverse_data/_OPALLAP_strings.txt:03cd2d` —
   `Зеркальное "-1-й поворот 1-е увеличен. 2-е увеличен."` — пункт блока
   «ЭЛЕМЕНТАРНЫЕ ПРЕОБРАЗОВАНИЯ» (рядом: анаморф., оборач., повороты,
   увеличения) = зеркальное оборачивание изображения (ср.
   `C:\GOLDEN_DOS\DOC\SPACE.DOC`: «зеркальное оборачивание»), к типу
   поверхности отношения не имеет. В остальных модулях (OPALO, OPALOW, OPAVA,
   GENIZE) «зерк» не встречается вовсе.
5. Единственный «зеркальный» standalone — YBBS77_ «Тор» (n_surf=2, λ=1):
   отклонён ранее — 4+ NOOPALA2 (дрейф pulldown «Меню работ»; для fixа нужен
   контроль подсветки перед RIGHT = правка драйвера, запрещённая). В очередь
   не включён.
6. Зеркальные корпуса — 6 в LBO (corpus_v2, статус ok): LENS_SPC ×4
   (ST01FH01 зеркально-линзовый f'=55, ST01FH02 f'=450, ST01FH03 Ричи-Кретьен
   f'=1500, ST01FI02 ИК з-л), USLENS ×2 (US01FH01 MIRR 2M+4L, US01FH02
   MAKS-CASS). Библиотеки физически на стенде: `C:\GOLDEN_DOS\Lib\*.LBO`
   (14 файлов). Рецепт g2bank грузит только .OPJ файловым диалогом Чтения;
   загрузка из библиотеки идёт через другой диалог → нужен новый рецепт +
   расширение драйвера. **Future work (волна 4):** исследовать диалог библиотеки
   и напечатать эти 6 — именно они закроют приоритет ТЗ «зеркальные».
7. Нюанс: US00KI02 (в банке, sanity, ИК 10 мкм) в манифесте помечен «ИК
   зеркальный» — по заголовку это «IR -.2X D=10 2W=72 10L 2USP»: 10 линз
   (20 поверхностей), «-.2X» = отрицательное увеличение. ИК-e2e представитель в
   банке уже есть, зеркального e2e — нет (см. п.6).

## 5. YBBG00 — hex-анализ

`YBBG00.OPJ` (472 б) — **«basic test», синтетический тестовый файл, НЕ
зеркальный и НЕ особая оптика**:

- имя системы (0x0C–0x33) = `basic test`; flags (0x36) = 3 (у большинства
  файлов 1; такой же flags=3 у GTIN0); n_surf=6, n_wl=3.
- glass-блок НЕ отсутствует, а ПУСТ: 3 записи по 8 пробелов + терминатор 00 00
  (0x15E–0x175) — маркера ВОЗДУХ нет вовсе, в отличие от US00KI02/PLIOPT, у
  которых glass-блока нет как региона. Парсер `opj_reader` поэтому даёт
  `glass_block_offset = -1`.
- Реальные данные: пары (R, d) по 0xE0: (2.4, 0.5), (4.2, 2.0), далее нулевые
  заглушки до n=6; в хвосте — обычные для формата регионы (`14 00 00 00 01 …`,
  float32 1.0 ×N, double 2.2, поле 24) — структура та же, что у обычных файлов
  (ср. DEM), т.е. файл не «чужого» формата, а вырожденно-простой.
- Зеркальных признаков нет: `ff ff` @0x46 — стандартное поле заголовка (§3),
  минус-имён нет, формата LBO-индексов нет.
- Вердикт: печатать можно (RT по KUZNEC/KUZNEC1 — тоже без имён стёкол —
  печатался OK), но система тестовая (2 ненулевых поверхности, без стёкол).
  Ставится в КОНЕЦ очереди (B5) как эксперимент; ожидаемо OK-NOAXIAL либо
  вырожденная печать — ценность как регресс-кейс «система без glass-блока».

## 8. Правила печати (из ТЗ TASK_GOLDEN_WAVE3.md, п.2)

- Печатать пачками по 3–5 систем; после каждой пачки — коммит

- Полностью мёртвый стенд (DOSBox не стартует / OPALA не грузится 3 бута

- Рецепт g2bank (последовательность клавиш, тайминги, RT.REG=TX, удаление
  PROTOCOL.PRN на старте RT) — НЕ менять. `RT.REG.bak_g2bank` на стенде есть.
- Печатается только РАСЧЕТ-RT ('4' габариты → '6' осевой пучок → F4 F9 ENTER
  из вида '6'); F6 в основном пути НЕ жать (toggle текст↔график).
- Файлы OPJ — со стенда `C:\GOLDEN_DOS` (только чтение); extracted/ не нужен.

## 9. Драйвер-обвязка (monkey-patch из %TEMP%)

`scripts/g2bank.py` менять запрещено (параллельные агенты; scripts/ закрыт), а
`analysis/` нашей копии разрешён только для `golden_verify.py`. При этом
g2bank жёстко пришит `ROOT = ...\opal_okb` (другая рабочая копия): BANK пишет в
ЧУЖОЙ банк, манифест — в чужой analysis/, скрины — в чужой capture/. Решение —
драйвер-обвязка в %TEMP%: импортирует g2bank как модуль и перенаправляет
константы до вызова `main()` (функции g2bank читают их в рантайме).

Файл `%TEMP%\g2w3_driver.py` (точный текст):

```python
# g2w3_driver.py — обвязка волны 3. Запуск: py %TEMP%\g2w3_driver.py ИМЯ [ИМЯ...]
# scripts/g2bank.py НЕ правим: импорт как модуль + перенаправление путей.
import importlib.util, os, sys
HERE = r'C:\Users\mikhail\.openclaw\workspace\opal_okb_gw3'
TMP  = os.environ['TEMP']
spec = importlib.util.spec_from_file_location('g2bank', os.path.join(HERE, 'scripts', 'g2bank.py'))
g = importlib.util.module_from_spec(spec); spec.loader.exec_module(g)
g.SEND = os.path.join(HERE, 'scripts', 'dosbox_send.py')   # запуск наших копий — не правка
g.SHOT = os.path.join(HERE, 'scripts', '_g2_shot.py')
g.CAP  = os.path.join(TMP, 'g2w3_cap'); os.makedirs(g.CAP, exist_ok=True)
g.BANK = os.path.join(HERE, 'analysis', 'reverse_data', 'golden', 'bank')  # наш worktree
g.MANIFEST = os.path.join(TMP, 'G2W3_manifest.md')         # analysis/ закрыт: строки манифеста сюда
g.main()
```

Пояснения:

- `SEND`/`SHOT` — копии в `scripts/` НАШЕЙ копии (запуск чужого скрипта не
  является правкой; файлы идентичны прецедентным, dosbox_send.py уже содержит
  патч `_`/`#`).
- `BANK` — `analysis/reverse_data/golden/bank/` нашего worktree: новые .PRN
  сразу в рабочей зоне волны 3 (коммит — оркестратором после пачки).
- `MANIFEST` — `%TEMP%\G2W3_manifest.md`: g2bank дописывает строки
  `| ИМЯ | RT | размер | статус | …` — по ним заполняется таблица итогов
  `analysis/REVERSE_G2BANK.md` (волна 3) и `G2W3_FINDINGS.md` без правки
  закрытых каталогов из агента печати.
- `CAP` — скрины в `%TEMP%\g2w3_cap` (capture/ не в рабочей зоне).
- `GD`, `DOSBOX`, `CONF` не трогаются: стенд `C:\GOLDEN_DOS` и conf в %TEMP%
