# TASK_COMMANDS_W3.md — Волна 3: массовое покрытие командами (параллельно, 4 домена)

**База:** ветка `feature/command-registry` (реестр, CLI, REPL, 32 команды — Волна 1).
**Цель:** покрыть командами все основные вычислительные операции приложения.
**Параллельность:** каждый агент работает в СВОЁМ git worktree и СВОЕЙ ветке `w3/<domain>`. Общий файл `commands/builtin/__init__.py` НЕ трогать (координатор обновит сам после мержа).

## Общие правила для всех доменных агентов

1. Изучи Волну 1 как эталон: `commands/base.py` (Command, Param, CommandResult, CommandError), `commands/builtin/calc_cmds.py` и `analyze_cmds.py` (стиль обёрток), `commands/context.py`, `commands/systemio.py` (загрузка систем).
2. Сначала изучи фактические API своего домена (сигнатуры, типы, что уже покрыто тестами). Оборачивай ТОЛЬКО функции без Qt: чистые вычисления. Если функция тянет Qt — пропусти и запиши в отчёт «пропущено, причина».
3. Свой файл: `commands/builtin/<domain>_cmds.py`. Регистрация через существующий декоратор `@command(...)`. Имена: `<domain>.<action>` (например `trace.fan`, `aber.field`, `psf.grid`, `opt.run`).
4. Аргументы/результаты — примитивы JSON (str/float/int/bool/list/dict). Параметры системы: `file` (путь .opj/.lbo/.json, опционально `lbo_index`/`lbo_name`) ИЛИ `system` (имя в контексте REPL) — использовать готовый хелпер из Волны 1, НЕ дублировать загрузку.
5. Тяжёлые параметры (N лучей, размеры сеток, число итераций) — параметры команды с дефолтами из существующего кода; магические числа — в именованные константы.
6. Тесты: `tests/test_commands_<domain>.py` — smoke КАЖДОЙ команды (демо-система через system.new/file из tests или fixtures существующих тестов). Смотри, как сделано в tests/test_commands_builtin.py Волны 1 — переиспользуй фиксттуры, не дублируй.
7. Не менять domain/analysis/optimizer/visualization — только обёртки. Не менять чужие builtin-файлы. Не трогать CLI/registry/base.
8. Полный прогон `py -m pytest tests/test_commands_<domain>.py -q` — зелёный; плюс `py -m commands list` не падает (реестр собирается).
9. Коммит(ы) в свою ветку. НЕ пушить, НЕ мержить.
10. Отчёт в конце вывода: список добавленных команд (имя — кратко), список пропущенного с причинами.

## Критерии качества
- Никаких дублей между builtin-модулями: общий хелпер — один, в systemio (Волна 1).
- Type hints, docstrings (русский — как в Волне 1), константы.
- Каждая команда реально считает (smoke-тест сравнивает с прямым вызовом функции домена, как в Волне 1).
