# TASK_COMMANDS_W4.md — Волна 4: перевязка UI на реестр команд

**База:** ветка `feature/command-registry` (реестр 128 команд, Волны 1+3).
**Цель:** вся ЛОГИКА меню и панели идёт через реестр команд; UI — тонкая обвязка.
**Принцип (VS Code):** кнопка не считает сама — она вызывает команду и рендерит результат. Чисто UI-действия (переключить вкладку, zoom, показать окно) командами НЕ становятся и НЕ трогаются.

## Общие правила (оба агента)

1. Сначала ИНВЕНТАРИЗАЦИЯ: пройди все экшены/обработчики СВОЕГО файла, каждый классифицируй:
   - `bound` — логика уже покрыта существующей командой (128 команд: file/system/calc/catalog/analyze/trace/beam/vign/tables/aber/adv/seidel/chrom/psf/mtf/diffr/strehl/zern/focus/opt/plot/diagram);
   - `gap` — логика нужна UI, но команды нет → создай команду в СВОЁМ новом файле `commands/builtin/w4_<src>_cmds.py` (правила обёрток — как в Волне 1: без Qt, JSON-контракт, тесты);
   - `ui-only` — чистый UI (вкладки, окна, выделение) → не трогать;
   - `direct-keep` — требует живого Qt-интерактива (например, интерактивный ввод в виджете) → оставить прямой вызов.
   Результат — таблица в `docs/tasks/W4_INVENTORY_<src>.md` (экшен → класс → команда).
2. Bridge — единая точка вызова из UI: `gui/cmdbridge.py` (общий модуль, создаёт агент main; агент panel импортирует, не дублирует):
   - `execute(name, ctx, **kwargs) -> CommandResult` — обёртка над `default_registry.execute`;
   - `report_error(parent, result)` — единый показ ошибок (QMessageBox, текст с кодом команды);
   - модуль НЕ содержит бизнес-логики.
3. Перевязка: обработчик меню/кнопки собирает параметры из диалогов/состояния GUI → `bridge.execute(...)` → рендер результата теми же виджетами, что и раньше. **Поведение для пользователя не меняется**: те же окна, тот же вывод, те же горячие клавиши.
4. Если команда возвращает данные в другой форме, чем рисовал старый код — адаптер пишется в bridge/виджете-рендере, НЕ в команде. Контракты команд (Волны 1+3) НЕ менять.
5. Регистрация новых w4-команд: свой файл + `register()`; `commands/builtin/__init__.py` НЕ трогать (координатор добавит после мержа). В тестах регистрировать вручную + guard `has()`.
6. Тесты: каждая перевязка не ломает существующие pytest-qt тесты; на каждое `gap`-поведение — smoke теста команды. Полный прогон `py -m pytest -q` в конце — зелёный (база: 1472 passed, 8 skipped).
7. Не менять domain/analysis/fileio/catalog. Не менять чужие GUI-файлы (main НЕ трогает gui/, panel НЕ трогает main.py; общий только gui/cmdbridge.py — main создаёт, panel только импортирует; если panel стартует раньше и файла нет — создаёт по спецификации выше, main-агент при конфликте оставляет свою версию если она совместима).
8. Коммит(ы) в свою ветку w4/<src>. Не пушить, не мержить.
9. Отчёт в конце: сколько bound/gap/ui-only/direct-keep, список новых команд, что осталось прямым и почему.

## Критерии готовности
- Инвентарь 100% экшенов твоего файла (ни один не «забыт»).
- Каждый `bound`/`gap` экшен вызывает команду через bridge (проверка: в обработчике нет прямых импортов analysis/domain вне рендера результата).
- Полный pytest зелёный.
- GUI вручную не проверяем — полагаемся на pytest-qt набор.
