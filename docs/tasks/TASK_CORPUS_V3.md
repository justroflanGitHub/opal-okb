# TASK_CORPUS_V3 — Корпус волна 3: разбор и классификация 216 отказов spot/mtf_geo

**Проект:** OPAL-OKB (реимплантация оптического САПР OPAL-PC). Ты в изолированной копии, ветка `feature/corpus-v3` (уже создана и активна, базируется на свежем main `de883be` со влитыми тремя ветками: corpus v1+v2, registry-500, golden-44). В main лежит волна 2: `scripts/corpus_scan.py` с `--ops`, `docs/reports/corpus_v2.json` (schema 2), `CORPUS_REPORT_V2.md`, `docs/tasks/CORPUS_PLAN.md`. Если `docs/reports/corpus_v2.json` отсутствует — СТОП: сообщи, база не готова.

**Контекст:** волна 2 дала карту здоровья 612 систем по 10 ops, но spot ok только 402/612 (66%), mtf_geo — 399/612 (65%). 216 систем first-fail на spot; известные семейства отказов: RUSSAR 51, OCULAR 44, USLENS 29, LENS 23, REPROD 11, USREPROD 11, BINOCUL 10, MICROLEN 9, USBINOCL 9, USMICRO 5, ZOOM 4. Объяснены лишь 33 из 216: 24 US-патента (efl=0), 9 layout-объективов (L=0). Остальные ~183 — неклассифицированная дыра: это главная неизвестная в готовности порта. Отдельный бонус-класс: 7 систем MICROLEN — `ZeroDivisionError` в vignette при L=0.

**Цель:** каждая из 216 систем получает честный вердикт-класс первопричины; всё, что чинится на стороне сканера — починено; покрытие spot/mtf_geo выросло настолько, насколько позволяют реальные причины (цель — не 100% любой ценой, а полная классификация + прозрачный отчёт).

## План (пакетами, атомарные коммиты)

1. **A. Реестр отказов**: прогон сканера на полном корпусе → промежуточный артефакт-таблица: система, семейство, op, тип ошибки + сообщение, триггер. Основа — уже лежащие ошибки в `corpus_v2.json`. Коммит (артефакт в docs/).
2. **B. Классификация**: разбить отказы на классы первопричин (гипотезы: срезание кромкой EDGE/TIR при трассировке поля; US-патенты efl=0; layout L=0; afocal-выход; ZeroDivision L=0; NaN; прочее). Для каждого класса разобрать 1–3 системы вручную (реестр/domain API: трассировка, полудиаметры, поле) — почему именно падает, с числами. Классы закрепить как константы-перечисление в одном месте (единый источник: scan и stats импортируют оттуда). Коммит.
3. **C. Правки сканера** (только scanner-side, движок не трогать): skip-правила для efl=0/L=0 (не падение, а класс `unscannable: <причина>` — ops false + error = класс), защита от ZeroDivision, корректные параметры трассировки (прецедент проекта: временное расширение полудиаметров при полевых расчётах — см. фикстуры полевых аберраций). На каждый класс — регресс-тест с 1–2 системами-фикстурами. Коммиты.
4. **D. Повторный прогон**: полный корпус → `docs/reports/corpus_v3.json` (schema 2, те же ops; отдельный файл, v2 не перезаписывать) + дифф-свод покрытия v2→v3 по всем ops. Коммит.
5. **E. Отчёт**: `docs/reports/CORPUS_REPORT_V3.md` — матрица «семейство × класс», покрытие до/после, отдельный раздел «движковые находки» (что требует правок движка — для тяжёлой модели, НЕ чинить самому), выводы. CHANGELOG `[1.32.0]`, строка в README. Коммит.
6. **Финал**: полный `py -m pytest -q` зелёный; тесты в `tests/test_corpus_scan.py` расширены (классы отказов, unscannable-контракт, читатель v3-файла).
