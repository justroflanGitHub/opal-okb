# TASK_GOLDEN_WAVE2 — Golden-верификация порта по банку 44 систем

**Проект:** OPAL-OKB (реимплантация оптического САПР OPAL-PC). Ты работаешь в изолированном git-worktree, ветка `feature/golden-44` (уже создана координатором).
**Контекст:** golden-банк эталонных распечаток `.PRN` вырос 16 → 44 файла (`analysis/reverse_data/golden/bank/*.PRN`). Существующие golden-тесты (`tests/test_golden_verify.py`, 307 GREEN) покрывают в основном старые ~14 систем. Новые 30 систем портом ещё не сверены.

**Цель:** каждая из 44 систем банка получает автоматическую сверку «порт vs оригинал»: параксиальные характеристики, суммы Зейделя, осевые аберрации — по числам из распечаток. Итог — в CI (тесты идут на GitHub Actions без локальных данных: банк в git, а вот `.OPJ` систем лежат в `C:\GOLDEN_DOS\<ИМЯ>.OPJ` — локально! значит тесты должны: при наличии `C:\GOLDEN_DOS` — полная сверка; при отсутствии — skip с reason, банк-PRN при этом всё равно парсится и валидируется формат).

## Источники истины

- `.PRN` банк: cp866, формат распечаток OPALTRAN (заголовок `<Имя> ... РАСЧЕТ-RT ... OPAL-PC>`, секции: габариты, осевой пучок TABOC и т.д.). Парсер: `parse_golden_prn` в tests (найди, где определён — НЕ дублировать, расширить при необходимости).
- `.OPJ` систем: `C:\GOLDEN_DOS\<ИМЯ>.OPJ` (85 файлов; в банке 44 имени). Загрузка портом: существующий модуль чтения .OPJ (см. tests/test_golden_verify.py как грузят US00KI02).
- Конвенции и допуски сравнения: смотри существующие тесты (TOL_ABERR, TOL_PARAX).

## План (пакетами, чекпойнты-коммиты)

### Пакет A — инвентаризация (без кода)
Для каждого из 44 имён: какие секции есть в PRN (габариты/осевой/хроматизм...), размер, есть ли OPJ. Таблица в `docs/tasks/G44_PROGRESS.md` (создать). Отметить LOV и прочие аномалии, если всплывут.

### Пакет B — расширение парсера
Если каких-то секций старый парсер не понимает — аккуратно расширить (обратно совместимо, существующие тесты не упасть). Коммит.

### Пакет C — параметризованная сверка
`tests/test_golden_wave2.py` с `@pytest.mark.parametrize` по всем системам:
- грузить `<ИМЯ>.OPJ` (если нет `C:\GOLDEN_DOS` — skip всей параметризации с reason);
- считать портом: EFL/BFD (paraxial), суммы Зейделя SI..SV, осевые продольные аберрации по зонам;
- сравнивать с числами PRN в допусках печати (оригинал печатает 6-7 значащих; допуск как в существующих тестах);
- РАСХОЖДЕНИЯ НЕ прятать: оформлять `xfail(strict=False, reason="G44: <система> <что> <дельта>")` и обязательно вносить строку в `docs/tasks/G44_FINDINGS.md` (система / метрика / порт / оригинал / гипотеза). Это ценные находки, не провал.

### Пакет D — итог
Полный `py -m pytest -q` зелёный; обновить README (строка golden bank в бейдже/Phase III: «44 systems, N checks GREEN», посчитать фактические GREEN-проверки); CHANGELOG `[1.30.0]`. Финальный отчёт в `docs/tasks/G44_FINAL_REPORT.md`: сколько систем сверено, сколько проверок, сколько xfail-расхождений и топ-гипотезы.
