# TASK_GTIE: GTIE00 — ГОЭ-система, реверс раскладки OPJ (Flash)

## Контекст
- analysis/REVERSE_GVERIFY.md §6: GTIE00 (ГОЭ-голограмма) — строгий парсер
  отвергает: отрицательные толщины (−17/−2/−8), мусорные gidx (65535/65533),
  нет маркера 1e20. Вне standalone-канона.
- Строгий парсер: analysis/fileio/standalone_opj.py (формат-досье в докстрингах
  и в REVERSE_GFIX §P6.1: предмет f64@0x4C, ND u16@0x3A, SD f64@0x6C,
  flags λ-слотов @0x36, апертура @0x5C).
- Исходник: C:\GOLDEN_DOS\GTIE00.OPJ (read-only!) + слот в OPAL.ARH
  (распаковщик/структура — тулзы arh_probe из G2-волн; см. REVERSE_OPCOM.md
  про файл-шину OPAL.ARH).

## Задача
1. Байтовый дифф GTIE00.OPJ против канонического OPJ (например US00KI02):
   найди сдвиги/отличия заголовка. Гипотезы: другой тип поверхностей
   (ГОЭ = hologram: возможно своя таблица типов, доп. поля порядка/фазы),
   релятивные толщины, нестандартный ns.
2. Восстанови раскладку: где что лежит, чем отличается. Декодируй поверхности
   (сколько, какие R/d/glass), опиши ГОЭ-специфику.
3. Загрузчик: расширь analysis/fileio/standalone_opj.py (или отдельный вход)
   — parse + standalone_to_system c best-effort: ГОЭ-поверхность как
   заглушка (тип + параметры сохранены), остальные поверхности — честно.
4. Если в OPAL.ARH есть слот GTIE00 — сравни с OPJ (может, OPJ битый, а ARH-копия канонична).
5. Досье analysis/REVERSE_GTIE.md: раскладка, поля, отличия, судьба загрузчика.
