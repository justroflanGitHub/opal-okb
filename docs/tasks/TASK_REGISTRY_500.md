## 0. Правила среды (Windows)

- Python запускать только `py` (не `python`/`python3` — это Store-стабы).
- Зависимости уже стоят: pytest, pytest-qt, PyQt5, numpy, matplotlib. Ничего не устанавливать.
- Консоль cp1251: в новых скриптах делать `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`, если печатаешь не-ASCII.
- Полный тест-прогон ~4 мин: `py -m pytest -q` (обязателен в конце каждого пакета, не внутри).
- Git: работать ТОЛЬКО в новой ветке `feature/registry-500` (создай от `main` первым делом). НЕ пушить, НЕ мержить в main — это сделает человек-ревьюер.
- В репо есть незакоммиченные локальные данные (extracted/, capture/, g2batch_night*.log) — НЕ трогать, НЕ коммитить их (git add по файлам, не `git add -A`).

## 1. Архитектура (что уже есть — изучить перед стартом)

- `commands/registry.py`, `commands/base.py` — реестр, `@command`-декоратор, типизированные Param, JSON-контракты, CommandContext (stateful: системы по имени, current).
- `commands/builtin/` — 22 модуля доменов: file, system, calc, catalog, tables, trace, aber, psf/adv (дифракция), opt, plot, panel, w4_main_cmds и др. Имена `домен.действие`, регистрация идемпотентная (`register_all`).
- `commands/cli.py` (CLI), `commands/jsonrepl.py` (REPL), `commands/mcp.py` (MCP-сервер, 140 tools).
- `gui/cmdbridge.py` — мост UI→команды; `main.py` + `gui/analysis_panel.py` уже перевязаны.
- Тесты: `tests/test_commands_*.py` — конвенция smoke-тестов по каждому домену (см. `tests/test_commands_builtin.py`).
- Документация контрактов: `docs/tasks/TASK_COMMANDS_W1.md` (Волна 1 — там конвенции), `docs/FORMULAS.md`, `analysis/reverse_data/golden/G2_NOTES.md`.
- Как считать команды: `py -c "import commands; commands.register_all(commands.default_registry); print(len(commands.default_registry.names()))"` → сейчас 140.

1. **UI-инвентарь** `docs/tasks/W4_INVENTORY_main.md` + `docs/tasks/W4_INVENTORY_panel.md`: экшены с классами `ui-only` (57 шт) и `direct-keep` — часть из них выносится в команды (не все: чисто-диалоговые остаются).
2. **Справочник ОПАЛ** `docs/SPRAV.*` / `docs/` — меню оригинального OPAL-PC: каждый расчётный пункт = кандидат (таблицы §14–§16, допуски, синтез, печать).
3. **Экспортные обёртки**: для каждой расчётной таблицы — `export CSV/JSON` вариант (`tables.taboc1.export`...), для графиков — `plot.*.save`.
4. **Пакетные/сервисные**: `system.validate` (санити-проверки системы), `catalog.search` расширенный, `file.diff` (сравнение двух систем), `trace.ray_bundle.export`, batch-прогоны по LBO-библиотеке (`library.batch` с фильтром).
5. **Параметризованные варианты** существующих: зоны/поля/λ как явные параметры с дефолтами — не дублировать логику, а расширить сигнатуры существующих команд (осторожно: обратная совместимость обязательна).

## 3. Пакетный цикл (повторять до 500+)

Один пакет = один домен-фрагмент, 20-30 команд:

1. **Эскиз** (без кода): список команд `имя → описание → вход/выход → источник (UI-инвентарь/справочник/сервис)`. Записать в `docs/tasks/R500_PACKAGES.md` (таблица прогресса; создай первым делом с полным планом пакетов до 500+).
2. **Реализация**: модуль `commands/builtin/<домен>_<тема>.py`, регистрация в `register_all` (идемпотентно, как соседние). Логика — поверх существующих движков (analysis/, src-модули); НИКОГДА не дублировать существующие функции — импортировать. Если движка нет — команда возвращает осмысленную ошибку `not_implemented`, а не пустышку (такие в счёт 500 не идут).
3. **Тесты**: smoke по конвенции (как tests/test_commands_builtin.py) на каждую команду + инвариант «число команд в реестре == ожидаемое» в `tests/test_commands_builtin.py::test_every_registered_command_has_smoke` (обновляй набор).
4. **Коммит**: `feat(r500): пакет N — <домен>, +K команд (итого M/500)` — мелкие атомарные коммиты. CHANGELOG.md: раздел `## [unreleased-r500]`, строка на пакет.
5. **Полный прогон** `py -m pytest -q` зелёный → следующий пакет. Если пакет «не идёт» (сложно/мутно) — записать в R500_PACKAGES.md статус `blocked: причина`, перейти к следующему. Вернуться в конце, если останется время.

- Не дублировать логику между модулями (правило №1 проекта): общее — в общие хелперы.

- Магических чисел в коде — нет, именованные константы.
- Git: никогда `git push`, никогда `git checkout main` для правок.
