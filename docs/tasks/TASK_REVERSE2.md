# TASK_REVERSE2: псевдокодинг трейсеров OPALA.EXE

## Цель
Восстановить алгоритм трассировки лучей из декомпилированных функций MS FORTRAN 5.0
и сверить его с Python-портом (`analysis/raytrace.py`). Результат — файл
`analysis/REVERSE_TRACE.md` с построчным соответствием.

## Входные данные
1. `C:\tools\rea-out\decomp_opala\1000_f344_FUN_1000_f344.c` — трейсировщик A (40 KB декомпила)
2. `C:\tools\rea-out\decomp_opala\1000_f359_FUN_1000_f359.c` — трейсировщик B (40 KB, вероятно хроматизм)
3. Порт: `analysis/raytrace.py` + `analysis/aberrations.py` (сверять формулы)
4. Карта: `analysis/REVERSE_MAP.md` (контекст)

## Что искать в декомпиле (маркёры FORTRAN-генерации)
- Вызовы RTL: sqrt → `0x35` intrinsic-паттерны; деления double (компилятор MSF 5.0
  хранит REAL*8 константы в литералах сегмента 5000)
- Паттерн переноса луча: X = X + T*D (координата + толщина*направляющий косинус)
- Паттеррн преломления Снеллиуса: векторная форма A=n*(D×N), B=n1/n2, D' = ...
- Цикл по поверхностям: инкремент указателя на структуру поверхности
  (в декомпиле — арифметика указателей puVar/pbVar с шагом sizeof структуры)
- REAL*8 массивы: пары undefined2 (4×16-бит = 8 байт)

## Формат результата (REVERSE_TRACE.md)
1. Восстановленный алгоритм f344 в псевдокоде Python (по шагам, с адресами декомпила)
2. То же для f359 (только отличия от f344)
3. Таблица соответствия: шаг алгоритма ↔ функция/строка raytrace.py порта
4. Вердикт: СОВПАДАЕТ / ОТЛИЧАЕТСЯ (по пунктам, с деталями формул)
