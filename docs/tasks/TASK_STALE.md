# TASK_STALE: свежие .PRN для OBEKTIV/OKULAR (Flash, DOSBox)

## Контекст
- analysis/REVERSE_GFIX.md §«Итог P6»: OBEKTIV 12/2/12/1, OKULAR 8/0/14/5 —
  их .PRN в банке STALE (сгенерены из другого состояния системы, чем OPJ на диске).
- Драйвер батча `scripts/g2bank.py` (проверен на 14 системах), тулзы
  `scripts/dosbox_send.py`, `_g2_*.py`. Рецепты в analysis/REVERSE_G2BANK.md.

## Задача
1. Перезагрузить OBEKTIV и OKULAR в стенд ЧИСТО: boot → загрузка из архива/OPJ →
   Работа-RT → '4' (габариты) → '6' (аберрации) → F4 → F9 → ENTER → RT__HHMM.PRN.
   Прогони КАЖДУЮ дважды с холодного рестарта — убедись в воспроизводимости
   (строки совпадают побайтово, кроме времени в шапке).
2. Свежие .PRN → analysis/reverse_data/golden/bank/ (замени stale-версии, старые
   переименуй в *_stale.PRN).
3. Перегон `py -X utf8 analysis/golden_verify.py` — статусы OBEKTIV/OKULAR в
   досье REVERSE_GFIX.md (§обновление STALE): цель R→минимум (остальное уже
   зелёное по конвенциям P6).
4. ВНИМАНИЕ: систему в редакторе НЕ править — только загрузить и считать.

## Правила
- Только эти два артефакта: новые .PRN + секция в REVERSE_GFIX.md. Код не трогать.
- Каждые ~15 мин обновляй REVERSE_GFIX.md §STALE (снаружи автокоммит).
- DOSBox прибивай за собой. Скрины capture/ (префикс st_).
- Если OPJ на диске не совпадает с тем, что грузит стенд (архив vs каталог) —
  зафиксируй откуда реально грузится система и откуда НАДО (файл OPJ vs OPAL.ARH).
