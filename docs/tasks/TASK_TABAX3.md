# TASK_TABAX3: хроматизм — OPAL-режим парных волн + сверка

## Контекст (analysis/REVERSE_TRACE.md §9)
Реверс OPALA.EXE установил: OPAL считает хроматизм как ПОВТОРНУЮ трассировку
того же луча с другой λ — но выбор волны ПОВЕРХНОСТНЫЙ: у каждой поверхности
флаг wl_flags[surf*2-2] (байт записи, шаг 0x18): 0 = основная λ → трейсер f344,
иначе → f359 + печать TABOC1/TABAX3 (FUN_1000_e920, [0x50c2]=1).
В EXE НЕТ таблицы спектральных линий — λ только из пользовательских данных.
Формат TABAX3 (DS 0x7af): (f8.3, f9.2, 5f12.6) — 7 колонок: λ/отрезок + 5 хромат. величин.

Порт сейчас: polychromatic-семейство (перебор system.wavelengths глобально) —
механизм совпадает, но per-surface пары нет.

## Задача
1. **Прочитать §9 REVERSE_TRACE.md** (строки ~655-700) + §2 карту cf98.
2. **Реализовать OPAL-режим** в analysis (новый модуль или расширение aberrations.py):
   `compute_chromatism_opal(system, wl_main=None) -> dict`:
   - для каждой поверхности i с wl_flag: прогон трассировки с wl_main → прогон с
     λ_поверхности (из system.wavelengths/записи) → РАЗНОСТИ координат/углов на
     изображении = осевые/поперечные хроматические величины
   - если wl-флагов в системе нет (современные системы) — fallback: пары
     (wl_main, wl) для всех wl в system.wavelengths — сравнимо со старым поведением
3. **Вывод TABAX3-таблицы** (возвращать строки): 7 колонок по формату OPAL
   (λ f8.3, отрезок f9.2, 5×f12.6) — метод .formatTabax3() или tabax3_rows()
4. **Сверка**: для 2-3 систем из LENS.LBO (f' на d/F/C линиях) — осевой хроматизм
   dF−dC должен совпасть с разностью paraxial_trace(wl=d)−paraxial_trace(wl=F)
   в пределах 1е-6 (это одна и та же формула двумя путями — консистентность)
5. **GUI не трогать** (только analysis-слой) — интеграцию потом отдельно.
